### Chapter 2: Characters, Glyphs, Bytes: An Introduction to Unicode
**著者：雅尼斯·哈拉蘭布斯 博士（Yannis Haralambous, Ph.D.）**

*譯者：[Lycoris \<lycorismisaka@gmail.com\>](mailto:lycorismisaka@gmail.com)*

在上一章中，我們見證了前 Unicode 時代的諸神混戰：從 7 位 ASCII 到各式各樣互不相容的 8 位 ISO 8859 擴充套件表，再到遠東漢字文化圈各自探索的雙位元組內碼表。這種地域性單位元組與多位元組標準割據的局面，給全球計算機資訊交換帶來了無窮無盡的亂碼夢魘。

如今，計算機世界正日益堅定地邁向全面接納 Unicode 的軌道，在面對東亞語言和複雜的非西方文字型系時更是如此。然而，向人類全部書寫體系開放胸懷是有代價的，那便是不得不接納這些文字型系背後與生俱來的複雜性。在本章中——作為對 Unicode 的系統導論——我們將深入剖析其基本哲學思想、底層技術機制以及宏觀平面規劃。在後續各章中，我們還將逐一檢視居住在 Unicode 殿堂內的具體文字型系及其技術屬性。

## 哲學命題：字元與字形（Characters and Glyphs）

在日常口語與早期淺顯的計算機文獻中，“字元”（character）、“字模”（letterform）與“字形”（glyph）常常被不加區分地混淆使用。然而在現代計算機排印學與編碼理論中，**嚴格釐清字元與字形的邊界，是進入 Unicode 殿堂的絕對第一前提**。

* **字元（Character）**：  
  字元是一個**抽象的概念實體（abstract, intangible entity）**。它是書寫語言中最基礎的語義單元，擁有明確的語言學身份、名稱與規範屬性，但它**本身沒有任何固定的外貌、大小或視覺形態**。例如，拉丁字母 “小寫字母 a” 是一個字元，漢字 “文” 是一個字元，阿拉伯字母 “BEH” 亦是一個字元。字元存在於邏輯與概念的心智世界中。
* **字形（Glyph）**：  
  字形是字元在物理世界的**具體視覺呈現形態（graphical image / visual presentation）**。它是落在紙面上的一團墨跡，或是投射在顯示屏上的一組發光畫素與貝塞爾向量曲線。同一個字元，在不同的字型設計師筆下、在不同的歷史書寫流派中、或在不同的排版上下文中，可以呈現為成百上千種截然不同的字形！

但現實往往比純粹的二元劃分更為複雜：
1. **存在沒有字形的字元**：例如空格（Space）、零寬不換行空格（Zero-Width No-Break Space）、從左至右標記（LRM）以及各式各樣的排版控制符，它們在頁面上完全沒有可見墨跡，卻承載著至關重要的邏輯與排版指令；
2. **存在對應多種不同字元的字形**：字形外觀完全相同的墨跡，在不同語言和語境下代表截然不同的抽象字元；
3. **存在同時對應多個字元的單一體字形**：最典型的便是排版連字（Ligatures，如 ‘ﬁ’ 同時對應字元 ‘f’ 與 ‘i’），以及印度次大陸文字中極其複雜的合體字（Conjuncts）；
4. **存在被拆散為多個碎片的字元**：在孟加拉文、泰米爾文或高棉文中，某些母音字元在視覺呈現上被分裂為左右兩側甚至環繞在子音四周的多個字形部件。

### 代表性字形（Representative Glyph）的非規範性

幸運的是，Unicode 標準正文以及聯盟官方網站上釋出的規範程式碼圖表（Code Charts），在給出每一個字元的描述性名稱時，總是伴隨提供一個視覺化的字形——這一字形被稱為**代表性字形（Representative Glyph）**。

必須強調的是：**代表性字形僅具有參考與說明意義，完全不具備強制約束力（informative, not prescriptive）**。字形的存在對於非該語言的母語使用者而言至關重要：若沒有代表性字形，非藏語學者根本無法僅憑名稱 “dzud rtags bzhi mig can” 想象出它是一個由四個小黑點構成的十字記號；而若非北歐如尼盧恩文字專家，人們也絕無可能知曉字母 “ingwaz” 的外貌形如一枚菱形菱角。

然而，若對某種文字缺乏基本認知，單憑代表性字形也常常會造成誤解。字元與其字形之間的對應關係可能由於風格流派、歷史演進（例如字母 ‘W’ 的印刷體與手寫體存在天壤之別）、乃至嚴苛的語法規則而發生劇烈形變。阿拉伯文便是最極端的例子：阿拉伯字母依據其在單詞中的位置（詞首、詞中、詞尾、獨立）必須展現不同的外觀。例如字元 `ARABIC LETTER KAF` 在 Unicode 程式碼圖表中的代表性字形是獨立形態，但在單詞中間，它卻呈現為一個完全不同、甚至連初學者都難以辨識的扁平字形。

對於表意漢字而言，代表性字形更是查閱字元的唯一途徑，因為 Unicode 對數萬個漢字完全無法提供語義層面的文字描述。我們或許可以設想將漢字 “門” 描述為“意為‘大門’的字元”；然而，僅在日文語境中，“門”便同時兼具“入口”、“門戶”、“門徑”、“部門”、“學科”、“弟子”、“學派”乃至“宗族”等十餘種截然不同的含義。若試圖以此方式為 Unicode 收錄的 70,027 個表意漢字編寫語義描述，不僅工作量浩瀚如煙海，而且在學術上也是徒勞無益的。

### 為什麼計算機不應編碼字形？

早期某些字元編碼之所以走向失敗，其根本原因就在於試圖將特定的“視覺字形”硬塞入字元表中。試想：如果一種字型中包含正體 ‘a’、斜體 ‘*a*’、粗體 ‘**a**’、雙層 ‘a’ 與單層手寫體 ‘ɑ’，我們是否應當為它們分別分配獨立的編碼碼位？

答案是絕對堅決的否定。如果將排版樣式的字形變體編碼為獨立字元，全文檢索、自然語言處理、語義分詞與拼寫檢查將瞬間陷入滅頂之災：搜尋引擎在匹配單詞 “apple” 時，將無法命中以斜體或粗體書寫的同一單詞！

因此，現代編碼哲學的至高法則為：**編碼（encoding）只負責收錄抽象的“字元”（What you mean），而字型（font）則負責提供具象的“字形”（How it looks）**。

如果我們將這些視覺字形轉換到小寫形態，字元的真實本質便瞬間原形畢露：拉丁字母是 ‘h’，希臘字母是 ‘η’，西裡爾字母則是 ‘н’。甚至在同一文字系統內部，也存在字形完全重合的獨立字元：例如大寫字母 ‘Ð’，在冰島文中是帶橫槓的 Eth（小寫為 ‘ð’），在塞爾維亞-克羅埃西亞文中是帶橫槓的 D（小寫為 ‘đ’），而在某些非洲語言中又是另一個獨立的音標字母。只有透過 Unicode 的字元碼位與底層屬性體系，軟體才能真正理解文字背後的數理與語言學本質，而無需在每一次排版時都重新發明輪子。

### Unicode 聯盟與 ISO 10646 的世紀合流

Unicode 運動最初於 1987 年由施樂帕洛阿爾託研究中心（Xerox PARC）的喬·貝克爾（Joe Becker）、李·柯林斯（Lee Collins）與蘋果公司的馬克·戴維斯（Mark Davis）共同倡議發起。1991 年 1 月，**Unicode 聯盟（Unicode Consortium）**在加州正式註冊成立。

與此並行，國際標準化組織（ISO）亦在推進其官方的國際多八位編碼字符集計劃——**ISO/IEC 10646**（即通用字符集 UCS, Universal Character Set）。在初期，ISO 陣營傾向於構建一個龐大的 31 位四維編碼空間（組 Group、面 Plane、排 Row、格 Cell），其總容量高達 20 億個碼位；而早期 Unicode 陣營則極力主張構建一個緊湊高效、面向全人類現代常用文字的統一 16 位定長編碼（$2^{16} = 65,536$ 個碼位）。

兩大標準體系的分裂勢必造成全球軟體工業的災難。所幸在 1991 年底，雙方達成了極具遠見的重大歷史和解與合併協議：
* 雙方的字元碼位分配實現**完全嚴格的一對一同步（1:1 synchronization）**；
* ISO/IEC 10646 的第一組第零平面（Group 00, Plane 00）被永久確立為 **基本多語言平面（BMP, Basic Multilingual Plane）**，其碼位與 Unicode 16 位空間完全一一對應；
* 雙方共用一套字元命名與屬性規範，徹底避免了世界計算標準的分裂。

## Unicode 十大第一原則（First Principles）

Unicode 體系之所以能夠超越此前所有字元編碼標準，在於其從誕生之初就確立了十項不可動搖的頂層公理架構（The Ten Principles of Unicode）：

1. **通用性（Universal repertoire）**：  
   Unicode 致力於收錄全世界一切書寫系統中所使用過的所有字元——不僅涵蓋所有現代活語言，亦囊括古文字、楔形文字、象形文字以及廣袤的數學、音樂、科學專業符號。
2. **高效性（Efficiency）**：  
   聽起來像是 1950 年代廣告裡的宣傳口號，但它包含著深刻的技術真理。從純工程角度看，Unicode 使我們徹底擺脫了 ASCII 控制字元、ISO 2022 的轉義狀態機切換等痛苦枷鎖。無可否認，Unicode 配套的文件（規範文字、技術報告、學術研討會文獻）遠比 ISO 標準冷酷乾癟的官僚條款更為高效實用。
3. **字元與字形的差異（Characters, not glyphs）**：  
   正如前文所述，字元與字形是截然不同的兩個概念，Unicode 嚴格僅為抽象字元編碼。儘管電腦科學界至今仍未能給“字元”下一個無懈可擊的形式語言定義，但 Unicode 至少釐清了長期盤踞在工程師腦海中的混沌觀念。
4. **明確定義字元語義（Semantics）**：  
   每一個已分配的碼位在任何時間、任何語境下，均唯一且無歧義地對應一個具體的抽象字元及其完整的數學、方向性、分類學與規範屬性。
5. **純文字原則（Plain text）**：  
   Unicode 序列僅承載最純粹的底層純文字字元流。任何關於字型選擇、字號大小、行距、邊距與色彩的排版富文字屬性，均屬於外部標記語言（如 HTML、XML、RTF）的範疇。作者在此指出：諸如段落折行方向或語言標籤等高層資訊，本應由上層協議（如 XML 的 `xml:lang` 屬性）優雅處理，Unicode 卻出於“純文字必須在任何封閉協議中自包含”的執念，固執地在底層引入了語言標籤控制符，這構成了 Unicode 設計哲學中頗耐人尋味的一筆。
6. **邏輯順序（Logical order）**：  
   在計算機記憶體與資料流中，字元必須嚴格按照人類思維書寫或朗讀發音的**邏輯先後順序（logical memory order）**儲存。對於阿拉伯文與希伯來文等從右向左（RTL）書寫的文字，其在記憶體中的儲存順序依然與從左向右（LTR）文字一致（先讀的在前，後讀的在後），螢幕上的逆向呈現完全交由排版系統的**雙向演算法（Bidi Algorithm）**負責。
7. **字元統合（Unification）**：  
   當不同文化或同一語言體系中的若干字元，在書寫歷史、圖形起源與現代語義上具有同源性與共同特徵時，Unicode 堅決將其統合歸併為一個單一碼位。最著名的範例莫過於**中日韓漢字統合（Han Unification）**。
8. **動態組合（Dynamic composition）**：  
   Unicode 允許帶有重音符或附加變音標記的字元透過“基礎字元 + 組合變音符”（Base Character + Combining Marks）在排版時動態拼合，而無需為每一種可能的複合變音字元窮舉分配靜態碼位。然而這種靈活性亦有代價：在一個 Unicode 字串中，若任意擷取一個以組合字元開頭的子串，該子串在語法上是不合法的——這在傳統的 ASCII 或 ISO 8859 中絕不會發生。
9. **等價序列（Equivalent sequences）**：  
   為了照顧既有遺留系統的相容性，Unicode 既保留了大量“預合成字元”（Precomposed Characters，如帶有重音的字母），又支援透過基礎字元加組合標記構成的“分解序列”（Decomposed Sequences）。原則九莊嚴承諾：這兩類在表現形式上不同的字元序列，在數理與排版語義上完全等價，並透過規範正規化形式（UAX #15）相互對映。
10. **可轉換性（Convertibility）與穩定性（Stability）**：  
    這是給 Unicode 帶來最大非議但也正是促成其被全球工業界全面接納的基石。該原則規定：所有在業界廣泛使用的既有國家或行業編碼標準，必須能夠**無損地（round-trip）可逆轉換到 Unicode**。其代價是殘酷的：每一個古怪、生僻、定義含糊、乃至純屬冗餘的字元（如通用貨幣符號、DOS 內碼表的製表線條、打字機退格重疊字元、甚至韓國為了兩種不同發音而對同一漢字進行的重複編碼），全都被抬進了 Unicode 的神聖殿堂！與此同時，**穩定性原則保證碼位一旦分配，其數值與名稱永恆凍結、絕不刪除、絕不更改**，即便發現歷史拼寫錯誤亦立字為據，永不變更。

## 技術命題：字元、碼位與位元組

正如哲學家所言，生活不僅有形而上的哲學，更有物理世界的骨感現實。在計算機系統內部，字元究竟如何落地為磁碟上的位元與位元組？

現代字元標準體系將字元的表徵清晰劃分為五層模型架構：
$$\text{抽象字符库（ACR）} \longrightarrow \text{编码字符集（CCS）} \longrightarrow \text{字符编码形式（CEF）} \longrightarrow \text{字符编码方案（CES）} \longrightarrow \text{传输语法（TES）}$$

1. **抽象字元庫（Abstract Character Repertoire, ACR）**：  
   所有被標準認定的抽象字元的無序集合；
2. **編碼字符集（Coded Character Set, CCS）**：  
   將抽象字元庫中的每一個字元對映到一個唯一的非負整數——這個整數被稱為**碼位（Code Point）**。在 Unicode 規範中，碼位以統一的字首標記：
   $$\text{U+0000} \sim \text{U+10FFFF}$$
   總共定義了 $16 \times 2^{16} + 2^{16} = 17 \times 65,536 = 1,114,112$ 個碼位。其中排除了代理區碼位後的有效字元碼位被稱為 **Unicode 標量值（Unicode scalar value）**。
3. **字元編碼形式（Character Encoding Form, CEF）**：  
   將整數碼位對映為定長的計算機基本整數單元（Code Unit, 碼元），即 UTF-32、UTF-16 與 UTF-8；
4. **字元編碼方案（Character Encoding Scheme, CES）**：  
   處理多位元組碼元序列在不同硬體架構下的**位元組序（Endianness）**，如 UTF-16BE（大端序）、UTF-16LE（小端序）；
5. **傳輸編碼語法（Transfer Encoding Syntax, TES）**：  
   針對特定有損通訊通道（如早期 7 位 SMTP 郵件）的資料封裝，如 Base64 與 Quoted-Printable。

步驟 (1) 至 (4) 在工業界統稱為**字元對映表（Character Map）**，其官方名稱在網際網路號碼分配局（IANA）正式註冊，以便在 MIME、HTTP 等底層網路協議中準確標識：
* `UTF-8`：最普及的 1 至 4 位元組變長編碼；
* `UTF-7`：專為 7 位郵件通道設計的非官方基數 64 轉移編碼（RFC 2152）；
* `UTF-32` / `UTF-32LE` / `UTF-32BE`：直接採用 32 位雙字定長表示的編碼形式與大小端方案；
* `UTF-16` / `UTF-16LE` / `UTF-16BE`：採用 16 位字（wyde）定長/變長代理對的編碼形式與大小端方案；
* `UNICODE-1-1` / `UNICODE-1-1-UTF-7`：歷史版本規範；
* `CESU-8`：面向 UTF-16 代理對的特殊 8 位相容方案；
* `SCSU`：Unicode 標準壓縮方案（UTS #6）；
* `BOCU-1`：保持二進位制排序特性的壓縮方案。

## 主流字元編碼形式（CEF）深度解析

### 1. UTF-32 與定長表示

UTF-32（以及 ISO 10646 的 UCS-4）是概念上最純粹的編碼形式：它使用一個完整的 32 位（4 位元組）無符號整數來直接表示每一個 Unicode 碼位。
* **優勢**：絕對的定長特性。字串中第 $N$ 個字元必然位於記憶體偏移量 $4N$ 處，使得按索引隨機訪問字元的時間複雜度達到最優的 $O(1)$；
* **致命缺陷**：對絕大多數以拉丁字母、希臘字母或常用符號構成的西方文字而言，UTF-32 中高達 75% 的位元組全部是無意義的零填充（`0x00 0x00 0x00`），造成了記憶體頻寬、快取命中率與磁碟空間的極其慘烈的浪費。

### 2. UTF-16 與代理對（Surrogate Pairs）數學機制

當 Unicode 聯盟在 1990 年代中期意識到 16 位（65,536 個碼位）終將無法容納全人類的生僻漢字與古代文字時，工業介面臨抉擇：要麼全面推倒重來強推 32 位，要麼設計一種平滑相容 16 位的優雅擴充套件演算法。

電腦科學家們最終提出了極其精妙的**代理對（Surrogate Pairs）機制**，由此誕生了 **UTF-16**。

在基本多語言平面（BMP，即 $\text{U+0000} \sim \text{U+FFFF}$）中，Unicode 特意開闢了一片永遠不分配給任何實際字元的“真空禁區”——**代理區（Surrogates, $\text{U+D800} \sim \text{U+DFFF}$，共 2,048 個碼位）**，並將其均分為兩大半區：
* **高半區代理（High Surrogates / Lead Surrogates）**：$\text{U+D800} \sim \text{U+DBFF}$（共 $1,024 = 2^{10}$ 個值）；
* **低半區代理（Low Surrogates / Trail Surrogates）**：$\text{U+DC00} \sim \text{U+DFFF}$（共 $1,024 = 2^{10}$ 個值）。

任何一個落在輔助平面（Planes 1–16，即 $\text{U+10000} \sim \text{U+10FFFF}$）的高位碼位 $N$，其數值必然滿足：
$$0 \le N - 0\text{x10000} \le 0\text{xFFFFF}$$

這個差值正好是一個 20 位的二進位制數！UTF-16 巧妙地將這 20 位對半切分為兩組 10 位：
* 高 10 位加上偏移基數 $0\text{xD800}$，生成一個**高半區代理字**（前導代理）；
* 低 10 位加上偏移基數 $0\text{xDC00}$，生成一個**低半區代理字**（後尾代理）。

#### 代理對數學轉換方程
* **編碼（碼位 $N \to$ 代理對 $(H, L)$）**：
  $$N' = N - 0\text{x10000}$$
  $$H = 0\text{xD800} + \lfloor N' / 0\text{x400} \rfloor = 0\text{xD800} + (N' \gg 10)$$
  $$L = 0\text{xDC00} + (N' \pmod{0\text{x400}}) = 0\text{xDC00} + (N' \ \& \ 0\text{x3FF})$$
* **解碼（代理對 $(H, L) \to$ 碼位 $N$）**：
  $$N = ((H - 0\text{xD800}) \times 0\text{x400}) + (L - 0\text{xDC00}) + 0\text{x10000}$$

由於高代理（`0xD800`–`0xDBFF`）與低代理（`0xDC00`–`0xDFFF`）的取值區間完全互斥，且與任何合法的 BMP 字元碼位完全隔離，解析引擎在資料流中向前或向後滑動時，能夠瞬間且無歧義地判定當前 16 位整數究竟是一個完整的單字元，還是代理對的頭部或尾部！

### 3. UTF-8：貝爾實驗室的傳世傑作

1992 年 9 月的一天晚上，在新澤西州的一家餐館裡，肯·湯普森（Ken Thompson）與羅布·派克（Rob Pike）在餐巾紙上勾勒出了計算歷史上最完美的編碼形式——**UTF-8**（原名 FSS-UTF）。

UTF-8 是一套純粹的**以 8 位位元組為基準的變長編碼形式（variable-width byte-based encoding）**，它使用 1 至 4 個位元組來對 21 位的 Unicode 碼位進行精確切分：

| 標量碼位範圍（十六進位制） | 位元組數 | 位元組 1（前導位元組） | 位元組 2（後隨位元組） | 位元組 3（後隨位元組） | 位元組 4（後隨位元組） |
| :--- | :---: | :--- | :--- | :--- | :--- |
| `00000000`–`0000007F` | 1 | `0xxxxxxx` | — | — | — |
| `00000080`–`000007FF` | 2 | `110yyyyy` | `10xxxxxx` | — | — |
| `00000800`–`0000FFFF` | 3 | `1110zzzz` | `10yyyyyy` | `10xxxxxx` | — |
| `00010000`–`0010FFFF` | 4 | `11110uuu` | `10uuzzzz` | `10yyyyyy` | `10xxxxxx` |

#### UTF-8 的工程美學巔峰：
1. **絕對向下相容 ASCII**：  
   對於 `0x00`–`0x7F` 的 128 個 ASCII 字元，UTF-8 使用單位元組儲存，且最高位（bit 7）恆為 0。這意味著任何合法的 ASCII 英文檔案，**無需做任何位元組轉換，本身就是一份完全合法的 UTF-8 檔案**！所有原本只認識 C 語言 ASCII 字串（以 `\0` 結尾）的古老系統工具（如 `grep`、`sed`、`awk`、編譯器），完全無需重寫即可直接操作 UTF-8。
2. **字首自同步特性（Self-synchronizing）**：  
   在多位元組序列中：
   * 前導位元組（Lead Byte）的高位具有特徵掩碼：`110...` 代表後續跟隨 1 個位元組；`1110...` 代表後續跟隨 2 個位元組；`11110...` 代表後續跟隨 3 個位元組；
   * 所有後隨位元組（Continuation Bytes）的高兩位**恆定為 `10xxxxxx`**！
   這種設計具有無與倫比的容錯性：如果由於網路傳輸丟包或磁碟損壞導致位元組流中間發生截斷，解碼器只需線性向後掃描，一旦遇到一個最高位不是 `10...` 的位元組，便能**瞬間找回同步邊界（resynchronize）**重新開始正確解碼，絕不會讓單點故障滾雪球式汙染整個後續文字！
3. **徹底根除大小端問題**：  
   由於 UTF-8 的資料單元本身就是 8 位位元組，它在任何 CPU 架構下都不存在多位元組整數的高低端重排問題，無需位元組順序標記（BOM）。
4. **非最短形式（Overlong Forms）與安全漏洞**：  
   在 UTF-8 早期實現中，某些解碼器允許多種位元組序列解碼為同一個字元（例如用雙位元組 `0xC0 0xAF` 表達斜槓 `/`，即 ASCII `0x2F`）。駭客利用此漏洞成功繞過了大量 Web 伺服器（如著名的 IIS 目錄遍歷漏洞）的路徑安全檢查。現代 Unicode 規範已徹底封禁一切非最短編碼形式，合法的 UTF-8 序列必須是絕對唯一的。

### 4. 位元組順序標記（Byte Order Mark, BOM）

在處理 UTF-16 與 UTF-32 時，多位元組整數在記憶體中究竟應當高位在前（大端序 Big-Endian）還是低位在前（小端序 Little-Endian），取決於底層 CPU 的物理架構（Intel x86 採用小端，Motorola/PowerPC 採用大端）。

為了在跨平臺交換檔案時消除歧義，Unicode 特意設計了**位元組順序標記（BOM）**：字元 **$U+\text{FEFF}$（零寬不換行空格 / ZERO WIDTH NO-BREAK SPACE）**。
* 如果接收方在檔案開頭讀入的兩個位元組是 `0xFE 0xFF`，則表明該文字採用大端序（UTF-16BE）；
* 如果讀入的兩個位元組是 `0xFF 0xFE`，則表明該文字採用小端序（UTF-16LE）。為什麼？因為在 Unicode 規範中，**$U+\text{FFFE}$ 已經被永久宣告為一個非法字元（Noncharacter）**，它在任何合法的 Unicode 文字中都絕不可能存在！一旦出現，唯一的解釋就是當前系統的位元組讀取順序顛倒了。
* 對於 UTF-32，其 BOM 為 `0x00 0x00 0xFE 0xFF`（大端）或 `0xFF 0xFE 0x00 0x00`（小端），反轉後的 `0xFF 0xFE 0x00 0x00` 遠超有效範圍，極易辨識。
* 至於剪下貼上中可能夾帶的冗餘 BOM，排版引擎和搜尋演算法會將其作為不可見無害字元自動忽略。Unicode 3.2 進一步引入了專用字元 $U+\text{2060}$（`WORD JOINER`）來承擔純粹的零寬不換行語義，使得 $U+\text{FEFF}$ 的職責更加純粹地聚焦於檔案開頭的 BOM 簽名。

### 5. CESU-8、SCSU 與 BOCU-1 壓縮機制

除了主流形式外，Unicode 歷史上還誕生過若干極具工程特色的特種編碼與壓縮演算法：

#### CESU-8（UTF-16 的 8 位相容編碼）
CESU-8（RFC 2781 / UTR #26）是 UTF-16 與 UTF-8 的奇特混合體。在 CESU-8 中，文字首先被轉換為 UTF-16（輔助平面字元被分解為高低代理對）；隨後，系統對每一個 16 位代理字分別執行獨立的 3 位元組 UTF-8 編碼！因此，一個本可在 UTF-8 中用 4 位元組表示的輔助平面漢字，在 CESU-8 中被膨脹成了兩個 3 位元組序列，共計 6 個位元組。CESU-8 在 Oracle 資料庫內部以及 Java 早期序列化中廣泛使用，但在公開網路資料交換中被嚴格禁止。

#### SCSU（Unicode 標準壓縮方案，UTS #6）
對於非英語環境（如俄文、阿拉伯文、希伯來文），UTF-16 導致檔案體積翻倍，而 UTF-8 亦需要 2 至 3 個位元組。為此，Unicode 聯盟設計了 SCSU 壓縮方案。其核心原理是引入一個**在 Unicode 碼錶中滑動的 128 字元寬度的“視窗”**：
* 系統維護 **8 個動態視窗**（可隨資料流動態重新定位）和 **8 個靜態預置視窗**；
* 初始狀態下位於視窗 0（ASCII）。當文字切換至特定語言塊時，透過傳送短小的控制指令改變活動視窗；
* 位於當前視窗內的字元，在位元組流中僅需佔用 **單個位元組（Single Byte, 0x80–0xFF）**！
* SCSU 包含“壓縮單位元組模式”與“Unicode（UTF-16）全寬模式”，透過如下指令精密切換：

| 控制指令 | 位元組值 | 功能語義與引數 |
| :--- | :--- | :--- |
| **SCU** | `0x0F` | 永久切換至 Unicode 16 位模式（直至另行切換） |
| **SQn** | `0x01`–`0x08` | 臨時從視窗 $n$ 引用單個字元（單字元臨時轉義） |
| **SCn** | `0x10`–`0x17` | 永久將活動視窗切換至動態視窗 $n$（鎖定切換） |
| **SDn** | `0x18`–`0x1F` | 將動態視窗 $n$ 的基準原點重新定義為索引位元組 $B$ 指向的區塊 |
| **SDX** | `0x0B` | 擴充套件視窗重定義，後隨雙位元組字 $W$ |
| **UQU** | `0xF0` | 在 Unicode 模式下直接引用一個非轉義 Unicode 字元 |
| **UCn / UDn** | `0xE0`–`0xEF` | 在 Unicode 模式下的視窗切換與重定義 |

在 SDn 指令中，索引位元組 $B$ 與實際碼位原點的對映關係極具語言學特色：
* `0x01`–`0x67`：原點為 $B \times 0\text{x80}$（覆蓋 $0\text{x0080} \sim 0\text{x3380}$ 的各個半區塊）；
* `0x68`–`0xA7`：原點為 $B \times 0\text{x80} + 0\text{xAC00}$（覆蓋 $0\text{xE000} \sim 0\text{xFF80}$）；
* 特殊離散值：`0xF9` $\to 0\text{x00C0}$（拉丁文），`0xFA` $\to 0\text{x0250}$（國際音標），`0xFB` $\to 0\text{x0370}$（希臘文），`0xFC` $\to 0\text{x0530}$（亞美尼亞文），`0xFD` $\to 0\text{x3040}$（日文平假名），`0xFE` $\to 0\text{x30A0}$（日文片假名），`0xFF` $\to 0\text{xFF60}$（半形片假名）。

#### BOCU-1（保持二進位制排序特性的壓縮方案，UTR #24）
雖然 SCSU 壓縮率極高，但它破壞了字串底層的碼位大小順序。BOCU-1 在提供與 SCSU 相當的壓縮效能的同時，實現了一個極其震撼的數學特性：**保持二進位制順序（Binary Ordered）**！  
這意味著：直接對若干段經過 BOCU-1 壓縮的原始二進位制位元組流進行字典序比較，其排序結果與將它們解壓回完整 Unicode 文字後的排序結果**完全嚴格一致**！這使得資料庫能夠在保持底層資料壓縮儲存的狀態下，直接在索引樹上執行高速二分查詢與歸併排序，同時它完全相容 MIME 協議，安全避開了 ASCII 關鍵控制符。

* **第 14 平面：特別用途補充平面（SSP, Supplementary Special-Purpose Plane, $0\text{xE0000}$–$0\text{xE0FFF}$）**：  
  類似“工程隔離檢疫區”，專門存放語言標籤標記與補充變體選擇符；
* **第 15 與 16 平面：私用補充平面（Supplementary Private Use Areas, Planes 15 & 16）**：  
  共計 $131,068$ 個完全對公眾開放的自定義碼位，供各類企業、字型檔廠商與專業研究機構自行定義內部專用字元。

### 1. 拉丁文字與西方語音擴充套件區（$0\text{x0000} \sim 0\text{x02AF}$）
* **基本拉丁（ASCII, $0\text{x0000}$–$0\text{x007F}$）**與 **Latin-1 補充（$0\text{x0080}$–$0\text{x00FF}$）**：原汁原味地保留了 ISO 8859-1 的全部碼位佈局；
* **拉丁文擴充套件-A 與擴充套件-B（$0\text{x0100}$–$0\text{x024F}$）**：收錄了中歐、波羅的海、土耳其語、以及西方語言學家為非洲及美洲土著語彙編的稀有拉丁變體字母；在此亦收錄了羅馬尼亞語中帶下逗號而非下加尾的特殊字母 ‘ș’ 與 ‘ț’，以及克羅埃西亞文與塞爾維亞文一一對應的三個雙合字母：‘Ǆ’（dž）、‘ǈ’（lj）與 ‘Ǌ’（nj）。由於這些雙合字母在詞首大寫（如 ‘Dž’）與全大寫（如 ‘DŽ’）時具有不同字形，Unicode 不得不為它們分別分配獨立碼位；
* **國際音標擴充套件（IPA Extensions, $0\text{x0250}$–$0\text{x02AF}$）**：國際語音學學會用於精確記錄全人類所有發音形態的單形態小寫音標符號。

### 2. 歐洲古典與東方基督教文種區（$0\text{x0370} \sim 0\text{x052F}$）
* **希臘文與科普特文（$0\text{x0370}$–$0\text{x03FF}$）**：包含現代單音希臘文與早期埃及科普特教會字母；而在隨後的 $0\text{x1F00}$–$0\text{x1FFF}$ 區段，則完整保留了古希臘語典雅的多音重音系統（Polytonic Greek，帶有粗氣符、柔氣符、銳音符與抑揚符）；
* **西裡爾字母及其擴充套件（$0\text{x0400}$–$0\text{x052F}$）**：不僅收錄了現代俄語、烏克蘭語、保加利亞語與塞爾維亞語字母，還收錄了古教會斯拉夫語（Old Church Slavonic）珍貴的早期西裡爾字母；
* **亞美尼亞文（$0\text{x0530}$–$0\text{x058F}$）**：公元五世紀聖梅斯羅布（Mesrop Mashtots）創立的高加索獨特文字。

### 3. 近東閃米特從右至左（RTL）文字區（$0\text{x0590} \sim 0\text{x08FF}$）
* **希伯來文（$0\text{x0590}$–$0\text{x05FF}$）**：包含現代方塊字母、聖經吟誦音符（Cantillation marks）與提比里亞母音點標記（Niqqud）；
* **阿拉伯文及其擴充套件（$0\text{x0600}$–$0\text{x06FF}$）**：收錄了阿拉伯語、波斯語、烏爾都語、普什圖語、信德語以及維吾爾語等所有使用阿拉伯字母書寫的語言符號體系；
* **敘利亞文（Syriac, $0\text{x0700}$–$0\text{x074F}$）**：美索不達米亞平原古基督教文學的重要載體；
* **它拿字母（Thaana, $0\text{x0780}$–$0\text{x07BF}$）**：印度洋島國馬爾地夫的官方書寫系統，其字母巧妙脫胎於阿拉伯數字與本地數字符號。

### 4. 印度次大陸與南亞婆羅米系文字群（$0\text{x0900} \sim 0\text{x0DFF}$）
涵蓋了梵文、印地文的天城文（Devanagari）、孟加拉文（Bengali）、果魯穆奇文（Gurmukhi，錫克教聖書文字）、古吉拉特文（Gujarati）、奧里亞文（Oriya）、泰米爾文（Tamil）、泰盧固文（Telugu）、卡納達文（Kannada）、馬拉雅拉姆文（Malayalam）與僧伽羅文（Sinhala）。這些文字在底層共用高度一致的婆羅米（Brahmi）音素音節架構，其碼位分佈呈現出近乎嚴密的平行映象佈局。

### 5. 東南亞、高加索與美洲土著文字區（$0\text{x0E00} \sim 0\text{x18FF}$）
* **泰文（Thai, $0\text{x0E00}$–$0\text{x0E7F}$）** 與 **寮國文（Lao, $0\text{x0E80}$–$0\text{x0EFF}$）**：詞間無空格的連續書寫系統；
* **藏文（Tibetan, $0\text{x0F00}$–$0\text{x0FFF}$）**：龐大的上下疊字子音與宗教法器記號；
* **緬甸文、喬治亞文與高棉文**；
* **衣索比亞文（Ethiopic, $0\text{x1200}$–$0\text{x137F}$）**：閃米特語族中唯一從左至右書寫的音節文字；
* **切羅基文（Cherokee, $0\text{x13A0}$–$0\text{x13F4}$）**：北美印第安酋長塞闊雅（Sequoyah）於 1820 年代獨立發明的音節文字，借用了拉丁字母外觀卻賦予其完全不同的發音（例如用字母 ‘D’、‘R’、‘T’ 分別表示音節 /a/、/e/、/i/）；
* **加拿大原住民音節文字（Unified Canadian Aboriginal Syllabics, $0\text{x1401}$–$0\text{x1676}$）**：以純粹幾何形狀及其空間旋轉方向表達不同母音的精妙書寫系統；
* **歐甘文字（Ogham, $0\text{x1680}$–$0\text{x169C}$）**與**如尼文字（Runic, $0\text{x16A0}$–$0\text{x16FF}$）**：古代凱爾特人刻於石柱稜線上的樹木文字，以及維京人的古代占卜文字；
* **菲律賓古代文字（塔加洛文、哈努諾文、布希德文、塔格巴努瓦文）**；
* **蒙古文（Mongolian, $0\text{x1800}$–$0\text{x18AF}$）**：源自回鶻字母、自上而下垂直書寫、且帶有極複雜詞首/詞中/詞尾變形的古老文字。

### 6. 通用符號、數學公式與技術製表符（$0\text{x2000} \sim 0\text{x2BFF}$）
這一大區是現代科學、製圖與數學排版的軍火庫：
* **常用標點（General Punctuation, $0\text{x2000}$–$0\text{x206F}$）**：收錄了各種寬度（Em-space, En-space, Thin-space）的排印空格、各式破折號（Em-dash, En-dash）、連字控制符（ZWJ / ZWNJ）；
* **上標與下標、貨幣符號（包括歐元符號 €）、組合符號用標記、字母式符號（如 $\mathbb{R}, \mathbb{C}, \aleph, \wp$）**；
* **數學運算子、幾何圖形、技術製表符（Box Drawing，DOS 介面遺老）**；
* **雜項技術符號、盲文點字（Braille Patterns, $0\text{x2800}$–$0\text{x28FF}$，用 8 位點陣的二進位制子集完美覆蓋全部 256 種盲文形態）**；
* **印刷雜符（Dingbats）**：全套繼承赫爾曼·察夫設計的 ITC Zapf Dingbats 經典裝飾符號。

### 7. 漢字部首、假名、注音與東亞大區（$0\text{x2E80} \sim 0\text{xA4CF}$）
* **康熙部首與表意文字描述符（IDC, $0\text{x2FF0}$–$0\text{x2FFB}$）**；
* **平假名、片假名、注音符號（Bopomofo）與諺文相容字母**；
* **彝文音節（Yi Syllables, $0\text{xA000}$–$0\text{xA48F}$）**：中國西南部大涼山彝族規範化的千餘個音節文字；
* **CJK 統一表意文字基本區（$0\text{x4E00} \sim 0\text{x9FA5}$）**：收錄了 20,902 箇中日韓常用漢字，構成了東亞文明的資訊中樞；
* **朝鮮文諺文音節（Hangul Syllables, $0\text{xAC00} \sim 0\text{xD7A3}$）**：收錄了全部 11,172 個預合成音節方塊字。

### 8. 代理區、私用區與相容區（$0\text{xD800} \sim 0\text{xDFFF}$ / $0\text{xE000} \sim 0\text{xFFFF}$）
* **代理區（Surrogates, $0\text{xD800}$–$0\text{xDFFF}$）**：永不分配任何字元的 UTF-16 專用禁區；
* **私用區（Private Use Area, PUA, $0\text{xE000}$–$0\text{xF8FF}$）**：共 6,400 個供使用者和廠商內部自由定義的私有碼位；
* **相容區與全半形變體區（$0\text{xFB00}$–$0\text{xFFFD}$）**：收錄了西文連字（ﬁ, ﬂ）、阿拉伯文連字形態、中日韓豎排相容符號、以及為了相容遺留終端而保留的半形假名與全形 ASCII 字元。

### 1. 第一輔助平面（SMP）：古代文獻與學術記號的方舟
SMP（第一平面，$\text{U+10000} \sim \text{U+1FFFF}$）堪稱全人類古代考古與死文字的數字萬神殿：
* **邁錫尼線形文字 B（Linear B, $0\text{x10000}$–$0\text{x100FA}$）**：克里特島米諾斯文明時期的古老文字（約公元前 2000 年），由英國建築師兼業餘考古學者邁克爾·文特里斯（Michael Ventris）於 1952 年奇蹟般破譯；
* **古希臘與愛琴海數字、古義大利字母與古哥特字母（Gothic）**；
* **美索不達米亞蘇美爾、阿卡德與波斯楔形文字（Cuneiform）**；
* **烏加里特文字（Ugaritic）與腓尼基字母（Phoenician）**；
* **德瑟雷特字母（Deseret, $0\text{x10400}$–$0\text{x1044F}$）**：19 世紀中葉猶他州摩門教徒試圖建立文化隔離而自創的一套奇異音標拼寫系統；
* **肖伯納字母（Shavian）**：劇作家蕭伯納在遺囑中資助建立的英語正字法改革字母；
* **卡羅須提文（Kharoshthi, $0\text{x10A00}$–$0\text{x10A5F}$）**：古代犍陀羅佛教文獻的核心文字；
* **音樂記號體系**：不僅收錄了現代西洋五線譜記號，還包括中世紀東正教**拜占庭音樂記號（Byzantine Musical Symbols）**與古希臘音樂記譜法；
* **數學字母數字符號（Mathematical Alphanumeric Symbols, $0\text{x1D400}$–$0\text{x1D7FF}$）**：為了讓數學公式中的粗體（$\mathbf{A}$）、黑板粗體（$\mathbb{R}, \mathbb{C}$）、手寫花體（$\mathcal{H}$）與哥特體（$\mathfrak{g}$）具有獨立的數學語義，Unicode 特意在 SMP 中為它們分別建立了嚴格獨立的碼位空間！

### 2. 第二輔助平面（SIP）：浩瀚漢字之海
SIP（第二平面，$\text{U+20000} \sim \text{U+2FFFF}$）幾乎完全被 **CJK 統一表意文字擴充套件 B 區（Extension B, $0\text{x20000}$–$0\text{x2A6DF}$）** 所佔據。

擴充套件 B 區收錄了驚人的 **42,711 個表意漢字**！這些漢字絕大多數來自中國古代《康熙字典》、《中華大字典》、《漢語大字典》、歷代地方誌、石刻碑帖以及佛教大藏經中的罕見異體字。在平面尾部，還收錄了來自臺灣 CNS 11643-1992 標準的補充相容表意文字（$0\text{x2F800}$–$0\text{x2FA1D}$）。擴充套件 B 區的入軌，使得全球學者在數字化整理千年前的甲骨、青銅銘文與宋元古籍時，第一次擺脫了字形造字與圖片貼圖的桎梏。

### 3. 第十四平面（SSP）：受控的特殊語言指令
SSP（第十四平面，$\text{U+E0000} \sim \text{U+E0FFF}$）收錄了極為罕見的控制標籤符：
* **語言標籤（Language Tags, $0\text{xE0001}$–$0\text{xE007F}$）**：這是整個 Unicode 標準中最具爭議的區塊。儘管高層標記語言（如 XML 的 `xml:lang`）能夠更乾淨地宣告語言，但為了在最受限的純文字通訊（如 URL）中亦能傳遞語言後設資料，Unicode 在此復刻了一整套 ASCII 碼的“幽靈標籤字元”；
* **補充變體選擇符（Variation Selectors Supplement, $0\text{xE0100}$–$0\text{xE01EF}$）**：共 240 個選擇符（`VS17` 至 `VS256`），與 BMP 中的 16 個變體選擇符相呼應，專門用於為海量生僻漢字與歷史古文字指定極其微妙的書寫流派異體字形。

## 候選文字與未來擴充套件（Scripts Proposed for Addition）

在作者成書之際，Unicode 的疆界依然在不斷向外開拓。人類學者與語言學家組成的專門委員會仍在夜以繼日地推進未入軌文字的標準化考察：
* **巴薩哇文（Bassa Vah）**：賴比瑞亞與獅子山沿海巴薩族人使用的古老字母。20 世紀初，一位名叫弗洛·達文·劉易斯（Flo Darvin Lewis）的化學家震驚地發現巴西與西印度群島的黑奴後裔仍在使用該文字，隨後他在賴比瑞亞大力推動了這一失落文字的復興；
* **布利斯符號（Blissymbolics）**：由查爾斯·布利斯（Charles Bliss）在 1950 年代發明的一套純表意視覺符號語言體系。布利斯原初夢想構建一種超越民族國家藩籬、促進國際和平與跨文化溝通的“世界共通語”，如今它廣泛應用於存在嚴重語言與認知交流障礙的殘障人士康復輔助交流系統；
* **瑟斯如尼文字（Cirth）**：托爾金（J.R.R. Tolkien）在奇幻文學史詩《魔戒》中為中土世界矮人與精靈專門發明的如尼符文體系；
* **赫梯楔形文字（Hittite）**：公元前 1600 至 1100 年安納托利亞中北部赫梯帝國使用的泥板楔形文字；
* **印度河文字（Indus Valley script）**：公元前 2500 至 1700 年哈拉帕印度河流域文明留下的神秘印章文字，至今仍未被破譯；
* **凱提文（Kaithi）**：古代至近代廣泛流行於北印度行政司法文書中的非正式草書文字；
* **蘭納文（Lanna / Tai Tham）**：泰國北部蘭納王國與西雙版納傣族的歷史佛教經書文字；
* **曼達文（Mandaic）**：伊拉克南部曼達教派使用的古代阿拉米文字變體；
* **柏格理苗文（Pollard script）**：二十世紀初英國傳教士塞繆爾·柏格理（Samuel Pollard）在中國西南烏蒙山區為苗族創立的精妙音節文字；
* **呂底亞文（Lydian）、卡里亞文（Carian）與呂基亞文（Lycian）**：小亞細亞安納托利亞半島的三大古希臘化前古代文字；
* **索永布文字（Soyombo）**：1686 年由蒙古高僧扎那巴扎爾創制的精美字母，其首個複合字元至今仍作為國家主權象徵傲然銘刻在蒙古國的國旗之上。

從字元的抽象神髓，到字形的千變萬化，再到十六進位制二進位制位元流在平面間的有序排列，Unicode 為人類文明築起了一座堅不可摧的數字巴別塔。

然而，僅有碼位的排列分配，並不足以支撐一篇賞心悅目的高質量文獻排印。每個字元在自然語言文字中具備怎樣的語法與排版特性？大寫與小寫如何對映？雙向文字如何折行？變音符號如何錨定？

這正是我們在**第三章：Unicode 字元核心屬性體系**中即將踏上的全新探索航程。
