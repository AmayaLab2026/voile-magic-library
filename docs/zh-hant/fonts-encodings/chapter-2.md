在上一章中，我們見證了前 Unicode 時代的諸神混戰：從 7 位 ASCII 到各式各樣互不兼容的 8 位 ISO 8859 擴展表，再到遠東漢字文化圈各自探索的雙字節代碼頁。這種地域性單字節與多字節標準割據的局面，給全球計算機信息交換帶來了無窮無盡的亂碼夢魘。

二十世紀八十年代末，一場旨在統一全人類所有書寫系統的計算革命應運而生。然而，要想構建一套能夠包容全世界過去、現在與未來所有文字的通用字符集，計算機科學家與語言學家首先必須退回到哲學的原點，回答幾個看似簡單、實則極爲深刻的本體論命題：**什麼是字符？什麼是字形？它們與計算機底層的二進制字節之間，究竟維持着怎樣的數理映射關係？**

## 哲學命題：字符與字形（Characters and Glyphs）

在日常口語與早期淺顯的計算機文獻中，“字符”（character）、“字模”（letterform）與“字形”（glyph）常常被不加區分地混淆使用。然而在現代計算機排印學與編碼理論中，**嚴格釐清字符與字形的邊界，是進入 Unicode 殿堂的絕對第一前提**。

* **字符（Character）**：  
  字符是一個**抽象的概念實體（abstract, intangible entity）**。它是書寫語言中最基礎的語義單元，擁有明確的語言學身份、名稱與規範屬性，但它**本身沒有任何固定的外貌、大小或視覺形態**。例如，拉丁字母 “小寫字母 a” 是一個字符，漢字 “文” 是一個字符，阿拉伯字母 “BEH” 亦是一個字符。字符存在於邏輯與概念的心智世界中。
* **字形（Glyph）**：  
  字形是字符在物理世界的**具體視覺呈現形態（graphical image / visual presentation）**。它是落在紙面上的一團墨跡，或是投射在顯示屏上的一組發光像素與貝塞爾矢量曲線。同一個字符，在不同的字體設計師筆下、在不同的歷史書寫流派中、或在不同的排版上下文中，可以呈現爲成百上千種截然不同的字形！

### 爲什麼計算機不應編碼字形？

早期某些字符編碼之所以走向失敗，其根本原因就在於試圖將特定的“視覺字形”硬塞入字符表中。試想：如果一種字體中包含正體 ‘a’、斜體 ‘*a*’、粗體 ‘**a**’、雙層 ‘a’ 與單層手寫體 ‘ɑ’，我們是否應當爲它們分別分配獨立的編碼碼位？

答案是絕對堅決的否定。如果將排版樣式的字形變體編碼爲獨立字符，全文檢索、自然語言處理、語義分詞與拼寫檢查將瞬間陷入滅頂之災：搜索引擎在匹配單詞 “apple” 時，將無法命中以斜體或粗體書寫的同一單詞！

因此，現代編碼哲學的至高法則爲：**編碼（encoding）只負責收錄抽象的“字符”（What you mean），而字體（font）則負責提供具象的“字形”（How it looks）**。

### Unicode 聯盟與 ISO 10646 的世紀合流

Unicode 運動最初於 1987 年由施樂帕洛阿爾託研究中心（Xerox PARC）的喬·貝克爾（Joe Becker）、李·柯林斯（Lee Collins）與蘋果公司的馬克·戴維斯（Mark Davis）共同倡議發起。1991 年 1 月，**Unicode 聯盟（Unicode Consortium）**在加州正式註冊成立。

與此並行，國際標準化組織（ISO）亦在推進其官方的國際多八位編碼字符集計劃——**ISO/IEC 10646**（即通用字符集 UCS, Universal Character Set）。在初期，ISO 陣營傾向於構建一個龐大的 31 位四維編碼空間（組 Group、面 Plane、排 Row、格 Cell），而早期 Unicode 陣營則主張構建一個緊湊高效、面向全人類現代常用文字的統一 16 位定長編碼（$2^{16} = 65,536$ 個碼位）。

兩大標準體系的分裂勢必造成全球軟件工業的災難。所幸在 1991 年底，雙方達成了極具遠見的重大歷史和解與合併協議：
* 雙方的字符碼位分配實現**完全嚴格的一對一同步（1:1 synchronization）**；
* ISO/IEC 10646 的第一組第零平面（Group 00, Plane 00）被永久確立爲 **基本多語言平面（BMP, Basic Multilingual Plane）**，其碼位與 Unicode 16 位空間完全一一對應；
* 雙方共用一套字符命名與屬性規範，徹底避免了世界計算標準的分裂。

## Unicode 十大第一原則（First Principles）

Unicode 體系之所以能夠超越此前所有字符編碼標準，在於其從誕生之初就確立了十項不可動搖的頂層公理架構（The Ten Principles of Unicode）：

1. **通用性（Universal repertoire）**：  
   Unicode 致力於收錄全世界一切書寫系統中所使用過的所有字符——不僅涵蓋所有現代活語言，亦囊括古文字、楔形文字、象形文字以及廣袤的數學、音樂、科學專業符號。
2. **高效性（Efficiency）**：  
   文本數據流必須易於解析與處理，絕不依賴像 ISO 2022 那樣容易因通信損耗導致後續全部解碼錯亂的有狀態“模式切換”。
3. **統一性（Uniformity）**：  
   在給定的編碼形式下，所有字符均採用統一寬度的基準數理單位，提供固定且確定性的碼位引用體系。
4. **明確性（Unambiguity）**：  
   每一個已分配的碼位（code point）在任何時間、任何語境下，均唯一且無歧義地對應一個具體的抽象字符。
5. **字符而非字形（Characters, not glyphs）**：  
   這是 Unicode 最核心的基石。Unicode 只爲抽象字符分配碼位，字形的外觀變體（粗體、斜體、連字、位置變換形態）交由上層字體與排版引擎負責。
6. **語義純文本原則（Plain text）**：  
   Unicode 序列僅承載純文本字符流。任何關於字體選擇、字號大小、行距、邊距與色彩的排版富文本屬性，均屬於外部標記語言（如 HTML、XML、RTF）的範疇。
7. **邏輯順序（Logical order）**：  
   在計算機內存與數據流中，字符必須嚴格按照人類思維書寫或朗讀發音的**邏輯先後順序（logical memory order）**存儲。對於阿拉伯文與希伯來文等從右向左（RTL）書寫的文字，其在內存中的存儲順序依然與從左向右（LTR）文字一致（先讀的在前，後讀的在後），屏幕上的逆向呈現完全交由排版系統的**雙向算法（Bidi Algorithm）**負責。
8. **字符統合（Unification）**：  
   當不同文化或同一語言體系中的若干字符，在書寫歷史、圖形起源與現代語義上具有同源性與共同特徵時，Unicode 堅決將其統合歸併爲一個單一碼位。最著名的範例莫過於**中日韓漢字統合（Han Unification）**。
9. **動態組合（Dynamic composition）**：  
   Unicode 允許帶有重音符或附加變音標記的字符通過“基礎字符 + 組合變音符”（Base Character + Combining Marks）在排版時動態拼合，而無需爲每一種可能的複合變音字符窮舉分配靜態碼位。
10. **永久穩定性（Stability）**：  
    一個碼位一旦被正式賦予某個字符，其**碼位數值與規範名稱永久不變、絕不回收、絕不重新分配**給其他字符；字符的核心規範屬性在後續版本中只增不刪，確保歷史數據的永恆可逆性。

## 技術命題：字符、碼位與字節

離開了物理硬件，純粹的哲學將無法運轉。在計算機系統內部，字符究竟如何落地爲磁盤上的比特與字節？

現代字符標準體系將字符的表徵清晰劃分爲五層模型架構：
$$\text{抽象字符庫（ACR）} \longrightarrow \text{編碼字符集（CCS）} \longrightarrow \text{字符編碼形式（CEF）} \longrightarrow \text{字符編碼方案（CES）} \longrightarrow \text{傳輸語法（TES）}$$

1. **抽象字符庫（Abstract Character Repertoire, ACR）**：  
   所有被標準認定的抽象字符的無序集合；
2. **編碼字符集（Coded Character Set, CCS）**：  
   將抽象字符庫中的每一個字符映射到一個唯一的非負整數——這個整數被稱爲**碼位（Code Point）**。在 Unicode 規範中，碼位以統一的前綴標記：
   $$\text{U+0000} \sim \text{U+10FFFF}$$
   總共定義了 $16 \times 2^{16} + 2^{16} = 17 \times 65,536 = 1,114,112$ 個碼位。其中排除了代理區碼位後的有效字符碼位被稱爲 **Unicode 標量值（Unicode scalar value）**。
3. **字符編碼形式（Character Encoding Form, CEF）**：  
   將整數碼位映射爲定長的計算機基本整數單元（Code Unit, 碼元），即 UTF-32、UTF-16 與 UTF-8；
4. **字符編碼方案（Character Encoding Scheme, CES）**：  
   處理多字節碼元序列在不同硬件架構下的**字節序（Endianness）**，如 UTF-16BE（大端序）、UTF-16LE（小端序）；
5. **傳輸編碼語法（Transfer Encoding Syntax, TES）**：  
   針對特定有損通信信道（如早期 7 位 SMTP 郵件）的數據封裝，如 Base64 與 Quoted-Printable。

## 主流字符編碼形式（CEF）深度解析

### 1. UTF-32 與定長表示

UTF-32（以及 ISO 10646 的 UCS-4）是概念上最純粹的編碼形式：它使用一個完整的 32 位（4 字節）無符號整數來直接表示每一個 Unicode 碼位。
* **優勢**：絕對的定長特性。字符串中第 $N$ 個字符必然位於內存偏移量 $4N$ 處，使得按索引隨機訪問字符的時間複雜度達到最優的 $O(1)$；
* **致命缺陷**：對絕大多數以拉丁字母、希臘字母或常用符號構成的西方文本而言，UTF-32 中高達 75% 的字節全部是無意義的零填充（`0x00 0x00 0x00`），造成了內存帶寬、緩存命中率與磁盤空間的極其慘烈的浪費。

### 2. UTF-16 與代理對（Surrogate Pairs）數學機制

當 Unicode 聯盟在 1990 年代中期意識到 16 位（65,536 個碼位）終將無法容納全人類的生僻漢字與古代文字時，工業界面臨抉擇：要麼全面推倒重來強推 32 位，要麼設計一種平滑兼容 16 位的優雅擴展算法。

計算機科學家們最終提出了極其精妙的**代理對（Surrogate Pairs）機制**，由此誕生了 **UTF-16**。

在基本多語言平面（BMP，即 $\text{U+0000} \sim \text{U+FFFF}$）中，Unicode 特意開闢了一片永遠不分配給任何實際字符的“真空禁區”——**代理區（Surrogates, $\text{U+D800} \sim \text{U+DFFF}$，共 2,048 個碼位）**，並將其均分爲兩大半區：
* **高半區代理（High Surrogates / Lead Surrogates）**：$\text{U+D800} \sim \text{U+DBFF}$（共 $1,024 = 2^{10}$ 個值）；
* **低半區代理（Low Surrogates / Trail Surrogates）**：$\text{U+DC00} \sim \text{U+DFFF}$（共 $1,024 = 2^{10}$ 個值）。

任何一個落在輔助平面（Planes 1–16，即 $\text{U+10000} \sim \text{U+10FFFF}$）的高位碼位 $N$，其數值必然滿足：
$$0 \le N - 0\text{x10000} \le 0\text{xFFFFF}$$

這個差值正好是一個 20 位的二進制數！UTF-16 巧妙地將這 20 位對半切分爲兩組 10 位：
* 高 10 位加上偏移基數 $0\text{xD800}$，生成一個**高半區代理字**（前導代理）；
* 低 10 位加上偏移基數 $0\text{xDC00}$，生成一個**低半區代理字**（後尾代理）。

#### 代理對數學轉換方程
* **編碼（碼位 $N \to$ 代理對 $(H, L)$）**：
  $$N' = N - 0\text{x10000}$$
  $$H = 0\text{xD800} + \lfloor N' / 0\text{x400} \rfloor = 0\text{xD800} + (N' \gg 10)$$
  $$L = 0\text{xDC00} + (N' \pmod{0\text{x400}}) = 0\text{xDC00} + (N' \ \& \ 0\text{x3FF})$$
* **解碼（代理對 $(H, L) \to$ 碼位 $N$）**：
  $$N = ((H - 0\text{xD800}) \times 0\text{x400}) + (L - 0\text{xDC00}) + 0\text{x10000}$$

由於高代理（`0xD800`–`0xDBFF`）與低代理（`0xDC00`–`0xDFFF`）的取值區間完全互斥，且與任何合法的 BMP 字符碼位完全隔離，解析引擎在數據流中向前或向後滑動時，能夠瞬間且無歧義地判定當前 16 位整數究竟是一個完整的單字符，還是代理對的頭部或尾部！

### 3. UTF-8：貝爾實驗室的傳世傑作

1992 年 9 月的一天晚上，在新澤西州的一家餐館裏，肯·湯普森（Ken Thompson）與羅布·派克（Rob Pike）在餐巾紙上勾勒出了計算歷史上最完美的編碼形式——**UTF-8**（原名 FSS-UTF）。

UTF-8 是一套純粹的**以 8 位字節爲基準的變長編碼形式（variable-width byte-based encoding）**，它使用 1 至 4 個字節來對 21 位的 Unicode 碼位進行精確切分：

| 標量碼位範圍（十六進制） | 字節數 | 字節 1（前導字節） | 字節 2（後隨字節） | 字節 3（後隨字節） | 字節 4（後隨字節） |
| :--- | :---: | :--- | :--- | :--- | :--- |
| `00000000`–`0000007F` | 1 | `0xxxxxxx` | — | — | — |
| `00000080`–`000007FF` | 2 | `110yyyyy` | `10xxxxxx` | — | — |
| `00000800`–`0000FFFF` | 3 | `1110zzzz` | `10yyyyyy` | `10xxxxxx` | — |
| `00010000`–`0010FFFF` | 4 | `11110uuu` | `10uuzzzz` | `10yyyyyy` | `10xxxxxx` |

#### UTF-8 的工程美學巔峯：
1. **絕對向下兼容 ASCII**：  
   對於 `0x00`–`0x7F` 的 128 個 ASCII 字符，UTF-8 使用單字節存儲，且最高位（bit 7）恆爲 0。這意味着任何合法的 ASCII 英文文件，**無需做任何字節轉換，本身就是一份完全合法的 UTF-8 文件**！所有原本只認識 C 語言 ASCII 字符串（以 `\0` 結尾）的古老系統工具（如 `grep`、`sed`、`awk`、編譯器），完全無需重寫即可直接操作 UTF-8。
2. **前綴自同步特性（Self-synchronizing）**：  
   在多字節序列中：
   * 前導字節（Lead Byte）的高位具有特徵掩碼：`110...` 代表後續跟隨 1 個字節；`1110...` 代表後續跟隨 2 個字節；`11110...` 代表後續跟隨 3 個字節；
   * 所有後隨字節（Continuation Bytes）的高兩位**恆定爲 `10xxxxxx`**！
   這種設計具有無與倫比的容錯性：如果由於網絡傳輸丟包或磁盤損壞導致字節流中間發生截斷，解碼器只需線性向後掃描，一旦遇到一個最高位不是 `10...` 的字節，便能**瞬間找回同步邊界（resynchronize）**重新開始正確解碼，絕不會讓單點故障滾雪球式污染整個後續文本！
3. **徹底根除大小端問題**：  
   由於 UTF-8 的數據單元本身就是 8 位字節，它在任何 CPU 架構下都不存在多字節整數的高低端重排問題，無需字節順序標記（BOM）。

### 4. 字節順序標記（Byte Order Mark, BOM）

在處理 UTF-16 與 UTF-32 時，多字節整數在內存中究竟應當高位在前（大端序 Big-Endian）還是低位在前（小端序 Little-Endian），取決於底層 CPU 的物理架構（Intel x86 採用小端，Motorola/PowerPC 採用大端）。

爲了在跨平臺交換文件時消除歧義，Unicode 特意設計了**字節順序標記（BOM）**：字符 **$U+\text{FEFF}$（零寬不換行空格 / ZERO WIDTH NO-BREAK SPACE）**。
* 如果接收方在文件開頭讀入的兩個字節是 `0xFE 0xFF`，則表明該文本採用大端序（UTF-16BE）；
* 如果讀入的兩個字節是 `0xFF 0xFE`，則表明該文本採用小端序（UTF-16LE）。爲什麼？因爲在 Unicode 規範中，**$U+\text{FFFE}$ 已經被永久聲明爲一個非法字符（Noncharacter）**，它在任何合法的 Unicode 文本中都絕不可能存在！一旦出現，唯一的解釋就是當前系統的字節讀取順序顛倒了。

## Unicode 宏觀組織：平面與區段路線圖

整個 Unicode 碼位空間（$U+0000 \sim U+10FFFF$）被均分爲 **17 個大小相等的平面（Planes）**，每個平面包含 $2^{16} = 65,536$ 個碼位。

在目前定義的 17 個平面中，已正式入駐字符的共有 **6 大核心平面**，如 **Figure 2-2** 所示：

![Unicode 版本 4 中已填充的六大平面全貌（Figure 2-2）](/images/fonts-encodings/fig2-2-populated-planes-unicode.png)
*Unicode 版本 4 中已填充的六大平面全貌（Figure 2-2）*
:::

*圖 2-2：Unicode 體系中已分配填充的六大平面（The six currently populated planes of Unicode）：第 0 平面（BMP）、第 1 平面（SMP）、第 2 平面（SIP）、第 14 平面（SSP）、以及第 15 與 16 平面（私用補充平面）。*

* **第 0 平面：基本多語言平面（BMP, Basic Multilingual Plane, $0\text{x0000}$–$0\text{xFFFF}$）**：  
  全書最核心的心臟地帶，囊括了當今現代世界正在使用的絕大多數書寫系統、全套通用符號體系與常用漢字表意文字；
* **第 1 平面：第一輔助平面 / 多語言補充平面（SMP, Supplementary Multilingual Plane, $0\text{x10000}$–$0\text{x1FFFF}$）**：  
  主要容納人類歷史上的古代文獻書寫系統（如埃及象形文字、蘇美爾與波斯楔形文字、古希臘古代碑銘與音樂記號）、專業數學字母數字符號、以及歷史古記號；
* **第 2 平面：第二輔助平面 / 表意文字補充平面（SIP, Supplementary Ideographic Plane, $0\text{x20000}$–$0\text{x2FFFF}$）**：  
  東亞中日韓表意漢字的海量擴充庫（收錄擴展 B、C、D 等大批古籍異體字、歷史地名及生僻姓氏字）；
* **第 14 平面：特別用途補充平面（SSP, Supplementary Special-Purpose Plane, $0\text{xE0000}$–$0\text{xE0FFF}$）**：  
  類似“工程隔離檢疫區”，專門存放語言標籤標記與補充變體選擇符；
* **第 15 與 16 平面：私用補充平面（Supplementary Private Use Areas, Planes 15 & 16）**：  
  共計 $131,068$ 個完全對公衆開放的自定義碼位，供各類企業、字庫廠商與專業研究機構自行定義內部專用字符。

*圖 2-3：Unicode 基本多語言平面（BMP）宏觀路線圖（The roadmap of Unicode's Basic Multilingual Plane）。橫軸與縱軸以十六進制網格標示，直觀展現了從西歐拉丁字母、近東閃米特文字、南亞天城文系統、直到東亞浩瀚漢字表意文字大區的完整拓撲結構。*

讓我們順着這幅宏偉的知識地圖，逐一勘察 BMP 各核心區塊的精妙佈局：

### 1. 拉丁文字與西方語音擴展區（$0\text{x0000} \sim 0\text{x02AF}$）
* **基本拉丁（ASCII, $0\text{x0000}$–$0\text{x007F}$）**與 **Latin-1 補充（$0\text{x0080}$–$0\text{x00FF}$）**：原汁原味地保留了 ISO 8859-1 的全部碼位佈局；
* **拉丁文擴展-A 與擴展-B（$0\text{x0100}$–$0\text{x024F}$）**：收錄了中歐、波羅的海、土耳其語、以及西方語言學家爲非洲及美洲土著語彙編的稀有拉丁變體字母；在此亦收錄了克羅地亞文與塞爾維亞文一一對應的三個雙合字母：‘Ǆ’（dž）、‘ǈ’（lj）與 ‘Ǌ’（nj）；
* **國際音標擴展（IPA Extensions, $0\text{x0250}$–$0\text{x02AF}$）**：國際語音學學會用於精確記錄全人類所有發音形態的單形態小寫音標符號。

### 2. 歐洲古典與東方基督教文種區（$0\text{x0370} \sim 0\text{x052F}$）
* **希臘文與科普特文（$0\text{x0370}$–$0\text{x03FF}$）**：包含現代單音希臘文與早期埃及科普特教會字母；而在隨後的 $0\text{x1F00}$–$0\text{x1FFF}$ 區段，則完整保留了古希臘語典雅的多音重音系統（Polytonic Greek，帶有粗氣符、柔氣符、銳音符與抑揚符）；
* **西裏爾字母及其擴展（$0\text{x0400}$–$0\text{x052F}$）**：不僅收錄了現代俄語、烏克蘭語、保加利亞語與塞爾維亞語字母，還收錄了古教會斯拉夫語（Old Church Slavonic）珍貴的早期西裏爾字母；
* **亞美尼亞文（$0\text{x0530}$–$0\text{x058F}$）**：公元五世紀聖梅斯羅布（Mesrop Mashtots）創立的高加索獨特文字。

### 3. 近東閃米特從右至左（RTL）文字區（$0\text{x0590} \sim 0\text{x08FF}$）
* **希伯來文（$0\text{x0590}$–$0\text{x05FF}$）**：包含現代方塊字母以及《希伯來聖經》特有的提比裏安發音點號（Niqqud）與誦讀吟誦標記（Cantillation marks）；
* **阿拉伯文及其展示形式（$0\text{x0600}$–$0\text{x06FF}$ 及 $0\text{xFB50}$–$0\text{xFEFC}$）**：不僅服務於阿拉伯語，更全面覆蓋了波斯語、烏爾都語、普什圖語、信德語以及維吾爾語的擴展字母；
* **敘利亞文（Syriac, $0\text{x0700}$–$0\text{x074F}$）**與**西非書面文字（N'Ko, $0\text{x07C0}$–$0\text{x07FF}$）**。

### 4. 印度次大陸與南亞婆羅米系文字羣（$0\text{x0900} \sim 0\text{x0DFF}$）
這一區域構成了 Unicode 中結構最爲繁複瑰麗的章節。所有源自古代阿育王婆羅米文字（Brahmi script）的南亞與東南亞音素文字（Abugida），全部嚴格遵循統一的音標網格結構並行排列：
* **天城文（Devanagari, $0\text{x0900}$–$0\text{x097F}$）**：用於書寫梵文、印地語與馬拉地語；
* **孟加拉文、果魯穆奇文（旁遮普語）、古吉拉特文、奧里亞文、泰米爾文、泰盧固文、卡納達文、馬拉雅拉姆文與僧伽羅文**；
* 緊隨其後的是中南半島的**泰文（$0\text{x0E00}$–$0\text{x0E7F}$）**、**老撾文（$0\text{x0E80}$–$0\text{x0EFF}$）**、神聖宏大的**藏文（Tibetan, $0\text{x0F00}$–$0\text{x0FFF}$）**、以及**緬甸文與高棉文**。

### 5. 通用符號、數學公式與技術製表符（$0\text{x2000} \sim 0\text{x2BFF}$）
* **通用標點符號（$0\text{x2000}$–$0\text{x206F}$）**：包含了排印學上所有嚴格度量的空格（全角空格 Em space、半角空格 En space、三分之一空格 Thin space、不換行空格）、破折號（Em dash, En dash）、彎引號（‘ ’ “ ”）、以及現代雙向文本控制符（LRM、RLM、ZWNJ、ZWJ）；
* **數學符號矩陣**：包括數學運算符（$\sum, \prod, \int, \sqrt{}$）、箭頭符號、幾何圖形、技術控制符號與盲文點字（Braille Patterns）。

### 6. 漢字表意文字與東亞文字大區（$0\text{x2E80} \sim 0\text{xA4CF}$）
這是基本多語言平面中面積最遼闊的陸地：
* **部首與結構符**：康熙字典部首（$0\text{x2F00}$–$0\text{x2FDF}$）與漢字表意文字描述符（IDC, $0\text{x2FF0}$–$0\text{x2FFF}$）；
* **假名與注音**：日文平假名、片假名以及漢語注音符號（Bopomofo）；
* **CJK 統一表意文字擴展 A 區（Extension A, $0\text{x3400}$–$0\text{x4DBF}$）**：收錄 6,582 個生僻表意漢字；
* **CJK 統一表意文字主區（CJK Unified Ideographs, $0\text{x4E00}$–$0\text{x9FFF}$）**：**整整 20,902 個核心漢字**，集結了中日韓三國最核心的通用字彙；
* **彝文音節文字（$0\text{xA000}$–$0\text{xA48F}$）**與**現代韓文諺文音節區（Hangul Syllables, $0\text{xAC00}$–$0\text{xD7A3}$）**：完整收錄全部 $11,172$ 個由初聲、中聲、終聲組合而成的現代韓文音節方塊字。

### 1. 第一輔助平面（SMP）：古代文獻與學術記號的方舟
SMP（第一平面，$\text{U+10000} \sim \text{U+1FFFF}$）堪稱全人類古代考古與死文字的數字萬神殿：
* **邁錫尼線形文字 B（Linear B, $0\text{x10000}$–$0\text{x1007F}$）**：英國建築師邁克爾·文特里斯（Michael Ventris）於 1952 年破譯的歐洲最古老文獻文字；
* **美索不達米亞蘇美爾與阿卡德楔形文字（Cuneiform, $0\text{x12000}$–$0\text{x123FF}$）**；
* **音樂與記號體系**：不僅完整收錄了現代西洋五線譜記號（音符、休止符、調號），更罕見地收錄了中世紀東正教**拜占庭音樂記號（Byzantine Musical Symbols）**與古希臘音樂記譜法；
* **數學字母數字符號（Mathematical Alphanumeric Symbols, $0\text{x1D400}$–$0\text{x1D7FF}$）**：爲了讓數學公式中的粗體（$\mathbf{A}$）、黑板粗體（$\mathbb{R}, \mathbb{C}$）、手寫花體（$\mathcal{H}$）與哥特體（$\mathfrak{g}$）具有獨立的數學語義，Unicode 特意在 SMP 中爲它們分別建立了嚴格獨立的碼位空間！

### 2. 第二輔助平面（SIP）：浩瀚漢字之海
SIP（第二平面，$\text{U+20000} \sim \text{U+2FFFF}$）幾乎完全被 **CJK 統一表意文字擴展 B 區（Extension B, $0\text{x20000}$–$0\text{x2A6DF}$）** 所佔據。

擴展 B 區收錄了驚人的 **42,711 個表意漢字**！這些漢字絕大多數來自中國古代《康熙字典》、《中華大字典》、《漢語大字典》、歷代地方誌、石刻碑帖以及佛教大藏經中的罕見異體字。擴展 B 區的入軌，使得全球學者在數字化整理千年前的甲骨、青銅銘文與宋元古籍時，第一次擺脫了字形造字與圖片貼圖的桎梏。

### 3. 第十四平面（SSP）：受控的特殊語言指令
SSP（第十四平面，$\text{U+E0000} \sim \text{U+E0FFF}$）收錄了極爲罕見的控制標籤符：
* **語言標籤（Language Tags, $0\text{xE0001}$–$0\text{xE007F}$）**：允許在純文本內部隱蔽嵌入當前文字所屬的 RFC 3066 語言代碼（如 `en-US` 或 `zh-CN`）；
* **補充變體選擇符（Variation Selectors Supplement, $0\text{xE0100}$–$0\text{xE01EF}$）**：用於爲 CJK 漢字或古文字指定極其微妙的歷史異體寫法。

## 候選文字與未來擴展（Scripts Proposed for Addition）

在作者成書之際，Unicode 的疆界依然在不斷向外開拓。人類學者與語言學家組成的專門委員會仍在夜以繼日地推進未入軌文字的標準化考察：
* **埃及聖書體象形文字（Egyptian Hieroglyphs）**：數千個描繪神明、鳥獸、法老與器物的象形表意符號，如今已在後續 Unicode 版本中正式落定於 SMP；
* **伯格理苗文（Pollard script）**：二十世紀初英國傳教士柏格理在中國西南苗族聚居區創立的精妙音節文字；
* **復活節島朗格朗格木板文（Rongorongo）**：太平洋絕海孤島上至今未被完全破譯的神祕象形木刻銘文；
* **古南阿拉伯文字（Ancient South Arabian）**：前伊斯蘭時期也門與紅海沿岸商路的古老文字；
* **蒙古索永布文字（Soyombo）**：1686 年由蒙古高僧扎那巴扎爾創制的精美字母，其首字母至今仍作爲國家主權象徵傲然銘刻在蒙古國的國旗之上。

---

從字符的抽象神髓，到字形的千變萬化，再到十六進制二進制比特流在平面間的有序排列，Unicode 爲人類文明築起了一座堅不可摧的數字巴別塔。

然而，僅有碼位的排列分配，並不足以支撐一篇賞心悅目的高質量文獻排印。每個字符在自然語言文本中具備怎樣的語法與排版特性？大寫與小寫如何映射？雙向文本如何折行？變音符號如何錨定？

這正是我們在**第三章：Unicode 字符核心屬性體系**中即將踏上的全新探索航程。
