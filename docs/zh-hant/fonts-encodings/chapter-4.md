# 第四章 · 規範化、雙向算法與東亞字符體系
### Chapter 4: Normalization, bidirectionality, and East Asian characters

**著者：雅尼斯·哈拉蘭博斯（Yannis Haralambous, Ph.D.）**  
*選自《Fonts & Encodings》第 127–158 頁*  
*譯者：ヴワル魔法図書館（Voile Magic Library）文獻翻譯工房*

---

在本章中，我們將深入探討 Unicode 體系中表面上看似毫無關聯、但皆要求深厚計算機技術背景的三個核心高級領域。對於普通文字處理者而言，它們或許顯得過於晦澀精深；然而對於計算語言學學者、排版引擎架構師以及系統級軟件工程師而言，它們卻是決定數字文字處理成敗的基石：
1. **分解與規範化流程**（Decomposition and Normalization）：這是所有面向萬維網（Web）與數據庫的文本引擎開發者所必須徹底精通的底層算法；
2. **雙向文本排版算法**（The Bidirectional Algorithm）：這是正確呈現阿拉伯文、希伯來文與敘利亞文等從右至左文字不可或缺的核心渲染管線；
3. **東亞書寫系統**（East Asian Scripts）：涵蓋中日韓統一表意文字（CJK Ideographs）與朝鮮語諺文（Hangul）音節塊的編碼哲學、字形構造學與字母組合算術。

## 分解與規範化（Decompositions and Normalizations）

### 組合字符與規範結合類（Combining Characters & Combining Classes）

在上一章中，我們已經對**組合字符**（Combining Characters）區塊以及非進幅附加符號（Nonspacing Marks）進行了宏觀介紹。然而，這些字符在計算機底層究竟是如何運作的？

在排版渲染時，一個組合字符的字形必須與它所依附的**基底字符**（Base Character）發生幾何物理交互。這種交互呈現出千變萬化的形式：銳音符位於字母上方，下加符（Cedilla）位於字母下方，希伯來文的重音點（Dagesh）嵌入字母腹中，等等。

部分附加符號在空間與語言學上是彼此完全獨立的：在一個字母下方添加下加符，絲毫不會妨礙在字母上方繼續疊加揚抑符（Circumflex）。然而，另一些附加符號則佔據着完全相同的空間拓撲位置，此時它們出現的物理先後次序便具有決定性的正字法意義。例如在越南語（Vietnamese）中，字母 ‘$\hat{\tilde{\text{E}}}$’ 同時帶有揚抑符與硬顎波浪符，並且必須嚴格遵循先揚抑、後波浪的層疊次序；顛倒其次序將被視爲嚴重的拼寫錯誤。

這一切事實昭示了兩個核心原理：
1. 變音符號可以劃分爲彼此“正交”（Orthogonal）的空間與功能範疇；
2. 在同一個正交範疇內部，附加符號的施加次序至關重要。

Unicode 通過引入**規範結合類**（Canonical Combining Class，簡稱 `ccc`）將這一機制形式化。在 Unicode 5.0 中，共收錄了 352 個組合字符，它們被精細分配在 53 個結合類之中。

每個結合類被賦予一個 0 至 255 之間的整數數值：
- **類 0**：基底字符（Base Characters）以及所有產生進幅間距的獨立字符；
- **類 1**：重疊覆蓋符號（Overlay Marks，如劃槓、斜槓）；
- **類 7**：希伯來文音調符號（Nukta）；
- **類 9**：印度系文字維拉瑪符號（Virama / Halant）；
- **類 200..240**：依空間拓撲位置嚴格細分的結合類：
  - 類 202：下加附着符號（如中世紀拉丁文尾符）；
  - 類 216：迴旋附着符號；
  - 類 218：左下結合符號；
  - 類 220：正下方結合符號（Below，如 Cedilla、下加點）；
  - 類 222：右下結合符號；
  - 類 228：左上結合符號；
  - 類 230：正上方結合符號（Above，如 Acute、Grave、Circumflex、Macron、Tilde）；
  - 類 232：右上結合符號；
  - 類 240：希臘文變音符號專有類（Iota Subscript）。

### 規範重排序算法（Canonical Ordering Algorithm）

假設我們在內存中擁有一串由基底字符與多個組合變音符拼接而成的字符序列。由於不同輸入法、鍵盤驅動或 OCR 軟件的錄入習慣差異，這些結合符號在原始字節流中的存儲順序可能完全不同。如果計算機直接進行按位二進制比對，就會將字形完全相同、發音完全相同的兩個詞彙誤判爲不同內容。

爲了徹底消解這種歧義，Unicode 規定了著名的**規範重排序算法**（Canonical Ordering Algorithm）：
1. 遍歷字符串中的字符序列，獲取每個字符的結合類數值 `ccc`；
2. 保持所有結合類爲 0 的基底字符位置絕對不動；
3. 對於依附於同一基底字符之後的一連串結合字符，**依據其規範結合類數值 `ccc` 的升序（從低到高）進行穩定排序**；
4. 若兩個相鄰結合字符具有完全相同的結合類數值（且不爲 0），則保持它們原有的相對輸入先後順序不變。

經過規範重排序清洗後，原本次序混亂的變音符序列將被收斂爲數學上嚴格唯一的規範表示形式。

---

### 規範合成（Canonical Composition）

在解決重排序問題後，下一個核心挑戰是：某些字符在 Unicode 中既可以表示爲一個預先組合好的獨立單字符（Precomposed Character，如 ‘é’ `U+00E9`），也可以表示爲一個基底字母加結合符號的拆分序列（“e” `U+0065` + “´” `U+0301`）。

在 Unicode 的架構哲學中，這兩者被稱爲**規範等價**（Canonically Equivalent）。排版軟件與搜索引擎必須無條件地將它們視爲完全一致的同一對象。

將預組合單字符拆解爲基底與結合符序列的過程，稱爲**規範分解**（Canonical Decomposition）；反之，將基底與結合符合併爲一個獨立預組合單字符的過程，則稱爲**規範合成**（Canonical Composition）。

爲了確保合成過程的確定性與單向收斂，Unicode 嚴格規定了**主合成字符**（Primary Composites）的判定標準，並排除了那些具有複合分解歷史缺陷的孤立字符。

---

### 四大規範化形式（The Four Normalization Forms）

將上述分解、重排序與合成技術系統化組合，Unicode 聯合會確立了舉世聞名的**四大規範化形式**（The Four Unicode Normalization Forms，詳見 UAX #15）：

| 形式代碼 | 英文全稱 | 核心算法流程與特徵定義 |
| :--- | :--- | :--- |
| **`NFD`** | Normalization Form D（規範分解形式） | 先對所有字符執行遞歸的**規範分解**，隨後執行**規範重排序**。結果文本中所有預組合帶音符字母均被徹底拆卸爲基底加變音符的標準序列。 |
| **`NFC`** | Normalization Form C（規範合成形式） | 先執行 `NFD`（完整規範分解與重排序），隨後在可能的最大範圍內執行**規範合成**。這是**現代萬維網（W3C）官方推薦的首選通用傳輸格式**。 |
| **`NFKD`** | Normalization Form KD（兼容分解形式） | 先對所有字符執行徹底的**兼容分解**（包括連字拆解、上標下標降級、粗體花體等樣式剝離、全角半角歸一），隨後執行規範重排序。語義信息會發生部分不可逆削減。 |
| **`NFKC`** | Normalization Form KC（兼容合成形式） | 先執行 `NFKD`（完整兼容分解），隨後執行最大規範合成。常用於搜索引擎文本清洗、無差別模糊匹配與通用標識符預處理。 |

## 雙向排版算法（The Bidirectional Algorithm / UAX #9）

### 段落排印的宏觀流動與微觀斷行

在人類書寫文明的畫卷中，西方拉丁語系文字遵循從左至右（Left-to-Right, LTR）的書寫方向；而閃米特語系的希伯來文（Hebrew）與阿拉伯文（Arabic）則遵循從右至左（Right-to-Left, RTL）的書寫方向。當這兩種截然相反的書寫傳統在同一個段落、甚至同一行文字中相互交織碰撞時，便誕生了計算排版領域最精妙複雜的算法構型——**Unicode 雙向排版算法**（Unicode Bidirectional Algorithm，簡稱 Bidi 算法）。

要理解雙向算法，首先必須辨明**宏觀全局語境**（Global Context）與**微觀局部流**（Local Run）的本質區別。

### 雙向字符類型（Bidirectional Character Types）

在 `UnicodeData.txt` 的第 4 號字段中，記錄了每一個字符的**雙向字符類型**（Bidi Character Type）。Unicode 將全體字符劃分爲 19 種類型，並歸入三大陣營：

1. **強字符（Strong Types）**：具有不可動搖的固有書寫方向性，絕不隨上下文而動搖：
   - `L`（Left-to-Right）：強左至右字符（拉丁字母、漢字、假名、諺文等）；
   - `R`（Right-to-Left）：強右至左字符（非阿拉伯系 RTL 字符，如希伯來字母）；
   - `AL`（Right-to-Left Arabic）：阿拉伯文字及其衍生字符，具有特化的數字上下文關聯。
2. **弱字符（Weak Types）**：其方向性相對被動，極易受鄰近強字符的影響：
   - `EN`（European Number）：歐洲數字（0..9）；
   - `ES`（European Number Separator）：歐洲數字分隔符（加號、減號）；
   - `ET`（European Number Terminator）：歐洲數字終止符（度數符號、百分號、貨幣符）；
   - `AN`（Arabic-Indic Number）：阿拉伯-印度數字；
   - `CS`（Common Number Separator）：通用數字分隔符（逗號、冒號、小數點）；
   - `NSM`（Nonspacing Mark）：非進幅附加符號；
   - `BN`（Boundary Neutral）：邊界中性符（零寬字符、控制碼）。
3. **中性字符（Neutral Types）**：本身完全不具備固有方向性，其排印方向徹底隨波逐流：
   - `B`（Paragraph Separator）：段落分隔符；
   - `S`（Segment Separator）：段內製表分隔符；
   - `WS`（Whitespace）：普通空白空格符；
   - `ON`（Other Neutral）：其餘一切符號與通用標點（感嘆號、括號、斜槓等）。
4. **顯式格式控制符（Explicit Formatting Codes）**：
   - `LRE`、`RLE`：顯式指定子串進入 LTR 或 RTL 嵌入模式；
   - `LRO`、`RLO`：強行覆蓋（Override）後續字符的方向性；
   - `PDF`（Pop Directional Format）：終結當前嵌入或覆蓋模式，彈出調用棧。

### 雙向算法六大步驟（The Six Steps of UAX #9）

1. **確定段落邊界與基底嵌入級別（Base Level）**：
   掃描段落中出現的第一個強方向性字符。若爲 `L`，則段落基底級別設爲 0（偶數，代表 LTR）；若爲 `R` 或 `AL`，則基底級別設爲 1（奇數，代表 RTL）。
2. **處理顯式嵌入與覆蓋狀態棧（Explicit Levels and Overrides）**：
   建立深度可達 61 級的方向棧。每當遇到 `LRE` / `RLE` / `LRO` / `RLO` 時將新級別壓入棧頂；遇到 `PDF` 時彈出棧頂。字符隨之繼承其所處的顯式級別。
3. **解析弱類型（Resolving Weak Types）**：
   依據嚴格的 `W1` 至 `W7` 規則狀態機，消解非進幅標誌、以及將位於特定數字前後的分隔符與終止符轉化爲確定類型的弱數字。
4. **解析中性類型（Resolving Neutral Types）**：
   依據 `N1` 與 `N2` 規則，若中性字符兩端被相同方向的強字符所包夾，則該中性字符蛻變爲該強方向；否則，它將退化並服從當前所處環境的嵌入級別方向。
5. **計算最終隱式嵌入級別（Resolving Implicit Levels）**：
   結合字符的固有屬性與計算得到的環境級別，對歐洲數字與阿拉伯數字施加微調加權，得出最終的整數嵌入級別值。
6. **執行子串逆序反轉（Reversing Substrings）**：
   這是整個算法最富美感的高潮：**在內存中尋找當前最高級別的字符運行切片，將其原地反向顛倒；隨後將級別閾值遞減 1，再次反轉包含該級別的更大連續切片，直至回退到段落基底級別。** 經過這番自內向外的層層反轉，原本在邏輯內存中線序存儲的雙向文本便在屏幕上完美呈現出符合人類自然閱讀習慣的視覺佈局！

### 鏡像屬性（Mirroring & BidiMirroring.txt）

在雙向排版中，括號等成對標點符號帶來了一個隱蔽而深邃的問題：在英文（LTR）中，開括號 ‘(’ 開口朝右；但當我們在一段希伯來文（RTL）中書寫開括號時，由於閱讀方向是從右向左流動的，因此“開啓”該語段的括號在視覺上必須**開口朝左**！

如果排版引擎機械地保留原有字形，原本具有開啓語義的括號就會在視覺上變成閉括號。

爲此，Unicode 在 `UnicodeData.txt` 的第 9 字段中設立了鏡像標誌位（`Bidi_Mirrored`），並在配套數據庫 `BidiMirroring.txt` 中詳盡維護了 320 對具有鏡像拓撲關係的字符映射表（如 `0028; 0029` 圓括號對、`003C; 003E` 小於大於號對等）。排版引擎在 RTL 環境下會自動調用其鏡像字形進行替換。

## 東亞書寫系統（East Asian Scripts）

### 中日韓漢字表意文字（Ideographs of Chinese Origin / CJK）

漢字是人類文明史上唯一歷經數千年風霜而延綿不絕的語素文字體系（Logographic Writing System）。面對海峽兩岸、日本、韓國以及越南在漫長曆史中演化出的龐大字庫，早期的數字編碼標準陷入了各自爲政的泥潭。

Unicode 聯合會與 ISO/IEC 聯合技術委員會所取得的里程碑式成就，正是啓動了**中日韓漢字統合工程**（Han Unification）。專家委員會確立了三項金科玉律：
1. **源字典考證法**：凡見於《康熙字典》、《大漢和辭典》、《漢語大字典》或《大韓民國漢字字典》的字形均予嚴格覈驗；
2. **部首與筆畫分析法**：依據東漢許慎《說文解字》確立、並經《康熙字典》發揚光大的 **214 康熙部首體系**，計算字根歸屬與剩餘筆畫數；
3. **字源異體字分離原則**：對於在中國大陸、臺灣、日本、韓國呈現不同現代字體風貌（如字形筆畫存在微小印刷風格差異）但歷史源流、構字理據與語義完全相同的漢字，**統一賦予同一個唯一的 Unicode 編碼碼點**，將其細微差異交由字體字形（Glyphs）與樣式系統去呈現；唯有當兩個字在歷史源字典中確立爲不同字素時，方分別賦予獨立碼點。

#### 漢字結構描述字符（Ideographic Description Characters, IDC）
儘管 Unicode 收錄了數萬個統合漢字，但在歷史古籍、佛教經典、方言俚字乃至現代人名中，依然存在着數以十萬計的未編碼罕用字。爲了徹底終結“造字無門”的困境，Unicode 極富創造力地在 `U+2FF0..U+2FFB` 區塊設立了 12 個**漢字結構描述字符**（IDC）：

### 字符描述語言（Character Description Language, CDL）

在 20 世紀 80 年代，漢學專家湯姆·畢曉普（Tom Bishop）與文林軟件研究所（Wenlin Institute）在開發漢字教學系統時，開創了一種革命性的漢字結構解析模型。伴隨着 XML 技術的風靡，這套模型被昇華爲國際標準提案——**字符描述語言**（Character Description Language，簡稱 CDL）。

CDL 的核心哲學在於：**任何複雜的漢字均可以通過遞歸的 XML 樹狀結構，由最基礎的筆畫（Strokes）與構件（Components）在標準座標系空間內拼裝而成。**

例如，漢字構件不僅可以通過其自身的 Unicode 碼點進行定位引用，更能在網格座標系中精確限定其外接包圍盒（Bounding Box）：

```xml
<cdl char="L">
  <comp char="K" points="0,0 40,128"/>
  <comp char="E" points="60,12 128,128"/>
</cdl>
```

而在原子筆畫層級，CDL 將中國傳統書法理論中的“永字八法”進行了現代數字化形式重構，系統提煉出了整整 **42 種基礎筆畫原型**。以下歷史文獻圖版完整收錄了全部 42 種基本筆畫的官方形態、漢語拼音定名、標準英文縮寫及真實構字範例：

- **撇（piě, p）**：向左下輕快掠出的弧線筆畫；

- **圈（quān, o）**：閉合圓圈筆畫。

### 朝鮮語諺文（Hangul）與字母算術

在公元 15 世紀以前，朝鮮半島一直借用漢字（吏讀、口訣）來記錄其與漢語完全不同的黏着語系母語。由於漢字極其深奧難懂，廣大平民階層深陷文盲困境。

公元 1443 年，朝鮮王朝第四代君主**世宗大王**（King Sejong the Great, 1397–1450）召集集賢殿學者，歷經數年嘔心瀝血的祕密鑽研，於 1446 年正式頒佈了曠世鉅作《**訓民正音**》（Hunminjeongeum，意爲“教導百姓以正確聲音”）。這部被諸多現代西方語言學家讚譽爲“**人類歷史上設計最爲精妙完備的書寫系統**”的誕生，徹底改寫了東亞文字史。

諺文的偉大之處在於其高度自洽的**發音器官象形理論**與**東方哲學宇宙觀**：

### 現代諺文音節塊的數字算法藝術

在書寫時，朝鮮語諺文並非線性排布字母，而是將一個或多個聲母輔音、介音元音與韻尾輔音，在正方形漢字方塊的二維空間內拼接拼裝爲一個獨立的**音節塊**（Syllable Block）。

例如，聲母 ‘ᄒ’（h）+ 韻母 ‘ᅡ’（a）+ 韻尾 ‘ᆫ’（n）凝結爲一個方塊字：‘**한**’（Han）。

在 Unicode 編碼體系中，爲了同時滿足傳統音素級檢索與現代高速文本處理的雙重需求，標準設立了雙軌制：
1. **諺文字母區塊**（Hangul Jamo, `U+1100..U+11FF`）：記錄純粹的單個初聲、中聲與終聲字母；
2. **預組合諺語音節區塊**（Hangul Syllables, `U+AC00..U+D7A3`）：以驚人的氣魄完整分配了現代朝鮮語中所可能組合出的**全部 11,172 個標準音節塊**！

更令人歎服的是，這 11,172 個音節塊的碼點絕非隨機散亂分配，而是嚴格遵循嚴密的**離散數學多項式算術法則**：

現代韓語拼音包含：
- **初聲（Choseong, L）**：共 19 種可能（$L_0$ 至 $L_{18}$）；
- **中聲（Jungseong, V）**：共 21 種可能（$V_0$ 至 $V_{20}$）；
- **終聲（Jongseong, T）**：共 28 種可能（包含 0 號“無終聲”以及 27 種輔音韻尾）。

三者組合的笛卡爾積空間恰好爲：
$$N = 19 \times 21 \times 28 = 11{,}172$$

任何一個三元組 $(L, V, T)$ 所對應的預組合音節碼點 $S$，均可以通過以下簡潔優美的線性算式無損計算得出：

$$\text{CodePoint} = \text{0xAC00} + (L_{\text{index}} \times 21 \times 28) + (V_{\text{index}} \times 28) + T_{\text{index}}$$

反之，給定任意一個落在 `0xAC00..0xD7A3` 範圍內的韓語音節，計算引擎只需進行簡單的除法與模運算（Modulo Arithmetic），即可在零內存開銷、零查表延遲的前提下，瞬間將其解構還原爲最本源的初聲、中聲與終聲字母序列！
