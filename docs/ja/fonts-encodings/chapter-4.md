本章において我々は、Unicode 体系の中で一見すると相互に無関係に見えながらも、いずれも深遠な計算機技術の知見を要求する 3 つの中核的・高度領域へと深く分け入る。一般的なワープロソフトの利用者にとっては過度に難解に見えるかもしれないが、計算言語学の研究者、組版エンジンの設計者、そしてシステムソフトウェアの技術者にとっては、これらはデジタル文字処理の成否を決定づける最重要の礎石である。
1. **分解と正規化プロセス**（Decomposition and Normalization）：Web 技術やデータベース向けテキストエンジンの開発者が完全に習熟すべき低水準アルゴリズム。
2. **双方向テキスト組版アルゴリズム**（The Bidirectional Algorithm）：アラビア文字、ヘブライ文字、シリア文字などの右横書き（RTL）文字を正しく組版・レンダリングするための不可欠の中核パイプライン。
3. **東アジアの書記体系**（East Asian Scripts）：日中韓統合漢字（CJK Ideographs）および朝鮮語ハングル（Hangul）音節ブロックの符号化哲学、グリフ構造学、そして字母の組み合わせ算術。

## 分解と正規化（Decompositions and Normalizations）

### 結合文字と規準結合クラス（Combining Characters & Combining Classes）

前章において、我々は**結合文字**（Combining Characters）ブロックおよび非前進記号（Nonspacing Marks）の概要を学んだ。しかし、これらの文字はコンピュータの低水準においていかに機能しているのであろうか？

組版レンダリング時、結合文字のグリフはそれが依拠する**基底文字**（Base Character）と幾何学的・物理的に相互作用しなければならない。この相互作用は千変万化の形態をとる。アキュートアクセントは文字の上部に配置され、セディーユ（Cedilla）は文字の下部に位置し、ヘブライ語のダゲシュ（Dagesh）は文字の内部に埋め込まれる。

一部の付加記号は、空間的にも言語学的にも互いに完全に直交・独立している。文字の下部にセディーユを付加することは、文字の上部にサーカムフレックスを重ねることを些かも妨げない。しかし、他の付加記号はまったく同一の空間トポロジーを占有し、その出現順序が決定的な正書法上の意味を持つ。例えばベトナム語（Vietnamese）において、字母 ‘$\hat{\tilde{\text{E}}}$’ はサーカムフレックスとチルダの双方を伴い、まずサーカムフレックス、次いでチルダという厳格な積層順序に従わねばならない。順序の反転は重大な綴り間違いと見なされる。

これらの事実は、二つの根本的原理を明確に示している。
1. 分音記号は、空間的・機能的に「直交」（Orthogonal）する範疇へと分類できる。
2. 同一の直交範疇内において、付加記号の適用順序は極めて重要である。

Unicode は**規準結合クラス**（Canonical Combining Class、略称 `ccc`）を導入することでこの機構を定式化した。Unicode 5.0 において、収録された 352 個の結合文字は 53 の結合クラスへと精緻に配分されている。

個々の結合クラスには $0 \sim 255$ の整数値が割り振られている。
- **クラス 0**：基底文字（Base Characters）、および前進幅を持つすべての独立文字。
- **クラス 1**：重複被覆記号（Overlay Marks、スラッシュ重ねなど）。
- **クラス 7**：ヘブライ語ヌクダ記号（Nukta）。
- **クラス 9**：インド系文字ヴィラーマ記号（Virama / Halant）。
- **クラス 200..240**：空間トポロジー位置に応じて厳格に細分化された結合クラス：
  - クラス 202：下部付着記号（中世ラテン語の尾符など）。
  - クラス 216：回旋付着記号。
  - クラス 218：左下結合記号。
  - クラス 220：真下結合記号（Below、セディーユや下付きドットなど）。
  - クラス 222：右下結合記号。
  - クラス 228：左上結合記号。
  - クラス 230：真上結合記号（Above、アキュート、グレイブ、サーカムフレックス、マクロン、チルダなど）。

### 規準並べ替えアルゴリズム（Canonical Ordering Algorithm）

規準結合クラスの数値体系が確立されたことにより、結合文字の並び順の曖昧性を解消するための**規準並べ替えアルゴリズム**（Canonical Ordering Algorithm）が機能する。

文字列内において、クラス 0 の基底文字に続く一連の結合文字（結合文字シーケンス）について：
- 各結合文字をその `ccc` 値の昇順（小さい順）に安定ソート（Stable Sort）する。
- ただし、`ccc` 値が等しい結合文字同士（同一のトポロジー位置を競合するもの）の相対順序は厳格に維持する。

これにより、入力順序が “基底文字 ＋ 上アクセント ＋ 下アクセント” であっても、“基底文字 ＋ 下アクセント ＋ 上アクセント” であっても、並べ替え後には必ず同一の一意な正規順序（下アクセント ccc=220 が先、上アクセント ccc=230 が後）へと収斂する。

### 規準合成（Canonical Composition）

並べ替えを経て正規順序に整列した文字列に対し、先行する基底文字と後続の結合文字が公式の**合成排除リスト**（Composition Exclusion List）に該当しない場合、それらは単一の事前合成済み文字（Precomposed Character）へと再結合される。

### 四大正規化形式（The Four Normalization Forms）

正規分解と互換分解、そして合成の組み合わせにより、Unicode は **4 種類の公式正規化形式**（UAX #15）を定めている。

1. **NFD（Normalization Form D）**：規準分解（Canonical Decomposition）。すべての合成可能文字を純粋な基底文字と結合記号の並びへと分解し、規準並べ替えを施す。
2. **NFC（Normalization Form C）**：規準分解を行って並べ替えた後、可能な限り再び事前合成文字へと規準合成する。Web（W3C）および大多数の OS における標準推奨形式である。
3. **NFKD（Normalization Form KD）**：互換分解（Compatibility Decomposition）。書式化タグ（`<font>`、`<super>`、全角半角など）を含む互換文字もすべて平坦な基本文字へと不可逆分解する。
4. **NFKC（Normalization Form KC）**：互換分解を行った後に規準合成を適用する。検索エンジンや識別子の照合に多用される。

## 双方向組版アルゴリズム（The Bidirectional Algorithm / UAX #9）

### 段落組版のマクロな流れとミクロな行分割

人類の書記文明において、西洋のラテン系言語は左から右（Left-to-Right, LTR）へと書かれ、セム語系のヘブライ語（Hebrew）やアラビア語（Arabic）は右から左（Right-to-Left, RTL）へと書かれる。これら二つの相反する書字伝統が同一の段落、さらには同一の行内で交錯するとき、計算機組版における最も精妙なアルゴリズム――**Unicode 双方向アルゴリズム**（Bidi 算法）が発動する。

双方向アルゴリズムを理解するためには、まず**大域的大枠文脈**（Global Context）と**局所的連なり**（Local Run）の本質的相違を弁別せねばならない。

全体が左から右の組版文脈（英文の書籍など）において、段落の先頭行は右へのインデントを持ち、段落の最終行は右側に余白を残して終了する。

この迷宮に絶対的な数学的秩序を与えるため、Unicode は形式化された 6 段階の状態機械アルゴリズムを策定した。

### 双方向文字型（Bidirectional Character Types）

`UnicodeData.txt` の第 4 フィールドには各文字の**双方向文字型**（Bidi Type）が記録されている。
1. **強文字（Strong Types）**：明瞭な固有の方向性を持つ文字。
   - `L`（Left-to-Right）：ラテン文字、ギリシャ文字、キリル文字、漢字など。
   - `R`（Right-to-Left）：ヘブライ文字など。
   - `AL`（Right-to-Left Arabic）：アラビア文字など（数字の解釈において特殊な規則を持つ）。
2. **弱文字（Weak Types）**：周囲の文脈によって方向性が決定される文字。
   - `EN`（European Number）：ヨーロッパ数字（`0`〜`9`）。
   - `ES`（European Number Separator）：プラス記号やマイナス記号。
   - `ET`（European Number Terminator）：通貨記号やパーセント記号。
   - `AN`（Arabic Number）：アラビア・インド数字。
   - `CS`（Common Number Separator）：コンマやコロン。
3. **中立文字（Neutral Types）**：方向性を持たない文字。
   - `B`（Paragraph Separator）：段落区切り。
   - `S`（Segment Separator）：タブ文字。
   - `WS`（Whitespace）：空白文字。
   - `ON`（Other Neutral）：一般約物、記号など。

### 双方向アルゴリズムの 6 大ステップ（UAX #9）
アルゴリズムはテキストを行ごとに以下の順序で処理する。
1. **段落境界の検出と基本方向の決定**（明示的指定、または段落内の最初の強文字に基づく）。
2. **埋め込みレベル（Embedding Levels）の割り当て**（明示的制御文字 LRE, RLE, LRO, RLO, PDF の解釈）。
3. **弱文字型の解決**（数字や区切り記号の周囲文脈による型昇格）。
4. **中立文字型の解決**（空白や約物を両隣の強文字のレベルへ吸収）。
5. **暗黙的レベルの解決**（偶数レベル＝LTR、奇数レベル＝RTL の原則による微調整）。
6. **行内並べ替え（Reordering）と文字反転**（各レベルの連なりを最高レベルから降順に部分反転していき、最終的な視覚的表示順序を確定）。

### 鏡像属性（Mirroring & BidiMirroring.txt）
RTL 文脈において開き括弧 ‘(’ は視覚的に右側が開いていなければならない。Unicode は `Bidi_Mirrored=Yes` 属性を持つ約物について、`BidiMirroring.txt` に基づきレンダリング時に自動的に対称グリフ（‘(’ と ‘)’ の交換など）へと反転させる。

## 東アジアの書記体系（East Asian Scripts）

### 日中韓漢字表意文字（CJK Ideographs）

数万字におよぶ漢字を体系的に整理するため、Unicode は字形構成の幾何学的記述体系を整備した。

#### 漢字構成記述文字（Ideographic Description Characters, IDC）
Unicode は `U+2FF0`〜`U+2FFB` の区間に 12 個の**漢字構成記述文字**を定義している。これらは前置記法（ポーランド記法）の二項または三項演算子として機能する。

| コード | 文字 | 幾何学的構造 | 実例 |
| :--- | :---: | :--- | :--- |
| `U+2FF0` | ⿰ | 左右並置構造（Left to Right） | `⿰ 木 木` $\to$ 「林」 |
| `U+2FF1` | ⿱ | 上下配置構造（Above to Below） | `⿱ 木 木` $\to$ 「森」の基礎 |

### 文字記述言語（Character Description Language, CDL）

1980 年代、漢字研究の権威トム・ビショップ（Tom Bishop）と Wenlin 研究所は、漢字教育システムのために革新的な構造解析モデルを創案した。XML の台頭とともに、このモデルは国際標準提案――**文字記述言語**（Character Description Language, CDL）へと昇華した。

CDL の核心哲学は次の一言に尽きる。**いかなる複雑な漢字も、再帰的な XML 木構造により、最も基礎的な筆画（Strokes）と構成部品（Components）を標準座標空間内で組み合わせることで記述できる。**

```xml
<cdl char="L">
  <comp char="K" points="0,0 40,128"/>
  <comp char="E" points="60,12 128,128"/>
</cdl>
```

筆画レベルにおいて、CDL は伝統的な「永字八法」をデジタルに再構築し、全 **42 種類の基礎筆画プロトタイプ** を体系化した。以下の歴史的図版は、全 42 種の筆画形態、漢語拼音名、標準英語略称、実際の構字例を完全収録している。

これら筆画名称は、基本用語の複合によって構成されている。
- **横（héng, h）**：水平ストローク。
- **提（tí, t）**：左下から右上へ撥ね上げるストローク。
- **竪（shù, s）**：垂直ストローク。
- **撇（piě, p）**：左下へ払う曲線ストローク。
- **捺（nà, n）**：右下へ広がる波磔ストローク。
- **点（diǎn, d）**：微小な点。
- **折（zhé, z）**：折れ曲がり角。
- **鉤（gōu, g）**：終端の尖った鉤。
- **弯（wān, w）**：緩やかな丸みを帯びた曲線。
- **圏（quān, o）**：閉じた円。

これらを組み合わせることで、組版エンジンは未登録の稀少文字であっても即座に動的輪郭を生成し、高品位にレンダリングすることが可能となる。

### 朝鮮語ハングル（Hangul）と字母算術

15 世紀以前、朝鮮半島では自国語の記録に難解な漢字（吏読、口訣）を借用していたため、民衆の識字率は極めて低かった。

1443 年、朝鮮王朝第 4 代君主**世宗大王**（King Sejong the Great, 1397–1450）は集賢殿の学者とともに秘密裏に研究を重ね、1446 年に不朽の大著『**訓民正音**』（Hunminjeongeum）を頒布した。近代西洋の言語学者からも「**人類史上最も精妙に設計された文字体系**」と絶賛されるこの文字の誕生は、東アジアの文字史を一変させた。

ハングルの偉大さは、その**発音器官象形理論**と**東洋哲学的宇宙観**の完全なる融合にある。

#### 子音の発音器官幾何学的象形

- ‘ᅵ’（縦線）：直立する**人**（Man）。

### 現代ハングル音節ブロックの数理アルゴリズム

ハングルは字母を横に並べるのではなく、初声子音、中声母音、終声子音を正方形の方塊空間内で組み合わせ、単一の**音節ブロック**（Syllable Block）を形成する。
例えば、初声 ‘ᄒ’（h）＋ 中声 ‘ᅡ’（a）＋ 終声 ‘ᆫ’（n）が融合して ‘**한**’（Han）となる。

Unicode 規格はこの処理のために二重の方式を確立した。
1. **ハングル字母ブロック**（Hangul Jamo, `U+1100..U+11FF`）：個々の初声、中声、終声字母を独立して記録。
2. **合成済みハングル音節文字ブロック**（Hangul Syllables, `U+AC00..U+D7A3`）：現代朝鮮語で理論上組み合わされうる**全 11,172 個の音節ブロック**を完備！

この 11,172 個のコードポイントは、極めて優雅な**離散数学の多項式算術**に厳密に従っている。

現代ハングルは以下から構成される。
- **初声（Choseong, L）**：全 19 種（$L_0 \sim L_{18}$）。
- **中声（Jungseong, V）**：全 21 種（$V_0 \sim V_{20}$）。
- **終声（Jongseong, T）**：全 28 種（終声なしの 0 番、および 27 種の子音末尾）。

三者の直積空間は正確に次の値をとる。
$$N = 19 \times 21 \times 28 = 11{,}172$$

任意の三つ組 $(L, V, T)$ に対応する合成済み音節のコードポイント $S$ は、以下の線形算式により無損失に計算できる。

$$\text{CodePoint} = \text{0xAC00} + (L_{\text{index}} \times 21 \times 28) + (V_{\text{index}} \times 28) + T_{\text{index}}$$

逆に、`0xAC00..0xD7A3` の範囲にある任意のハングル音節について、計算エンジンは単純な除算と剰余算（Modulo Arithmetic）を行うだけで、メモリ消費ゼロ、テーブル参照遅延ゼロで、瞬時に根源的な初声・中声・終声シーケンスへと分解・復元できるのである！
