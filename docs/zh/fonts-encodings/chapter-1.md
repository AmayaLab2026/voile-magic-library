当我们尝试对那些在日常计算机使用中略显模糊的概念进行严格的数学与学术定义时，往往会发现它们的严密内涵远比字面常识深刻。

在展开编码历史的长卷之前，我们必须首先厘清构成全书基石的核心概念体系：
* **字符（Character）**：书写语言中用于组织、控制或表征文本信息的最基本抽象语义元素（如拉丁字母 ‘A’、阿拉伯字母 ‘Ba’、汉字‘字’或回车换行指令）。它是一个纯粹的形而上概念；
* **字符集（Character Set）**：一组明确界定、无歧义的字符集合；
* **字码 / 码位（Code Point）**：字符集中的某个特定逻辑槽位或整数索引；
* **编码字符集（Coded Character Set, CCS）**：建立起“抽象字符”与“非负整数码位”之间严格一一映射关系的数学查表（例如 ASCII 规范中将字母 ‘A’ 映射为十进制整数 65）；
* **字符编码表述形式 / 字符编码方案（Character Encoding Scheme, CES）**：将整数码位无歧义转换为底层物理计算机存储或网络传输所需的具体字节序列（Byte Sequence）的规则集合（例如 UTF-8 或 ISO 2022 转义流）；
* **字节（Byte）与八位组（Octet）**：
  * **八位组（Octet）**：严格由 8 个二进制位（Bits）构成的数据单元，数值范围恒定为 $0 \sim 255$（十六进制 `0x00` 至 `0xFF`）；
  * **字节（Byte）**：由计算机硬件架构决定的最小可寻址内存单元。1956 年，IBM 7030（Stretch 超级计算机工程）首席架构师维尔纳·布赫霍尔茨（Werner Buchholz）创造了 **“byte”** 这个术语——为了防止在打字或口头传递中将其与比特（bit）意外混淆，他刻意将单词 bite 拼写为了 byte。在早期计算机科学史上，一个字节的物理宽度因机而异：6 位、7 位、8 位乃至 9 位均曾盛极一时。正如高德纳（Donald E. Knuth）在《计算机程序设计艺术》（TAOCP）中虚构的 MIX 计算机架构所示，高德纳定义一个字节“能够容纳 64 至 100 种不同离散状态”，从而在硬件上允许 6 位字节与十进制双位字节共存。直至二十世纪七十年代微处理器工业标准化确立之后，业界才几乎完全将 1 字节（Byte）与 1 八位组（Octet）划上了等号。

带着这套严密的术语装备，让我们翻开人类将文字符号转化为电信号的波澜壮阔的技术演化史。

## 军用数字通信先驱：FIELDATA 体系

在民用计算机工业尚未统一标准的冷战前夕，数字字符编码的最早突破源自军工通信领域。1956 年，美国陆军信号兵团（US Army Signal Corps）联手各大国防承包商（如 UNIVAC、Sylvania 等），主导研发了世界上第一套通用野战数据传输标准——**FIELDATA**。

当时的电传打字机（Teletype）普遍依赖十九世纪博多（Émile Baudot）发明的 5 单位电传码（Baudot Code）。5 位二进制仅能表达 $2^5 = 32$ 种状态，必须依赖两组机械物理升降键——“字母移位”（Letters Shift, LTRS）与“图形移位”（Figures Shift, FIGS）在同一组按键上复用字母与数字。这种机制在野战恶劣环境下极易因信号噪声丢失移位码，导致后续整段情报沦为无法辨读的乱码。

FIELDATA 彻底摒弃了繁重的机械移位，率先确立了面向现代数字处理器的定长编码结构：
* **基础单元为 6 位（64 个码位）与 7 位（128 个码位）**；
* 每一个字符在内存中占据 6 位有效负载，并配备 1 位用于硬件奇偶校验（Parity Bit）的第 7 位；
* 军方将其严密划分为 $8 \times 8$ 的逻辑状态矩阵，如 **Plate 1-1** 所示：

::: tip 历史排印图版：FIELDATA 字符矩阵全貌（Plate 1-1）
![Plate 1-1: FIELDATA Character Matrix](/images/fonts-encodings/plate1-1-fieldata-table.png)
*图版 1-1：FIELDATA 字符编码矩阵（选自原著第 29 页）。左侧高位行 `000` 至 `111` 与顶端低位列 `000` 至 `111` 共同交织出 64 个基本码位。*
:::

仔细审读该矩阵，可以清晰捕捉到现代编码的原生胚胎：
* **大写拉丁字母 `A` 至 `Z`** 占据了从 `011 000`（八进制 30）开始的连续区域；
* **阿拉伯数字 `0` 至 `9`** 集中分布在 `110 000` 至 `111 001`；
* 首次引入了专用的硬件控制信号：例如主空格（Master Space, `ms`）、大小写控制码（Upper Case / Lower Case, `uc/lc`）、数据块起始（Start of Block）与停止符（Stop）。

FIELDATA 规范作为北约军队的统一标准运行了数十年，它不仅为 UNIVAC 1100 系列大型机奠定了系统字符架构，其将控制码与文本图形码严格分区划分的思想，更是直接启迪了 ASCII 规范的诞生。

## ASCII 的诞生与标准化历程

二十世纪五十年代末，随着商业计算与远程电信网络的井喷，各大计算机厂商（IBM、Remington Rand、Burroughs、GE）各自为战，全美充斥着数十种互不兼容的私有字符集，设备之间交换磁带如同巴别塔般混乱。

为此，美国标准化协会（ASA，即今日的 ANSI）于 1960 年成立了 X3.4 委员会，由被誉为“ASCII 之父”的计算机科学家**罗伯特·贝默（Bob Bemer）**领衔，启动了全美信息交换标准代码——**ASCII（American Standard Code for Information Interchange）**的研制。

### 1. 7 位空间的理性架构
在 6 位（64 字符，无法容纳小写字母与充分标点）与 8 位（256 字符，在当时昂贵的核心磁芯内存与穿孔纸带上成本过高）的激烈博弈中，委员会达成了一个极具前瞻性的妥协：**确立 7 位编码框架（$2^7 = 128$ 个码位），在 8 位通信信道中保留最高第 8 位作为物理传输奇偶校验位（Parity Check）**。

ASCII 的 $128$ 个码位被严谨划分为两大阵营，如 **Plate 1-2** 所示：

::: tip 历史排印图版：ASCII-1963 与 1967 标准矩阵对比（Plate 1-2）
![Plate 1-2: ASCII-1963 / 1967 Character Matrix](/images/fonts-encodings/plate1-2-ascii-table.png)
*图版 1-2：ASCII-1963 与 1967 编码矩阵（选自原著第 30 页）。第 0 列与第 1 列（0x00–0x1F）为 C0 终端控制码；第 2 列至第 7 列（0x20–0x7F）为可打印字符。*
:::

* **前 32 个位置（`0x00` 至 `0x1F`）与末尾 `0x7F`：通信与终端控制码（Control Characters, C0 集合）**  
  这批控制码直接服务于当时的电传打字机与调制解调器物理传输：
  * **换行（Line Feed, LF, `0x0A`）**：使打印滚筒垂直向前走纸一行；
  * **回车（Carriage Return, CR, `0x0D`）**：使笨重的打字滑架沿机械导轨猛烈弹回最左端；
  * **响铃（Bell, BEL, `0x07`）**：触发终端内部的实体小铜钟敲击一声，警示电报操作员；
  * **水平制表（Horizontal Tab, HT, `0x09`）** 与 **退格（Backspace, BS, `0x08`）**；
  * **传输控制**：通信起始（SOH）、正文开始（STX）、正文结束（ETX）、确认（ACK）、否定确认（NAK）。
* **可打印图形字符区（`0x20` 至 `0x7E`）**：
  * 空格字符（Space）安置于 `0x20`，兼具分隔符与可打印特性；
  * 数字 `0` 至 `9` 安置于 `0x30` 至 `0x39`。这一设计精妙绝伦：**要获取数字的二进制实际数值，只需将其 ASCII 码的高 4 位屏蔽（按位与 `& 0x0F`）即可瞬时转换！**
  * 大写字母 `A` 至 `Z`（`0x41` 至 `0x5A`）与小写字母 `a` 至 `z`（`0x61` 至 `0x7A`）之间保持着严格恒定的 32 个码位差（二进制位第 6 位翻转）。大小写转换在处理器内部仅需一条简单的单周期按位异或（XOR）或按位或（OR）指令！

### 2. ASCII-1963 与 ASCII-1967 的演变波澜
1963 年正式发布的 ASCII 第一版（ASA X3.4-1963）远未达到完美：当时小写字母的位置完全未被定义，留作空白；`0x5E` 处分配的是一个向上的实心箭头（$\uparrow$），而 `0x5F` 分配的是向左的箭头（$\leftarrow$）。

在罗伯特·贝默的持续力推下，1967 年的重大修订版彻底奠定了现代 ASCII 的全貌：
* 全面接纳了 **小写字母 `a` 至 `z`**；
* 引进了由贝默专为计算机逻辑编程设计的特殊字符：
  * **反斜杠（Backslash, `\`，`0x5C`）**：后被 DOS / Windows 采纳为目录路径分隔符，被高德纳选为 $\TeX$ 排版系统所有宏命令的前导转义符；
  * **垂直竖线（Vertical Bar, `|`，`0x7C`）**：后被贝尔实验室的肯·汤普逊与丹尼斯·里奇选为 Unix 终端的管线重定向操作符（Pipe）；
  * **尖括号与波浪号**：花括号 `{}`、波浪号 `~`、以及脱字字符 `^`。

1968 年，美国总统林登·约翰逊签署行政命令，强制规定美国联邦政府采购的一切计算机系统与电信设备必须无条件支持 ASCII。ASCII 由此一跃成为全人类信息时代的第一基石，并在 1983 年被国际标准化组织正式批准为 **ISO 646 国际标准**。

## IBM 的帝国坚壁：EBCDIC 体系与穿孔卡片力学遗传

正当整个科学界与电信工业欢呼 ASCII 的统一之时，计算机世界的超级霸主 IBM 却走上了一条完全分道扬镳的道路。

1964 年，IBM 隆重推出了震惊全球企业界的 **System/360 家族大型机**。然而，S/360 搭载的并不是新生的 ASCII，而是 IBM 专有的 **EBCDIC 体系（Extended Binary Coded Decimal Interchange Code，扩充二-十进制交换码）**。

IBM 为何不惜破坏通用标准，执意推出 EBCDIC？答案深藏在十九世纪机械计算的古老机械结构中。

### 1. 何乐礼穿孔卡片的机电原理
1890 年，赫尔曼·何乐礼（Herman Hollerith，其创办的公司日后演化为 IBM）发明了**电气穿孔卡片制表机（Punched Card Tabulating Machine）**。

如 **Figure 1-1** 所示，标准的 IBM 80 列穿孔卡片拥有 12 个水平穿孔行：

::: tip 档案工程图版：ISO 1681 标准 80 列穿孔卡片（Figure 1-1）
![Figure 1-1: A punch card (ISO 1681 standard)](/images/fonts-encodings/fig1-1-punch-card-iso-1681.png)
*图 1-1：ISO 1681 标准 80 列穿孔卡片（选自原著 Figure 1-1）。卡片包含顶端的 12 区孔、11 区孔、0 区孔，以及下方的 1 至 9 数字孔。*
:::

在何乐礼卡片机中，金属电刷扫过卡片：
* 若卡片被冲孔，电刷穿透孔洞接触下方的水银槽或铜滚轮闭合电路，计数继电器跳动一次；
* **数字 0 至 9**：只需在对应的单一行冲压一个孔；
* **字母 A 至 Z**：单孔无法区分 26 个字母。何乐礼开创性地引入了**“复合孔”机制**：将最顶部的三行定义为**区域孔（Zone Punches）**——第 12 行（顶区）、第 11 行（次区）与第 0 行（零区）；
  * **字母 `A` 至 `I`**：由 **12 区孔** 分别与 **数字孔 1 至 9** 复合冲孔而成（如 `A` = 12+1, `B` = 12+2）；
  * **字母 `J` 至 `R`**：由 **11 区孔** 分别与 **数字孔 1 至 9** 复合而成（如 `J` = 11+1, `R` = 11+9）；
  * **字母 `S` 至 `Z`**：由 **0 区孔** 分别与 **数字孔 2 至 9** 复合而成（数字孔 1 留空以防与纯数字 0 冲突）。

### 2. EBCDIC 字符矩阵与字母断裂之谜
当 IBM 设计 S/360 的内部字节集时，全球企业界仓库中堆积着数十亿张已穿孔的商业卡片。为了避免改写现有的卡片读取硬件解码译码器，IBM 工程师粗暴地**将穿孔卡片的区域孔与数字孔电信号直接硬编码到了 8 位字节的高低半字节中！**

这一工程妥协造就了 **Plate 1-3** 中极为诡异的 EBCDIC 矩阵：

::: tip 历史排印图版：EBCDIC 8 位字符编码矩阵（Plate 1-3）
![Plate 1-3: EBCDIC Character Matrix](/images/fonts-encodings/plate1-3-ebcdic-table.png)
*图版 1-3：EBCDIC 字符编码矩阵（选自原著第 32 页）。清晰呈现了大写字母在 0xC1–0xC9、0xD1–0xD9、0xE2–0xE9 之间的两处巨大空白断裂。*
:::

仔细审读该矩阵，可以解开困扰了无数早期 C 语言程序员的终极历史谜团：**为什么在 EBCDIC 字符集中，26 个英文字母在数值轴上竟然不是连续的？**
* 大写字母 `A` 至 `I` 的编码为 `0xC1` 至 `0xC9`（高位 `C` 代表 12 区孔）；
* 随后的 `0xCA` 至 `0xCF` 出现了一段整整 **6 个空洞的荒原**！
* 紧接着 `J` 至 `R` 落在 `0xD1` 至 `0xD9`（高位 `D` 代表 11 区孔）；
* 随后的 `0xDA` 至 `0xDF` 又是 **6 个空洞**！
* 最后 `S` 至 `Z` 落在 `0xE2` 至 `0xE9`（高位 `E` 代表 0 区孔）。

在 ASCII 系统中，判定一个字符是否为英文字母只需一行优雅的代码：
```c
if (c >= 'A' && c <= 'Z') /* 在 ASCII 中完全合法，但在 EBCDIC 中会误判中间无辜的空洞符号！ */
```
而在大型机 EBCDIC 环境下，程序员必须痛苦地写成：
```c
if ((c >= 'A' && c <= 'I') || (c >= 'J' && c <= 'R') || (c >= 'S' && c <= 'Z'))
```

为了适应全球市场，IBM 日后又强行衍生出了多达 57 种国家版本的 EBCDIC 代码页。不同国家的机器在处理方括号、花括号与重音字母时各执一词，成为企业级分布式计算长达数十年的梦魇。

## ISO 2022 转义序列框架与 8 位空间四分天下

进入二十世纪七十年代，计算机迅速走出英美，走向世界。7 位 ASCII 仅能容纳 128 个符号，连西欧法文、德文、西班牙文的基本重音字母都无法表达，更遑论希腊文、西里尔文、阿拉伯文与数万东亚汉字。

为了在不推翻现有 7 位与 8 位传输架构的前提下兼容全人类语言，国际标准化组织于 1986 年推出了极其庞大、充满图灵机状态变换色彩的元标准——**ISO 2022（对应 ECMA-35 标准）**。

### 1. 8 位空间的四分天下布局
ISO 2022 规范将一个标准的 8 位字节空间（256 个码位）严格切割为四大独立领地，如 **Figure 1-2** 所示：

::: tip 体系架构图版：ISO 2022 八位空间四分天下模型（Figure 1-2）
![Figure 1-2: Subdivisions of an 8-bit space in ISO 2022](/images/fonts-encodings/fig1-2-iso-2022-subdivisions.png)
*图 1-2：ISO 2022 对 8 位空间的划分子域模型（选自原著 Figure 1-2）。左半区（0x00–0x7F）为 C0 控制区与 GL 图形左区；右半区（0x80–0xFF）为 C1 控制区与 GR 图形右区。*
:::

这四大区域各司其职，拥有绝对不可逾越的边界：
1. **C0 控制区（`0x00` 至 `0x1F`）**：严格容纳 32 个终端控制字符，默认绑定经典 ASCII 控制码；
2. **GL 图形左区（Graphic Left, `0x20` 至 `0x7F`）**：严格容纳 94 或 96 个图形字符，默认无条件绑定 ASCII 图形字符（守住 ASCII 兼容性）；
3. **C1 控制区（`0x80` 至 `0x9F`）**：额外开辟的 32 个高级控制字符区，用于扩展转义控制协议；
4. **GR 图形右区（Graphic Right, `0xA0` 至 `0xFF`）**：开辟的第二图形窗口，用于动态投射各国扩展字符集。

### 2. 状态机插槽与转义机制（Escape Sequences）
ISO 2022 的精髓在于**动态状态机插槽架构**：
* 终端内部常驻 4 个图形字符集插槽（$G_0, G_1, G_2, G_3$）；
* 终端开机时，通过发送**转义序列（Escape Sequences，以 `ESC` 引导，如 `ESC ( B`）**，可以向国际标准化组织设立的“ISO 国际注册表（ISO-IR）”动态申请将特定的字符集（例如法国字符集、希腊字符集、甚至双字节汉字集）挂载进 $G_0 \sim G_3$ 槽位；
* 随后，通过**单次移位指令（Single Shift: SS2, SS3）**或**锁定移位指令（Locking Shift: LS0, LS1, LS2, LS3）**，可以在打字过程中瞬时将特定的 $G_n$ 插槽投射到当前的 GL 或 GR 窗口中！

ISO 2022 的思想极其宏大精妙，它构成了后来日本网络邮件标准 **ISO 2022-JP** 以及现代 Linux 终端转义控制序列（ANSI Escape Sequences）的核心内核。

## ISO 8859 家族：欧洲诸语言的地理割据

尽管 ISO 2022 具有无限的扩展理论潜能，但在个人电脑普及早期，其沉重的多状态机与级联转义序列对当时的微型操作系统（DOS、早期 Unix）而言开销过大，稍有丢包就会导致终端死锁。

业界迫切需要一种**静态的、确定性的、单字节 8 位编码标准**：无需发送任何转义指令，高 128 位码位固定表达扩展文字。

为此，ISO 委员会在 1987 年启动了著名的 **ISO 8859 系列标准**。其设计铁律是：**低半区（0x00–0x7F）全盘继承标准 ASCII；高半区（0xA0–0xFF）根据地理区域划分为 16 个互不兼容的平行代码页！**

### 1. 旗舰标准：ISO 8859-1（Latin-1）与 ISO 8859-15（Latin-9）
1987 年推出的 **ISO 8859-1（俗称 Latin-1）** 是整个系列的旗舰，覆盖西欧主流语言（英、法、德、西、葡、意、荷等），其 GR 高位表如 **Plate 1-4** 所示：

::: tip 历史排印图版：ISO 8859-1（Latin-1）高位字符矩阵（Plate 1-4）
![Plate 1-4: ISO 8859-1 (Latin-1) Table](/images/fonts-encodings/plate1-4-iso8859-1-table.png)
*图版 1-4：ISO 8859-1（Latin-1）高位区（0xA0–0xFF）字符矩阵（选自原著第 37 页）。包含了西欧重音字母、倒叹号/倒问号（¡, ¿）、德国双 S（ß）与微米符号（µ）。*
:::

然而，ISO 8859-1 在制定之初便犯下了严重的文化傲慢与学术疏漏：
* **粗暴遗漏法文连字**：它收录了单独的 `o` 和 `e`，却唯独漏掉了法语中极为核心的连字字母 **`œ` 与大写 `Œ`**（例如词汇 *cœur*, *œil*）！这导致法国学术界长期抗议该标准是对法兰西文化的严重侮辱；
* **遗漏荷兰语连字**：缺少荷兰语双合字母 `ĳ / Ĳ`；
* **粗暴遗漏芬兰语/爱沙尼亚语字母**：缺少带有抑扬符（Caron）的 `š/Š` 与 `ž/Ž`；
* **缺乏世纪货币标识**：二十世纪末欧洲经济与货币联盟成立，统一货币**欧元（Euro, €）**横空出世，但 ISO 8859-1 诞生时只有那个无人问津的“通用货币虚符” `¤`（Currency Sign, `0xA4`）。

为了拯救这一历史败笔，ISO 于 1999 年紧急推出了修正版——**ISO 8859-15（俗称 Latin-9）**：
* 在 `0xA4` 处直接废黜虚符 `¤`，换上崭新的**欧元符号 `€`**；
* 征用冷门符号槽位，补齐了法文连字 `œ / Œ` 以及芬兰语字母 `š / Š` 和 `ž / Ž`。

### 2. 中东欧与巴尔干标准：ISO 8859-2（Latin-2）与 ISO 8859-16（Latin-10）
服务于波兰、捷克、斯洛伐克、匈牙利、克罗地亚等中东欧斯拉夫语言的 **ISO 8859-2（Latin-2）**，集中收录了中欧语言繁密的重音符号（Ogonek 鼻音化钩标 `ą, ę`、Caron 抑扬符 `č, š, ž`、以及双锐音符 `ő, ű`）。

* **非拉丁文字的悲歌**：
  * **ISO 8859-5（西里尔文）**：承袭苏联 1987 年 GOST 19768 国家标准，但因在 PC 上受到微软 Windows-1251 与 KOI-8 系列标准的夹击而罕有人用；
  * **ISO 8859-6（阿拉伯文）**：严重脱离书法实际，仅录入了字符的孤立形标称码，完全未设计词内上下文形态变换，在排印工业中沦为死文字；
  * **ISO 8859-7（希腊文）**：仅支持现代希腊语单调正字法（Monotonic Greek），完全剔除了古典古希腊语浩瀚的锐音、钝音、扬抑符与下写 Iota 体系（Polytonic Greek），令全欧洲的古典文献学者深恶痛绝；
  * **ISO 8859-8（希伯来文）**：在网络早期深陷从左向右视觉顺序（Visual Order）与从右向左逻辑顺序（Logical Order）的倒转地狱。

## 远东文字（The Far East）：汉字与多字节编码工程

当欧美计算机科学家在单字节 256 个码位内为重音字母争吵不休时，东亚中日韩（CJK）三国却面临着完全不在一个数量级上的宏伟挑战：**汉字（Chinese Ideographs）浩如烟海，日常通用字即达数千，康熙字典与古典典籍更达五万以上！**

单字节架构彻底失效，东亚先驱必须破天荒地在 ASCII 基础上开拓**多字节编码（Multi-Byte Encodings）**的无人之境。

### 1. 日本的先驱探索：JIS X 0208 与 Shift-JIS
日本是东亚最早确立计算机汉字标准的国家：
* **JIS X 0208（区面点架构）**：开创了著名的 $94 \times 94$ 二维矩阵结构（94 个“区”，每区 94 个“点”）。每个汉字由两个字节表示，第一字节代表区号，第二字节代表点号（每个字节均加上偏移量 `0x20` 避开控制码）；
* **Shift-JIS（微机时代的工程杰作）**：在 1980 年代 DOS/V 与早期的 PC-98 电脑上，既要保持 ASCII 英文兼容，又要流畅输入半角片假名（Katakana），还要同时处理庞大的双字节汉字。微软工程师阿斯基（Kazuhiko Nishi）与 IBM 联手推出了 **Shift-JIS（SJIS）**：
  * 保留 `0x00–0x7F` 严格作为 ASCII；
  * 保留 `0xA1–0xDF` 作为日文半角片假名；
  * 将庞大的 JIS X 0208 汉字区“数学变换（Shift）”压缩到剩余的两个缝隙区间：首字节高位被限定在 `0x81–0x9F` 与 `0xE0–0xFC`，尾字节落在 `0x40–0x7E` 与 `0x80–0xFC`。文字处理软件只需探测首字节是否落在特征区间，即可在极低硬件开销下无缝切换单双字节！

### 2. 中国大陆的标准演进：从 GB 2312 到 GB 18030
* **GB 2312-80（信息交换用汉字编码字符集·基本集）**：1980 年由中国国家标准总局颁布，收录 6,763 个简体汉字与 682 个非汉字图形符号。同样采用区位码设计（94 个区，每区 94 位）。在 Unix 环境下，通过将高位最高比特（MSB）强制置 1（即加上 `0xA0` 偏移量），演化为著名的 **EUC-CN** 标准；
* **GBK 扩展规范（1995）**：随着微机进入政府与金融金融出版系统，GB 2312 的 6,763 个汉字无法满足中国人名生僻字、地名、古籍以及繁体字的需求。全国信息技术标准化技术委员会联合微软等厂商，全面利用双字节空闲空间，向下兼容收录了 21,886 个简繁汉字与符号；
* **GB 18030（强制性世纪大一统国标）**：2000 年与 2005 年两次重大发布，确立为国家强制执行标准。它以单字节（ASCII）、双字节（兼容 GBK）、四字节（覆盖 Unicode 全平面的 160 万码位空间）构筑了变长编码体系，正式将藏文、维吾尔文、蒙古文、彝文等少数民族语言收揽入库。

### 3. 港台繁体中文：Big5（大五码）
1984 年，台湾资讯工业策进会联手五大电脑厂商（宏碁、神通、佳佳、零壹、大众）推出了 **Big5（大五码）**。采用固定的双字节结构：首字节为 `0xA1–0xF9`，尾字节为 `0x40–0x7E` 与 `0xA1–0xFE`，收录了 13,060 个繁体汉字。Big5 伴随着香港、台湾两地的个人电脑、BBS 与早期网络社区的繁荣，成为了繁体中文世界的通用事实标准。

  * 单横线（`─`）、双横线（`═`）、单竖线（`│`）、双竖线（`║`）；

在 ISO 8859 标准中，`0x80` 至 `0x9F` 是必须保留给不可见通信控制码的“禁区（C1 Zone）”。但微软敏锐地意识到桌面个人电脑根本不需要这些陈旧的终端控制指令。

* 商标符号（`™`）、千分号（`‰`）、子弹点符号（Bullet, `•`）；
* 并在日后率先将新生的欧元符号（`€`）固定在 `0x80`。

由于 Windows 95/98 的绝对统治力，Code Page 1252 成为了互联网早期事实上的网页默认编码，无数早期跨平台开发者因其在 Unix / Mac 上产生非法字符而头痛欲裂。

## 电子邮件与互联网 MIME 协议传输革命

随着阿帕网（ARPANET）向现代互联网的飞速蜕变，人类面临着前所未有的全球网络异构字符交换困局。

早期的互联网邮件路由基于 1982 年制定的 **RFC 821（SMTP 协议）**。该协议被严密设计为一个“纯 7 位传输通道（7-bit Transport）”：在冷战时期的陈旧网关与路由器中，硬件微码默认会直接**粗暴地斩断每个字节的最高位（8th-bit Stripping）**！任何包含大于 `0x7F` 字符的 8 位邮件，经过跨洋路由跳点传输后，所有重音字母和汉字都会被剥去首位比特，瞬间坍塌为无法辨读的乱码死信。

为了拯救跨语言通信，互联网工程任务组（IETF）在 1993 至 1996 年联手推出了划时代的 **MIME 体系（Multipurpose Internet Mail Extensions，RFC 2045–2049）**。

### 1. MIME 核心头信息结构
MIME 为纯文本邮件注入了前所未有的元数据头（Headers）：
```http
MIME-Version: 1.0
Content-Type: text/plain; charset="ISO-8859-1"
Content-Transfer-Encoding: quoted-printable
```

### 2. 两大内容传输编码算法
* **Quoted-Printable 编码（面向轻度重音文本）**：
  * 对于标准 7 位 ASCII 字符，保持明文原样输出；
  * 对于大于 127 的 8 位字节（或等号自身），将其转义为一个等号加两个十六进制大写字符（例如字母 `é` 在 Latin-1 中为 `0xE9`，编码为 `=E9`）；
  * 行末添加软回车等号（`=`），确保任何单行长度绝对不会超过 76 个字符的路由器硬限制；
* **Base64 编码（面向非拉丁语系与二进制附件）**：
  * 采用纯粹的比特流重组算法：将输入流中每 3 个连续的 8 位字节（共 $3 \times 8 = 24$ 个比特位），重新切分为 4 个连续的 6 位单元（$4 \times 6 = 24$ 比特）；
  * 每个 6 位单元的值在 $0 \sim 63$ 之间，直接查表映射到由绝对安全的 64 个 ASCII 字符构成的安全表中（大写 `A–Z` 代表 0–25，小写 `a–z` 代表 26–51，数字 `0–9` 代表 52–61，加号 `+` 为 62，斜杠 `/` 为 63）；
  * 末尾不足 3 字节时，以填充符等号（`=`）对齐补齐。

通过 Quoted-Printable 与 Base64，非英美世界的人民终于第一次能够在 7 位的古老互联网管道中，安全无损地跨洲际传递本民族的重音诗篇、俄文诗歌与中文信函！

## 早期万维网（The Web）的字符集博弈与历史启示

当万维网（World Wide Web）在二十世纪九十年代呈指数级爆发时，超文本传输协议（HTTP）与超文本标记语言（HTML）全面承袭了 MIME 的字符集宣告思想：

### 1. 双重字符集声明机制
Web 服务器通过 HTTP 响应头向浏览器通告编码：
```http
HTTP/1.1 200 OK
Content-Type: text/html; charset=Shift_JIS
```
而在 HTML 文档内部，开发者亦可嵌入元数据标签作为兜底防御：
```html
<meta http-equiv="Content-Type" content="text/html; charset=GB2312" />
```

### 2. HTML 字符实体引用（Character Entity References）
为了让只支持特定编码的网页能够临时穿插生僻外国字母，HTML 规范引入了实体转义机制：
* **命名实体（Named Entities）**：例如以 `&eacute;` 表达 `é`，以 `&copy;` 表达 `©`；
* **十进制数值实体（Decimal Numeric Entities）**：例如以 `&#233;` 直接指定码位；
* **十六进制实体（Hexadecimal Entities）**：以 `&#xE9;` 指定十六进制码位。

## 历史的沉思：巴别塔倒塌前的最终绝响

在二十世纪末的数字世界版图上，人类文明被割裂成了上百座互不相通的“孤岛”：
* 同一个十六进制字节 `0xE9`：
  * 在 **ISO 8859-1（西欧）** 中，它代表优雅的带重音字母 **`é`**；
  * 在 **ISO 8859-5（西里尔文）** 中，它代表俄文字母 **`щ`**；
  * 在 **ISO 8859-7（希腊文）** 中，它代表希腊字母 **`θ`**；
  * 在 **ISO 8859-8（希伯来文）** 中，它代表希伯来字母 **`ט`**；
  * 在 **MS-DOS Code Page 437** 中，它代表一个微积分数学符号 **`Θ`**；
  * 而在 **MacRoman** 中，它甚至代表加利福尼亚数学家专用的上标记号！

如果收件人的计算机操作系统缺少正确的代码页，或者网页服务器返回了一个错误的 HTTP Header，整篇原本优美典雅的文章瞬间就会沦为满屏幕不可辨读的“乱码”（Mojibake / 字符垃圾）。

在不同语言混合混排（例如在一篇英法联合编写的俄文与日文汉学学术论文中），传统的单字节与区域双字节编码更是彻底无能为力：任何系统都无法在同一张 8 位代码页内同时兼顾西里尔字母、假名、汉字与阿拉伯连写！

世界在呼唤一个能够统揽全人类一切已消亡古文字、现存活文种、科学符号与表情图元的通用大一统字符集。

一场终结计算机文字巴别塔的宏伟革命——**Unicode 与通用字符集（Universal Character Set）**，已在地平线上破晓升起。
