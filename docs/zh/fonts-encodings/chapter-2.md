---

在上一章中，我们见证了前 Unicode 时代的诸神混战：从 7 位 ASCII 到各式各样互不兼容的 8 位 ISO 8859 扩展表，再到远东汉字文化圈各自探索的双字节代码页。这种地域性单字节与多字节标准割据的局面，给全球计算机信息交换带来了无穷无尽的乱码梦魇。

二十世纪八十年代末，一场旨在统一全人类所有书写系统的计算革命应运而生。然而，要想构建一套能够包容全世界过去、现在与未来所有文字的通用字符集，计算机科学家与语言学家首先必须退回到哲学的原点，回答几个看似简单、实则极为深刻的本体论命题：**什么是字符？什么是字形？它们与计算机底层的二进制字节之间，究竟维持着怎样的数理映射关系？**

## 哲学命题：字符与字形（Characters and Glyphs）

在日常口语与早期浅显的计算机文献中，“字符”（character）、“字模”（letterform）与“字形”（glyph）常常被不加区分地混淆使用。然而在现代计算机排印学与编码理论中，**严格厘清字符与字形的边界，是进入 Unicode 殿堂的绝对第一前提**。

* **字符（Character）**：  
  字符是一个**抽象的概念实体（abstract, intangible entity）**。它是书写语言中最基础的语义单元，拥有明确的语言学身份、名称与规范属性，但它**本身没有任何固定的外貌、大小或视觉形态**。例如，拉丁字母 “小写字母 a” 是一个字符，汉字 “文” 是一个字符，阿拉伯字母 “BEH” 亦是一个字符。字符存在于逻辑与概念的心智世界中。
* **字形（Glyph）**：  
  字形是字符在物理世界的**具体视觉呈现形态（graphical image / visual presentation）**。它是落在纸面上的一团墨迹，或是投射在显示屏上的一组发光像素与贝塞尔矢量曲线。同一个字符，在不同的字体设计师笔下、在不同的历史书写流派中、或在不同的排版上下文中，可以呈现为成百上千种截然不同的字形！

### 为什么计算机不应编码字形？

早期某些字符编码之所以走向失败，其根本原因就在于试图将特定的“视觉字形”硬塞入字符表中。试想：如果一种字体中包含正体 ‘a’、斜体 ‘*a*’、粗体 ‘**a**’、双层 ‘a’ 与单层手写体 ‘ɑ’，我们是否应当为它们分别分配独立的编码码位？

答案是绝对坚决的否定。如果将排版样式的字形变体编码为独立字符，全文检索、自然语言处理、语义分词与拼写检查将瞬间陷入灭顶之灾：搜索引擎在匹配单词 “apple” 时，将无法命中以斜体或粗体书写的同一单词！

因此，现代编码哲学的至高法则为：**编码（encoding）只负责收录抽象的“字符”（What you mean），而字体（font）则负责提供具象的“字形”（How it looks）**。

### Unicode 联盟与 ISO 10646 的世纪合流

Unicode 运动最初于 1987 年由施乐帕洛阿尔托研究中心（Xerox PARC）的乔·贝克尔（Joe Becker）、李·柯林斯（Lee Collins）与苹果公司的马克·戴维斯（Mark Davis）共同倡议发起。1991 年 1 月，**Unicode 联盟（Unicode Consortium）**在加州正式注册成立。

与此并行，国际标准化组织（ISO）亦在推进其官方的国际多八位编码字符集计划——**ISO/IEC 10646**（即通用字符集 UCS, Universal Character Set）。在初期，ISO 阵营倾向于构建一个庞大的 31 位四维编码空间（组 Group、面 Plane、排 Row、格 Cell），而早期 Unicode 阵营则主张构建一个紧凑高效、面向全人类现代常用文字的统一 16 位定长编码（$2^{16} = 65,536$ 个码位）。

两大标准体系的分裂势必造成全球软件工业的灾难。所幸在 1991 年底，双方达成了极具远见的重大历史和解与合并协议：
* 双方的字符码位分配实现**完全严格的一对一同步（1:1 synchronization）**；
* ISO/IEC 10646 的第一组第零平面（Group 00, Plane 00）被永久确立为 **基本多语言平面（BMP, Basic Multilingual Plane）**，其码位与 Unicode 16 位空间完全一一对应；
* 双方共用一套字符命名与属性规范，彻底避免了世界计算标准的分裂。

## Unicode 十大第一原则（First Principles）

Unicode 体系之所以能够超越此前所有字符编码标准，在于其从诞生之初就确立了十项不可动摇的顶层公理架构（The Ten Principles of Unicode）：

1. **通用性（Universal repertoire）**：  
   Unicode 致力于收录全世界一切书写系统中所使用过的所有字符——不仅涵盖所有现代活语言，亦囊括古文字、楔形文字、象形文字以及广袤的数学、音乐、科学专业符号。
2. **高效性（Efficiency）**：  
   文本数据流必须易于解析与处理，绝不依赖像 ISO 2022 那样容易因通信损耗导致后续全部解码错乱的有状态“模式切换”。
3. **统一性（Uniformity）**：  
   在给定的编码形式下，所有字符均采用统一宽度的基准数理单位，提供固定且确定性的码位引用体系。
4. **明确性（Unambiguity）**：  
   每一个已分配的码位（code point）在任何时间、任何语境下，均唯一且无歧义地对应一个具体的抽象字符。
5. **字符而非字形（Characters, not glyphs）**：  
   这是 Unicode 最核心的基石。Unicode 只为抽象字符分配码位，字形的外观变体（粗体、斜体、连字、位置变换形态）交由上层字体与排版引擎负责。
6. **语义纯文本原则（Plain text）**：  
   Unicode 序列仅承载纯文本字符流。任何关于字体选择、字号大小、行距、边距与色彩的排版富文本属性，均属于外部标记语言（如 HTML、XML、RTF）的范畴。
7. **逻辑顺序（Logical order）**：  
   在计算机内存与数据流中，字符必须严格按照人类思维书写或朗读发音的**逻辑先后顺序（logical memory order）**存储。对于阿拉伯文与希伯来文等从右向左（RTL）书写的文字，其在内存中的存储顺序依然与从左向右（LTR）文字一致（先读的在前，后读的在后），屏幕上的逆向呈现完全交由排版系统的**双向算法（Bidi Algorithm）**负责。
8. **字符统合（Unification）**：  
   当不同文化或同一语言体系中的若干字符，在书写历史、图形起源与现代语义上具有同源性与共同特征时，Unicode 坚决将其统合归并为一个单一码位。最著名的范例莫过于**中日韩汉字统合（Han Unification）**。
9. **动态组合（Dynamic composition）**：  
   Unicode 允许带有重音符或附加变音标记的字符通过“基础字符 + 组合变音符”（Base Character + Combining Marks）在排版时动态拼合，而无需为每一种可能的复合变音字符穷举分配静态码位。
10. **永久稳定性（Stability）**：  
    一个码位一旦被正式赋予某个字符，其**码位数值与规范名称永久不变、绝不回收、绝不重新分配**给其他字符；字符的核心规范属性在后续版本中只增不删，确保历史数据的永恒可逆性。

## 技术命题：字符、码位与字节

离开了物理硬件，纯粹的哲学将无法运转。在计算机系统内部，字符究竟如何落地为磁盘上的比特与字节？

现代字符标准体系将字符的表征清晰划分为五层模型架构：
$$\text{抽象字符库（ACR）} \longrightarrow \text{编码字符集（CCS）} \longrightarrow \text{字符编码形式（CEF）} \longrightarrow \text{字符编码方案（CES）} \longrightarrow \text{传输语法（TES）}$$

1. **抽象字符库（Abstract Character Repertoire, ACR）**：  
   所有被标准认定的抽象字符的无序集合；
2. **编码字符集（Coded Character Set, CCS）**：  
   将抽象字符库中的每一个字符映射到一个唯一的非负整数——这个整数被称为**码位（Code Point）**。在 Unicode 规范中，码位以统一的前缀标记：
   $$\text{U+0000} \sim \text{U+10FFFF}$$
   总共定义了 $16 \times 2^{16} + 2^{16} = 17 \times 65,536 = 1,114,112$ 个码位。其中排除了代理区码位后的有效字符码位被称为 **Unicode 标量值（Unicode scalar value）**。
3. **字符编码形式（Character Encoding Form, CEF）**：  
   将整数码位映射为定长的计算机基本整数单元（Code Unit, 码元），即 UTF-32、UTF-16 与 UTF-8；
4. **字符编码方案（Character Encoding Scheme, CES）**：  
   处理多字节码元序列在不同硬件架构下的**字节序（Endianness）**，如 UTF-16BE（大端序）、UTF-16LE（小端序）；
5. **传输编码语法（Transfer Encoding Syntax, TES）**：  
   针对特定有损通信信道（如早期 7 位 SMTP 邮件）的数据封装，如 Base64 与 Quoted-Printable。

## 主流字符编码形式（CEF）深度解析

### 1. UTF-32 与定长表示

UTF-32（以及 ISO 10646 的 UCS-4）是概念上最纯粹的编码形式：它使用一个完整的 32 位（4 字节）无符号整数来直接表示每一个 Unicode 码位。
* **优势**：绝对的定长特性。字符串中第 $N$ 个字符必然位于内存偏移量 $4N$ 处，使得按索引随机访问字符的时间复杂度达到最优的 $O(1)$；
* **致命缺陷**：对绝大多数以拉丁字母、希腊字母或常用符号构成的西方文本而言，UTF-32 中高达 75% 的字节全部是无意义的零填充（`0x00 0x00 0x00`），造成了内存带宽、缓存命中率与磁盘空间的极其惨烈的浪费。

### 2. UTF-16 与代理对（Surrogate Pairs）数学机制

当 Unicode 联盟在 1990 年代中期意识到 16 位（65,536 个码位）终将无法容纳全人类的生僻汉字与古代文字时，工业界面临抉择：要么全面推倒重来强推 32 位，要么设计一种平滑兼容 16 位的优雅扩展算法。

计算机科学家们最终提出了极其精妙的**代理对（Surrogate Pairs）机制**，由此诞生了 **UTF-16**。

在基本多语言平面（BMP，即 $\text{U+0000} \sim \text{U+FFFF}$）中，Unicode 特意开辟了一片永远不分配给任何实际字符的“真空禁区”——**代理区（Surrogates, $\text{U+D800} \sim \text{U+DFFF}$，共 2,048 个码位）**，并将其均分为两大半区：
* **高半区代理（High Surrogates / Lead Surrogates）**：$\text{U+D800} \sim \text{U+DBFF}$（共 $1,024 = 2^{10}$ 个值）；
* **低半区代理（Low Surrogates / Trail Surrogates）**：$\text{U+DC00} \sim \text{U+DFFF}$（共 $1,024 = 2^{10}$ 个值）。

任何一个落在辅助平面（Planes 1–16，即 $\text{U+10000} \sim \text{U+10FFFF}$）的高位码位 $N$，其数值必然满足：
$$0 \le N - 0\text{x10000} \le 0\text{xFFFFF}$$

这个差值正好是一个 20 位的二进制数！UTF-16 巧妙地将这 20 位对半切分为两组 10 位：
* 高 10 位加上偏移基数 $0\text{xD800}$，生成一个**高半区代理字**（前导代理）；
* 低 10 位加上偏移基数 $0\text{xDC00}$，生成一个**低半区代理字**（后尾代理）。

#### 代理对数学转换方程
* **编码（码位 $N \to$ 代理对 $(H, L)$）**：
  $$N' = N - 0\text{x10000}$$
  $$H = 0\text{xD800} + \lfloor N' / 0\text{x400} \rfloor = 0\text{xD800} + (N' \gg 10)$$
  $$L = 0\text{xDC00} + (N' \pmod{0\text{x400}}) = 0\text{xDC00} + (N' \ \& \ 0\text{x3FF})$$
* **解码（代理对 $(H, L) \to$ 码位 $N$）**：
  $$N = ((H - 0\text{xD800}) \times 0\text{x400}) + (L - 0\text{xDC00}) + 0\text{x10000}$$

由于高代理（`0xD800`–`0xDBFF`）与低代理（`0xDC00`–`0xDFFF`）的取值区间完全互斥，且与任何合法的 BMP 字符码位完全隔离，解析引擎在数据流中向前或向后滑动时，能够瞬间且无歧义地判定当前 16 位整数究竟是一个完整的单字符，还是代理对的头部或尾部！

### 3. UTF-8：贝尔实验室的传世杰作

1992 年 9 月的一天晚上，在新泽西州的一家餐馆里，肯·汤普森（Ken Thompson）与罗布·派克（Rob Pike）在餐巾纸上勾勒出了计算历史上最完美的编码形式——**UTF-8**（原名 FSS-UTF）。

UTF-8 是一套纯粹的**以 8 位字节为基准的变长编码形式（variable-width byte-based encoding）**，它使用 1 至 4 个字节来对 21 位的 Unicode 码位进行精确切分：

| 标量码位范围（十六进制） | 字节数 | 字节 1（前导字节） | 字节 2（后随字节） | 字节 3（后随字节） | 字节 4（后随字节） |
| :--- | :---: | :--- | :--- | :--- | :--- |
| `00000000`–`0000007F` | 1 | `0xxxxxxx` | — | — | — |
| `00000080`–`000007FF` | 2 | `110yyyyy` | `10xxxxxx` | — | — |
| `00000800`–`0000FFFF` | 3 | `1110zzzz` | `10yyyyyy` | `10xxxxxx` | — |
| `00010000`–`0010FFFF` | 4 | `11110uuu` | `10uuzzzz` | `10yyyyyy` | `10xxxxxx` |

#### UTF-8 的工程美学巅峰：
1. **绝对向下兼容 ASCII**：  
   对于 `0x00`–`0x7F` 的 128 个 ASCII 字符，UTF-8 使用单字节存储，且最高位（bit 7）恒为 0。这意味着任何合法的 ASCII 英文文件，**无需做任何字节转换，本身就是一份完全合法的 UTF-8 文件**！所有原本只认识 C 语言 ASCII 字符串（以 `\0` 结尾）的古老系统工具（如 `grep`、`sed`、`awk`、编译器），完全无需重写即可直接操作 UTF-8。
2. **前缀自同步特性（Self-synchronizing）**：  
   在多字节序列中：
   * 前导字节（Lead Byte）的高位具有特征掩码：`110...` 代表后续跟随 1 个字节；`1110...` 代表后续跟随 2 个字节；`11110...` 代表后续跟随 3 个字节；
   * 所有后随字节（Continuation Bytes）的高两位**恒定为 `10xxxxxx`**！
   这种设计具有无与伦比的容错性：如果由于网络传输丢包或磁盘损坏导致字节流中间发生截断，解码器只需线性向后扫描，一旦遇到一个最高位不是 `10...` 的字节，便能**瞬间找回同步边界（resynchronize）**重新开始正确解码，绝不会让单点故障滚雪球式污染整个后续文本！
3. **彻底根除大小端问题**：  
   由于 UTF-8 的数据单元本身就是 8 位字节，它在任何 CPU 架构下都不存在多字节整数的高低端重排问题，无需字节顺序标记（BOM）。

### 4. 字节顺序标记（Byte Order Mark, BOM）

在处理 UTF-16 与 UTF-32 时，多字节整数在内存中究竟应当高位在前（大端序 Big-Endian）还是低位在前（小端序 Little-Endian），取决于底层 CPU 的物理架构（Intel x86 采用小端，Motorola/PowerPC 采用大端）。

为了在跨平台交换文件时消除歧义，Unicode 特意设计了**字节顺序标记（BOM）**：字符 **$U+\text{FEFF}$（零宽不换行空格 / ZERO WIDTH NO-BREAK SPACE）**。
* 如果接收方在文件开头读入的两个字节是 `0xFE 0xFF`，则表明该文本采用大端序（UTF-16BE）；
* 如果读入的两个字节是 `0xFF 0xFE`，则表明该文本采用小端序（UTF-16LE）。为什么？因为在 Unicode 规范中，**$U+\text{FFFE}$ 已经被永久声明为一个非法字符（Noncharacter）**，它在任何合法的 Unicode 文本中都绝不可能存在！一旦出现，唯一的解释就是当前系统的字节读取顺序颠倒了。

## Unicode 宏观组织：平面与区段路线图

整个 Unicode 码位空间（$U+0000 \sim U+10FFFF$）被均分为 **17 个大小相等的平面（Planes）**，每个平面包含 $2^{16} = 65,536$ 个码位。

在目前定义的 17 个平面中，已正式入驻字符的共有 **6 大核心平面**，如 **Figure 2-2** 所示：

![Unicode 版本 4 中已填充的六大平面全貌（Figure 2-2）](/images/fonts-encodings/fig2-2-populated-planes-unicode.png)

*图 2-2：Unicode 体系中已分配填充的六大平面（The six currently populated planes of Unicode）：第 0 平面（BMP）、第 1 平面（SMP）、第 2 平面（SIP）、第 14 平面（SSP）、以及第 15 与 16 平面（私用补充平面）。*

* **第 0 平面：基本多语言平面（BMP, Basic Multilingual Plane, $0\text{x0000}$–$0\text{xFFFF}$）**：  
  全书最核心的心脏地带，囊括了当今现代世界正在使用的绝大多数书写系统、全套通用符号体系与常用汉字表意文字；
* **第 1 平面：第一辅助平面 / 多语言补充平面（SMP, Supplementary Multilingual Plane, $0\text{x10000}$–$0\text{x1FFFF}$）**：  
  主要容纳人类历史上的古代文献书写系统（如埃及象形文字、苏美尔与波斯楔形文字、古希腊古代碑铭与音乐记号）、专业数学字母数字符号、以及历史古记号；
* **第 2 平面：第二辅助平面 / 表意文字补充平面（SIP, Supplementary Ideographic Plane, $0\text{x20000}$–$0\text{x2FFFF}$）**：  
  东亚中日韩表意汉字的海量扩充库（收录扩展 B、C、D 等大批古籍异体字、历史地名及生僻姓氏字）；
* **第 14 平面：特别用途补充平面（SSP, Supplementary Special-Purpose Plane, $0\text{xE0000}$–$0\text{xE0FFF}$）**：  
  类似“工程隔离检疫区”，专门存放语言标签标记与补充变体选择符；
* **第 15 与 16 平面：私用补充平面（Supplementary Private Use Areas, Planes 15 & 16）**：  
  共计 $131,068$ 个完全对公众开放的自定义码位，供各类企业、字库厂商与专业研究机构自行定义内部专用字符。

## 基本多语言平面（BMP）全景宏观路线图

基本多语言平面（Plane 0）是整部人类数字文字文明的微缩全景图。在 **Figure 2-3** 中，作者绘制了一幅精妙绝伦的 BMP 分布矩阵总图：

![基本多语言平面（BMP）宏观路线分布矩阵图（Figure 2-3）](/images/fonts-encodings/fig2-3-bmp-roadmap.png)

*图 2-3：Unicode 基本多语言平面（BMP）宏观路线图（The roadmap of Unicode's Basic Multilingual Plane）。横轴与纵轴以十六进制网格标示，直观展现了从西欧拉丁字母、近东闪米特文字、南亚天城文系统、直到东亚浩瀚汉字表意文字大区的完整拓扑结构。*

让我们顺着这幅宏伟的知识地图，逐一勘察 BMP 各核心区块的精妙布局：

### 1. 拉丁文字与西方语音扩展区（$0\text{x0000} \sim 0\text{x02AF}$）
* **基本拉丁（ASCII, $0\text{x0000}$–$0\text{x007F}$）**与 **Latin-1 补充（$0\text{x0080}$–$0\text{x00FF}$）**：原汁原味地保留了 ISO 8859-1 的全部码位布局；
* **拉丁文扩展-A 与扩展-B（$0\text{x0100}$–$0\text{x024F}$）**：收录了中欧、波罗的海、土耳其语、以及西方语言学家为非洲及美洲土著语汇编的稀有拉丁变体字母；在此亦收录了克罗地亚文与塞尔维亚文一一对应的三个双合字母：‘Ǆ’（dž）、‘ǈ’（lj）与 ‘Ǌ’（nj）；
* **国际音标扩展（IPA Extensions, $0\text{x0250}$–$0\text{x02AF}$）**：国际语音学学会用于精确记录全人类所有发音形态的单形态小写音标符号。

### 2. 欧洲古典与东方基督教文种区（$0\text{x0370} \sim 0\text{x052F}$）
* **希腊文与科普特文（$0\text{x0370}$–$0\text{x03FF}$）**：包含现代单音希腊文与早期埃及科普特教会字母；而在随后的 $0\text{x1F00}$–$0\text{x1FFF}$ 区段，则完整保留了古希腊语典雅的多音重音系统（Polytonic Greek，带有粗气符、柔气符、锐音符与抑扬符）；
* **西里尔字母及其扩展（$0\text{x0400}$–$0\text{x052F}$）**：不仅收录了现代俄语、乌克兰语、保加利亚语与塞尔维亚语字母，还收录了古教会斯拉夫语（Old Church Slavonic）珍贵的早期西里尔字母；
* **亚美尼亚文（$0\text{x0530}$–$0\text{x058F}$）**：公元五世纪圣梅斯罗布（Mesrop Mashtots）创立的高加索独特文字。

### 3. 近东闪米特从右至左（RTL）文字区（$0\text{x0590} \sim 0\text{x08FF}$）
* **希伯来文（$0\text{x0590}$–$0\text{x05FF}$）**：包含现代方块字母以及《希伯来圣经》特有的提比里安发音点号（Niqqud）与诵读吟诵标记（Cantillation marks）；
* **阿拉伯文及其展示形式（$0\text{x0600}$–$0\text{x06FF}$ 及 $0\text{xFB50}$–$0\text{xFEFC}$）**：不仅服务于阿拉伯语，更全面覆盖了波斯语、乌尔都语、普什图语、信德语以及维吾尔语的扩展字母；
* **叙利亚文（Syriac, $0\text{x0700}$–$0\text{x074F}$）**与**西非书面文字（N'Ko, $0\text{x07C0}$–$0\text{x07FF}$）**。

### 4. 印度次大陆与南亚婆罗米系文字群（$0\text{x0900} \sim 0\text{x0DFF}$）
这一区域构成了 Unicode 中结构最为繁复瑰丽的章节。所有源自古代阿育王婆罗米文字（Brahmi script）的南亚与东南亚音素文字（Abugida），全部严格遵循统一的音标网格结构并行排列：
* **天城文（Devanagari, $0\text{x0900}$–$0\text{x097F}$）**：用于书写梵文、印地语与马拉地语；
* **孟加拉文、果鲁穆奇文（旁遮普语）、古吉拉特文、奥里亚文、泰米尔文、泰卢固文、卡纳达文、马拉雅拉姆文与僧伽罗文**；
* 紧随其后的是中南半岛的**泰文（$0\text{x0E00}$–$0\text{x0E7F}$）**、**老挝文（$0\text{x0E80}$–$0\text{x0EFF}$）**、神圣宏大的**藏文（Tibetan, $0\text{x0F00}$–$0\text{x0FFF}$）**、以及**缅甸文与高棉文**。

### 5. 通用符号、数学公式与技术制表符（$0\text{x2000} \sim 0\text{x2BFF}$）
* **通用标点符号（$0\text{x2000}$–$0\text{x206F}$）**：包含了排印学上所有严格度量的空格（全角空格 Em space、半角空格 En space、三分之一空格 Thin space、不换行空格）、破折号（Em dash, En dash）、弯引号（‘ ’ “ ”）、以及现代双向文本控制符（LRM、RLM、ZWNJ、ZWJ）；
* **数学符号矩阵**：包括数学运算符（$\sum, \prod, \int, \sqrt{}$）、箭头符号、几何图形、技术控制符号与盲文点字（Braille Patterns）。

### 6. 汉字表意文字与东亚文字大区（$0\text{x2E80} \sim 0\text{xA4CF}$）
这是基本多语言平面中面积最辽阔的陆地：
* **部首与结构符**：康熙字典部首（$0\text{x2F00}$–$0\text{x2FDF}$）与汉字表意文字描述符（IDC, $0\text{x2FF0}$–$0\text{x2FFF}$）；
* **假名与注音**：日文平假名、片假名以及汉语注音符号（Bopomofo）；
* **CJK 统一表意文字扩展 A 区（Extension A, $0\text{x3400}$–$0\text{x4DBF}$）**：收录 6,582 个生僻表意汉字；
* **CJK 统一表意文字主区（CJK Unified Ideographs, $0\text{x4E00}$–$0\text{x9FFF}$）**：**整整 20,902 个核心汉字**，集结了中日韩三国最核心的通用字汇；
* **彝文音节文字（$0\text{xA000}$–$0\text{xA48F}$）**与**现代韩文谚文音节区（Hangul Syllables, $0\text{xAC00}$–$0\text{xD7A3}$）**：完整收录全部 $11,172$ 个由初声、中声、终声组合而成的现代韩文音节方块字。

### 1. 第一辅助平面（SMP）：古代文献与学术记号的方舟
SMP（第一平面，$\text{U+10000} \sim \text{U+1FFFF}$）堪称全人类古代考古与死文字的数字万神殿：
* **迈锡尼线形文字 B（Linear B, $0\text{x10000}$–$0\text{x1007F}$）**：英国建筑师迈克尔·文特里斯（Michael Ventris）于 1952 年破译的欧洲最古老文献文字；
* **美索不达米亚苏美尔与阿卡德楔形文字（Cuneiform, $0\text{x12000}$–$0\text{x123FF}$）**；
* **音乐与记号体系**：不仅完整收录了现代西洋五线谱记号（音符、休止符、调号），更罕见地收录了中世纪东正教**拜占庭音乐记号（Byzantine Musical Symbols）**与古希腊音乐记谱法；
* **数学字母数字符号（Mathematical Alphanumeric Symbols, $0\text{x1D400}$–$0\text{x1D7FF}$）**：为了让数学公式中的粗体（$\mathbf{A}$）、黑板粗体（$\mathbb{R}, \mathbb{C}$）、手写花体（$\mathcal{H}$）与哥特体（$\mathfrak{g}$）具有独立的数学语义，Unicode 特意在 SMP 中为它们分别建立了严格独立的码位空间！

### 2. 第二辅助平面（SIP）：浩瀚汉字之海
SIP（第二平面，$\text{U+20000} \sim \text{U+2FFFF}$）几乎完全被 **CJK 统一表意文字扩展 B 区（Extension B, $0\text{x20000}$–$0\text{x2A6DF}$）** 所占据。

扩展 B 区收录了惊人的 **42,711 个表意汉字**！这些汉字绝大多数来自中国古代《康熙字典》、《中华大字典》、《汉语大字典》、历代地方志、石刻碑帖以及佛教大藏经中的罕见异体字。扩展 B 区的入轨，使得全球学者在数字化整理千年前的甲骨、青铜铭文与宋元古籍时，第一次摆脱了字形造字与图片贴图的桎梏。

### 3. 第十四平面（SSP）：受控的特殊语言指令
SSP（第十四平面，$\text{U+E0000} \sim \text{U+E0FFF}$）收录了极为罕见的控制标签符：
* **语言标签（Language Tags, $0\text{xE0001}$–$0\text{xE007F}$）**：允许在纯文本内部隐蔽嵌入当前文字所属的 RFC 3066 语言代码（如 `en-US` 或 `zh-CN`）；
* **补充变体选择符（Variation Selectors Supplement, $0\text{xE0100}$–$0\text{xE01EF}$）**：用于为 CJK 汉字或古文字指定极其微妙的历史异体写法。

## 候选文字与未来扩展（Scripts Proposed for Addition）

在作者成书之际，Unicode 的疆界依然在不断向外开拓。人类学者与语言学家组成的专门委员会仍在夜以继日地推进未入轨文字的标准化考察：
* **埃及圣书体象形文字（Egyptian Hieroglyphs）**：数千个描绘神明、鸟兽、法老与器物的象形表意符号，如今已在后续 Unicode 版本中正式落定于 SMP；
* **伯格理苗文（Pollard script）**：二十世纪初英国传教士柏格理在中国西南苗族聚居区创立的精妙音节文字；
* **复活节岛朗格朗格木板文（Rongorongo）**：太平洋绝海孤岛上至今未被完全破译的神秘象形木刻铭文；
* **古南阿拉伯文字（Ancient South Arabian）**：前伊斯兰时期也门与红海沿岸商路的古老文字；
* **蒙古索永布文字（Soyombo）**：1686 年由蒙古高僧扎那巴扎尔创制的精美字母，其首字母至今仍作为国家主权象征傲然铭刻在蒙古国的国旗之上。

从字符的抽象神髓，到字形的千变万化，再到十六进制二进制比特流在平面间的有序排列，Unicode 为人类文明筑起了一座坚不可摧的数字巴别塔。

然而，仅有码位的排列分配，并不足以支撑一篇赏心悦目的高质量文献排印。每个字符在自然语言文本中具备怎样的语法与排版特性？大写与小写如何映射？双向文本如何折行？变音符号如何锚定？

这正是我们在**第三章：Unicode 字符核心属性体系**中即将踏上的全新探索航程。
