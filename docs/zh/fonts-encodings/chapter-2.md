### Chapter 2: Characters, Glyphs, Bytes: An Introduction to Unicode
**著者：雅尼斯·哈拉兰布斯 博士（Yannis Haralambous, Ph.D.）**

*译者：[Lycoris \<lycorismisaka@gmail.com\>](mailto:lycorismisaka@gmail.com)*

在上一章中，我们见证了前 Unicode 时代的诸神混战：从 7 位 ASCII 到各式各样互不兼容的 8 位 ISO 8859 扩展表，再到远东汉字文化圈各自探索的双字节代码页。这种地域性单字节与多字节标准割据的局面，给全球计算机信息交换带来了无穷无尽的乱码梦魇。

如今，计算机世界正日益坚定地迈向全面接纳 Unicode 的轨道，在面对东亚语言和复杂的非西方文字体系时更是如此。然而，向人类全部书写体系开放胸怀是有代价的，那便是不得不接纳这些文字体系背后与生俱来的复杂性。在本章中——作为对 Unicode 的系统导论——我们将深入剖析其基本哲学思想、底层技术机制以及宏观平面规划。在后续各章中，我们还将逐一检视居住在 Unicode 殿堂内的具体文字体系及其技术属性。

## 哲学命题：字符与字形（Characters and Glyphs）

在日常口语与早期浅显的计算机文献中，“字符”（character）、“字模”（letterform）与“字形”（glyph）常常被不加区分地混淆使用。然而在现代计算机排印学与编码理论中，**严格厘清字符与字形的边界，是进入 Unicode 殿堂的绝对第一前提**。

* **字符（Character）**：  
  字符是一个**抽象的概念实体（abstract, intangible entity）**。它是书写语言中最基础的语义单元，拥有明确的语言学身份、名称与规范属性，但它**本身没有任何固定的外貌、大小或视觉形态**。例如，拉丁字母 “小写字母 a” 是一个字符，汉字 “文” 是一个字符，阿拉伯字母 “BEH” 亦是一个字符。字符存在于逻辑与概念的心智世界中。
* **字形（Glyph）**：  
  字形是字符在物理世界的**具体视觉呈现形态（graphical image / visual presentation）**。它是落在纸面上的一团墨迹，或是投射在显示屏上的一组发光像素与贝塞尔矢量曲线。同一个字符，在不同的字体设计师笔下、在不同的历史书写流派中、或在不同的排版上下文中，可以呈现为成百上千种截然不同的字形！

但现实往往比纯粹的二元划分更为复杂：
1. **存在没有字形的字符**：例如空格（Space）、零宽不换行空格（Zero-Width No-Break Space）、从左至右标记（LRM）以及各式各样的排版控制符，它们在页面上完全没有可见墨迹，却承载着至关重要的逻辑与排版指令；
2. **存在对应多种不同字符的字形**：字形外观完全相同的墨迹，在不同语言和语境下代表截然不同的抽象字符；
3. **存在同时对应多个字符的单一体字形**：最典型的便是排版连字（Ligatures，如 ‘ﬁ’ 同时对应字符 ‘f’ 与 ‘i’），以及印度次大陆文字中极其复杂的合体字（Conjuncts）；
4. **存在被拆散为多个碎片的字符**：在孟加拉文、泰米尔文或高棉文中，某些元音字符在视觉呈现上被分裂为左右两侧甚至环绕在辅音四周的多个字形部件。

### 代表性字形（Representative Glyph）的非规范性

幸运的是，Unicode 标准正文以及联盟官方网站上发布的规范代码图表（Code Charts），在给出每一个字符的描述性名称时，总是伴随提供一个可视化的字形——这一字形被称为**代表性字形（Representative Glyph）**。

必须强调的是：**代表性字形仅具有参考与说明意义，完全不具备强制约束力（informative, not prescriptive）**。字形的存在对于非该语言的母语使用者而言至关重要：若没有代表性字形，非藏语学者根本无法仅凭名称 “dzud rtags bzhi mig can” 想象出它是一个由四个小黑点构成的十字记号；而若非北欧如尼卢恩文字专家，人们也绝无可能知晓字母 “ingwaz” 的外貌形如一枚菱形菱角。

然而，若对某种文字缺乏基本认知，单凭代表性字形也常常会造成误解。字符与其字形之间的对应关系可能由于风格流派、历史演进（例如字母 ‘W’ 的印刷体与手写体存在天壤之别）、乃至严苛的语法规则而发生剧烈形变。阿拉伯文便是最极端的例子：阿拉伯字母依据其在单词中的位置（词首、词中、词尾、独立）必须展现不同的外观。例如字符 `ARABIC LETTER KAF` 在 Unicode 代码图表中的代表性字形是独立形态，但在单词中间，它却呈现为一个完全不同、甚至连初学者都难以辨识的扁平字形。

对于表意汉字而言，代表性字形更是查阅字符的唯一途径，因为 Unicode 对数万个汉字完全无法提供语义层面的文字描述。我们或许可以设想将汉字 “門” 描述为“意为‘大门’的字符”；然而，仅在日文语境中，“門”便同时兼具“入口”、“门户”、“门径”、“部门”、“学科”、“弟子”、“学派”乃至“宗族”等十余种截然不同的含义。若试图以此方式为 Unicode 收录的 70,027 个表意汉字编写语义描述，不仅工作量浩瀚如烟海，而且在学术上也是徒劳无益的。

### 为什么计算机不应编码字形？

早期某些字符编码之所以走向失败，其根本原因就在于试图将特定的“视觉字形”硬塞入字符表中。试想：如果一种字体中包含正体 ‘a’、斜体 ‘*a*’、粗体 ‘**a**’、双层 ‘a’ 与单层手写体 ‘ɑ’，我们是否应当为它们分别分配独立的编码码位？

答案是绝对坚决的否定。如果将排版样式的字形变体编码为独立字符，全文检索、自然语言处理、语义分词与拼写检查将瞬间陷入灭顶之灾：搜索引擎在匹配单词 “apple” 时，将无法命中以斜体或粗体书写的同一单词！

因此，现代编码哲学的至高法则为：**编码（encoding）只负责收录抽象的“字符”（What you mean），而字体（font）则负责提供具象的“字形”（How it looks）**。

如果我们将这些视觉字形转换到小写形态，字符的真实本质便瞬间原形毕露：拉丁字母是 ‘h’，希腊字母是 ‘η’，西里尔字母则是 ‘н’。甚至在同一文字系统内部，也存在字形完全重合的独立字符：例如大写字母 ‘Ð’，在冰岛文中是带横杠的 Eth（小写为 ‘ð’），在塞尔维亚-克罗地亚文中是带横杠的 D（小写为 ‘đ’），而在某些非洲语言中又是另一个独立的音标字母。只有通过 Unicode 的字符码位与底层属性体系，软件才能真正理解文本背后的数理与语言学本质，而无需在每一次排版时都重新发明轮子。

### Unicode 联盟与 ISO 10646 的世纪合流

Unicode 运动最初于 1987 年由施乐帕洛阿尔托研究中心（Xerox PARC）的乔·贝克尔（Joe Becker）、李·柯林斯（Lee Collins）与苹果公司的马克·戴维斯（Mark Davis）共同倡议发起。1991 年 1 月，**Unicode 联盟（Unicode Consortium）**在加州正式注册成立。

与此并行，国际标准化组织（ISO）亦在推进其官方的国际多八位编码字符集计划——**ISO/IEC 10646**（即通用字符集 UCS, Universal Character Set）。在初期，ISO 阵营倾向于构建一个庞大的 31 位四维编码空间（组 Group、面 Plane、排 Row、格 Cell），其总容量高达 20 亿个码位；而早期 Unicode 阵营则极力主张构建一个紧凑高效、面向全人类现代常用文字的统一 16 位定长编码（$2^{16} = 65,536$ 个码位）。

两大标准体系的分裂势必造成全球软件工业的灾难。所幸在 1991 年底，双方达成了极具远见的重大历史和解与合并协议：
* 双方的字符码位分配实现**完全严格的一对一同步（1:1 synchronization）**；
* ISO/IEC 10646 的第一组第零平面（Group 00, Plane 00）被永久确立为 **基本多语言平面（BMP, Basic Multilingual Plane）**，其码位与 Unicode 16 位空间完全一一对应；
* 双方共用一套字符命名与属性规范，彻底避免了世界计算标准的分裂。

## Unicode 十大第一原则（First Principles）

Unicode 体系之所以能够超越此前所有字符编码标准，在于其从诞生之初就确立了十项不可动摇的顶层公理架构（The Ten Principles of Unicode）：

1. **通用性（Universal repertoire）**：  
   Unicode 致力于收录全世界一切书写系统中所使用过的所有字符——不仅涵盖所有现代活语言，亦囊括古文字、楔形文字、象形文字以及广袤的数学、音乐、科学专业符号。
2. **高效性（Efficiency）**：  
   听起来像是 1950 年代广告里的宣传口号，但它包含着深刻的技术真理。从纯工程角度看，Unicode 使我们彻底摆脱了 ASCII 控制字符、ISO 2022 的转义状态机切换等痛苦枷锁。无可否认，Unicode 配套的文档（规范文本、技术报告、学术研讨会文献）远比 ISO 标准冷酷干瘪的官僚条款更为高效实用。
3. **字符与字形的差异（Characters, not glyphs）**：  
   正如前文所述，字符与字形是截然不同的两个概念，Unicode 严格仅为抽象字符编码。尽管计算机科学界至今仍未能给“字符”下一个无懈可击的形式语言定义，但 Unicode 至少厘清了长期盘踞在工程师脑海中的混沌观念。
4. **明确定义字符语义（Semantics）**：  
   每一个已分配的码位在任何时间、任何语境下，均唯一且无歧义地对应一个具体的抽象字符及其完整的数学、方向性、分类学与规范属性。
5. **纯文本原则（Plain text）**：  
   Unicode 序列仅承载最纯粹的底层纯文本字符流。任何关于字体选择、字号大小、行距、边距与色彩的排版富文本属性，均属于外部标记语言（如 HTML、XML、RTF）的范畴。作者在此指出：诸如段落折行方向或语言标签等高层信息，本应由上层协议（如 XML 的 `xml:lang` 属性）优雅处理，Unicode 却出于“纯文本必须在任何封闭协议中自包含”的执念，固执地在底层引入了语言标签控制符，这构成了 Unicode 设计哲学中颇耐人寻味的一笔。
6. **逻辑顺序（Logical order）**：  
   在计算机内存与数据流中，字符必须严格按照人类思维书写或朗读发音的**逻辑先后顺序（logical memory order）**存储。对于阿拉伯文与希伯来文等从右向左（RTL）书写的文字，其在内存中的存储顺序依然与从左向右（LTR）文字一致（先读的在前，后读的在后），屏幕上的逆向呈现完全交由排版系统的**双向算法（Bidi Algorithm）**负责。
7. **字符统合（Unification）**：  
   当不同文化或同一语言体系中的若干字符，在书写历史、图形起源与现代语义上具有同源性与共同特征时，Unicode 坚决将其统合归并为一个单一码位。最著名的范例莫过于**中日韩汉字统合（Han Unification）**。
8. **动态组合（Dynamic composition）**：  
   Unicode 允许带有重音符或附加变音标记的字符通过“基础字符 + 组合变音符”（Base Character + Combining Marks）在排版时动态拼合，而无需为每一种可能的复合变音字符穷举分配静态码位。然而这种灵活性亦有代价：在一个 Unicode 字符串中，若任意截取一个以组合字符开头的子串，该子串在语法上是不合法的——这在传统的 ASCII 或 ISO 8859 中绝不会发生。
9. **等价序列（Equivalent sequences）**：  
   为了照顾既有遗留系统的兼容性，Unicode 既保留了大量“预合成字符”（Precomposed Characters，如带有重音的字母），又支持通过基础字符加组合标记构成的“分解序列”（Decomposed Sequences）。原则九庄严承诺：这两类在表现形式上不同的字符序列，在数理与排版语义上完全等价，并通过规范正规化形式（UAX #15）相互映射。
10. **可转换性（Convertibility）与稳定性（Stability）**：  
    这是给 Unicode 带来最大非议但也正是促成其被全球工业界全面接纳的基石。该原则规定：所有在业界广泛使用的既有国家或行业编码标准，必须能够**无损地（round-trip）可逆转换到 Unicode**。其代价是残酷的：每一个古怪、生僻、定义含糊、乃至纯属冗余的字符（如通用货币符号、DOS 代码页的制表线条、打字机退格重叠字符、甚至韩国为了两种不同发音而对同一汉字进行的重复编码），全都被抬进了 Unicode 的神圣殿堂！与此同时，**稳定性原则保证码位一旦分配，其数值与名称永恒冻结、绝不删除、绝不更改**，即便发现历史拼写错误亦立字为据，永不变更。

## 技术命题：字符、码位与字节

正如哲学家所言，生活不仅有形而上的哲学，更有物理世界的骨感现实。在计算机系统内部，字符究竟如何落地为磁盘上的比特与字节？

现代字符标准体系将字符的表征清晰划分为五层模型架构：
$$\text{抽象字符库（ACR）} \longrightarrow \text{编码字符集（CCS）} \longrightarrow \text{字符编码形式（CEF）} \longrightarrow \text{字符编码方案（CES）} \longrightarrow \text{传输语法（TES）}$$

1. **抽象字符库（Abstract Character Repertoire, ACR）**：  
   所有被标准认定的抽象字符的无序集合；
2. **编码字符集（Coded Character Set, CCS）**：  
   将抽象字符库中的每一个字符映射到一个唯一的非负整数——这个整数被称为**码位（Code Point）**。在 Unicode 规范中，码位以统一的前缀标记：
   $$\text{U+0000} \sim \text{U+10FFFF}$$
   总共定义了 $16 \times 2^{16} + 2^{16} = 17 \times 65,536 = 1,114,112$ 个码位。其中排除了代理区码位后的有效字符码位被称为 **Unicode 标量值（Unicode scalar value）**。
3. **字符编码形式（Character Encoding Form, CEF）**：  
   将整数码位映射为定长的计算机基本整数单元（Code Unit, 码元），即 UTF-32、UTF-16 与 UTF-8；
4. **字符编码方案（Character Encoding Scheme, CES）**：  
   处理多字节码元序列在不同硬件架构下的**字节序（Endianness）**，如 UTF-16BE（大端序）、UTF-16LE（小端序）；
5. **传输编码语法（Transfer Encoding Syntax, TES）**：  
   针对特定有损通信信道（如早期 7 位 SMTP 邮件）的数据封装，如 Base64 与 Quoted-Printable。

步骤 (1) 至 (4) 在工业界统称为**字符映射表（Character Map）**，其官方名称在互联网号码分配局（IANA）正式注册，以便在 MIME、HTTP 等底层网络协议中准确标识：
* `UTF-8`：最普及的 1 至 4 字节变长编码；
* `UTF-7`：专为 7 位邮件信道设计的非官方基数 64 转移编码（RFC 2152）；
* `UTF-32` / `UTF-32LE` / `UTF-32BE`：直接采用 32 位双字定长表示的编码形式与大小端方案；
* `UTF-16` / `UTF-16LE` / `UTF-16BE`：采用 16 位字（wyde）定长/变长代理对的编码形式与大小端方案；
* `UNICODE-1-1` / `UNICODE-1-1-UTF-7`：历史版本规范；
* `CESU-8`：面向 UTF-16 代理对的特殊 8 位兼容方案；
* `SCSU`：Unicode 标准压缩方案（UTS #6）；
* `BOCU-1`：保持二进制排序特性的压缩方案。

## 主流字符编码形式（CEF）深度解析

### 1. UTF-32 与定长表示

UTF-32（以及 ISO 10646 的 UCS-4）是概念上最纯粹的编码形式：它使用一个完整的 32 位（4 字节）无符号整数来直接表示每一个 Unicode 码位。
* **优势**：绝对的定长特性。字符串中第 $N$ 个字符必然位于内存偏移量 $4N$ 处，使得按索引随机访问字符的时间复杂度达到最优的 $O(1)$；
* **致命缺陷**：对绝大多数以拉丁字母、希腊字母或常用符号构成的西方文本而言，UTF-32 中高达 75% 的字节全部是无意义的零填充（`0x00 0x00 0x00`），造成了内存带宽、缓存命中率与磁盘空间的极其惨烈的浪费。

### 2. UTF-16 与代理对（Surrogate Pairs）数学机制

当 Unicode 联盟在 1990 年代中期意识到 16 位（65,536 个码位）终将无法容纳全人类的生僻汉字与古代文字时，工业界面临抉择：要么全面推倒重来强推 32 位，要么设计一种平滑兼容 16 位的优雅扩展算法。

计算机科学家们最终提出了极其精妙的**代理对（Surrogate Pairs）机制**，由此诞生了 **UTF-16**。

在基本多语言平面（BMP，即 $\text{U+0000} \sim \text{U+FFFF}$）中，Unicode 特意开辟了一片永远不分配给任何实际字符的“真空禁区”——**代理区（Surrogates, $\text{U+D800} \sim \text{U+DFFF}$，共 2,048 个码位）**，并将其均分为两大半区：
* **高半区代理（High Surrogates / Lead Surrogates）**：$\text{U+D800} \sim \text{U+DBFF}$（共 $1,024 = 2^{10}$ 个值）；
* **低半区代理（Low Surrogates / Trail Surrogates）**：$\text{U+DC00} \sim \text{U+DFFF}$（共 $1,024 = 2^{10}$ 个值）。

任何一个落在辅助平面（Planes 1–16，即 $\text{U+10000} \sim \text{U+10FFFF}$）的高位码位 $N$，其数值必然满足：
$$0 \le N - 0\text{x10000} \le 0\text{xFFFFF}$$

这个差值正好是一个 20 位的二进制数！UTF-16 巧妙地将这 20 位对半切分为两组 10 位：
* 高 10 位加上偏移基数 $0\text{xD800}$，生成一个**高半区代理字**（前导代理）；
* 低 10 位加上偏移基数 $0\text{xDC00}$，生成一个**低半区代理字**（后尾代理）。

#### 代理对数学转换方程
* **编码（码位 $N \to$ 代理对 $(H, L)$）**：
  $$N' = N - 0\text{x10000}$$
  $$H = 0\text{xD800} + \lfloor N' / 0\text{x400} \rfloor = 0\text{xD800} + (N' \gg 10)$$
  $$L = 0\text{xDC00} + (N' \pmod{0\text{x400}}) = 0\text{xDC00} + (N' \ \& \ 0\text{x3FF})$$
* **解码（代理对 $(H, L) \to$ 码位 $N$）**：
  $$N = ((H - 0\text{xD800}) \times 0\text{x400}) + (L - 0\text{xDC00}) + 0\text{x10000}$$

由于高代理（`0xD800`–`0xDBFF`）与低代理（`0xDC00`–`0xDFFF`）的取值区间完全互斥，且与任何合法的 BMP 字符码位完全隔离，解析引擎在数据流中向前或向后滑动时，能够瞬间且无歧义地判定当前 16 位整数究竟是一个完整的单字符，还是代理对的头部或尾部！

### 3. UTF-8：贝尔实验室的传世杰作

1992 年 9 月的一天晚上，在新泽西州的一家餐馆里，肯·汤普森（Ken Thompson）与罗布·派克（Rob Pike）在餐巾纸上勾勒出了计算历史上最完美的编码形式——**UTF-8**（原名 FSS-UTF）。

UTF-8 是一套纯粹的**以 8 位字节为基准的变长编码形式（variable-width byte-based encoding）**，它使用 1 至 4 个字节来对 21 位的 Unicode 码位进行精确切分：

| 标量码位范围（十六进制） | 字节数 | 字节 1（前导字节） | 字节 2（后随字节） | 字节 3（后随字节） | 字节 4（后随字节） |
| :--- | :---: | :--- | :--- | :--- | :--- |
| `00000000`–`0000007F` | 1 | `0xxxxxxx` | — | — | — |
| `00000080`–`000007FF` | 2 | `110yyyyy` | `10xxxxxx` | — | — |
| `00000800`–`0000FFFF` | 3 | `1110zzzz` | `10yyyyyy` | `10xxxxxx` | — |
| `00010000`–`0010FFFF` | 4 | `11110uuu` | `10uuzzzz` | `10yyyyyy` | `10xxxxxx` |

#### UTF-8 的工程美学巅峰：
1. **绝对向下兼容 ASCII**：  
   对于 `0x00`–`0x7F` 的 128 个 ASCII 字符，UTF-8 使用单字节存储，且最高位（bit 7）恒为 0。这意味着任何合法的 ASCII 英文文件，**无需做任何字节转换，本身就是一份完全合法的 UTF-8 文件**！所有原本只认识 C 语言 ASCII 字符串（以 `\0` 结尾）的古老系统工具（如 `grep`、`sed`、`awk`、编译器），完全无需重写即可直接操作 UTF-8。
2. **前缀自同步特性（Self-synchronizing）**：  
   在多字节序列中：
   * 前导字节（Lead Byte）的高位具有特征掩码：`110...` 代表后续跟随 1 个字节；`1110...` 代表后续跟随 2 个字节；`11110...` 代表后续跟随 3 个字节；
   * 所有后随字节（Continuation Bytes）的高两位**恒定为 `10xxxxxx`**！
   这种设计具有无与伦比的容错性：如果由于网络传输丢包或磁盘损坏导致字节流中间发生截断，解码器只需线性向后扫描，一旦遇到一个最高位不是 `10...` 的字节，便能**瞬间找回同步边界（resynchronize）**重新开始正确解码，绝不会让单点故障滚雪球式污染整个后续文本！
3. **彻底根除大小端问题**：  
   由于 UTF-8 的数据单元本身就是 8 位字节，它在任何 CPU 架构下都不存在多字节整数的高低端重排问题，无需字节顺序标记（BOM）。
4. **非最短形式（Overlong Forms）与安全漏洞**：  
   在 UTF-8 早期实现中，某些解码器允许多种字节序列解码为同一个字符（例如用双字节 `0xC0 0xAF` 表达斜杠 `/`，即 ASCII `0x2F`）。黑客利用此漏洞成功绕过了大量 Web 服务器（如著名的 IIS 目录遍历漏洞）的路径安全检查。现代 Unicode 规范已彻底封禁一切非最短编码形式，合法的 UTF-8 序列必须是绝对唯一的。

### 4. 字节顺序标记（Byte Order Mark, BOM）

在处理 UTF-16 与 UTF-32 时，多字节整数在内存中究竟应当高位在前（大端序 Big-Endian）还是低位在前（小端序 Little-Endian），取决于底层 CPU 的物理架构（Intel x86 采用小端，Motorola/PowerPC 采用大端）。

为了在跨平台交换文件时消除歧义，Unicode 特意设计了**字节顺序标记（BOM）**：字符 **$U+\text{FEFF}$（零宽不换行空格 / ZERO WIDTH NO-BREAK SPACE）**。
* 如果接收方在文件开头读入的两个字节是 `0xFE 0xFF`，则表明该文本采用大端序（UTF-16BE）；
* 如果读入的两个字节是 `0xFF 0xFE`，则表明该文本采用小端序（UTF-16LE）。为什么？因为在 Unicode 规范中，**$U+\text{FFFE}$ 已经被永久声明为一个非法字符（Noncharacter）**，它在任何合法的 Unicode 文本中都绝不可能存在！一旦出现，唯一的解释就是当前系统的字节读取顺序颠倒了。
* 对于 UTF-32，其 BOM 为 `0x00 0x00 0xFE 0xFF`（大端）或 `0xFF 0xFE 0x00 0x00`（小端），反转后的 `0xFF 0xFE 0x00 0x00` 远超有效范围，极易辨识。
* 至于剪切粘贴中可能夹带的冗余 BOM，排版引擎和搜索算法会将其作为不可见无害字符自动忽略。Unicode 3.2 进一步引入了专用字符 $U+\text{2060}$（`WORD JOINER`）来承担纯粹的零宽不换行语义，使得 $U+\text{FEFF}$ 的职责更加纯粹地聚焦于文件开头的 BOM 签名。

### 5. CESU-8、SCSU 与 BOCU-1 压缩机制

除了主流形式外，Unicode 历史上还诞生过若干极具工程特色的特种编码与压缩算法：

#### CESU-8（UTF-16 的 8 位兼容编码）
CESU-8（RFC 2781 / UTR #26）是 UTF-16 与 UTF-8 的奇特混合体。在 CESU-8 中，文本首先被转换为 UTF-16（辅助平面字符被分解为高低代理对）；随后，系统对每一个 16 位代理字分别执行独立的 3 字节 UTF-8 编码！因此，一个本可在 UTF-8 中用 4 字节表示的辅助平面汉字，在 CESU-8 中被膨胀成了两个 3 字节序列，共计 6 个字节。CESU-8 在 Oracle 数据库内部以及 Java 早期序列化中广泛使用，但在公开网络数据交换中被严格禁止。

#### SCSU（Unicode 标准压缩方案，UTS #6）
对于非英语环境（如俄文、阿拉伯文、希伯来文），UTF-16 导致文件体积翻倍，而 UTF-8 亦需要 2 至 3 个字节。为此，Unicode 联盟设计了 SCSU 压缩方案。其核心原理是引入一个**在 Unicode 码表中滑动的 128 字符宽度的“窗口”**：
* 系统维护 **8 个动态窗口**（可随数据流动态重新定位）和 **8 个静态预置窗口**；
* 初始状态下位于窗口 0（ASCII）。当文本切换至特定语言块时，通过发送短小的控制指令改变活动窗口；
* 位于当前窗口内的字符，在字节流中仅需占用 **单个字节（Single Byte, 0x80–0xFF）**！
* SCSU 包含“压缩单字节模式”与“Unicode（UTF-16）全宽模式”，通过如下指令精密切换：

| 控制指令 | 字节值 | 功能语义与参数 |
| :--- | :--- | :--- |
| **SCU** | `0x0F` | 永久切换至 Unicode 16 位模式（直至另行切换） |
| **SQn** | `0x01`–`0x08` | 临时从窗口 $n$ 引用单个字符（单字符临时转义） |
| **SCn** | `0x10`–`0x17` | 永久将活动窗口切换至动态窗口 $n$（锁定切换） |
| **SDn** | `0x18`–`0x1F` | 将动态窗口 $n$ 的基准原点重新定义为索引字节 $B$ 指向的区块 |
| **SDX** | `0x0B` | 扩展窗口重定义，后随双字节字 $W$ |
| **UQU** | `0xF0` | 在 Unicode 模式下直接引用一个非转义 Unicode 字符 |
| **UCn / UDn** | `0xE0`–`0xEF` | 在 Unicode 模式下的窗口切换与重定义 |

在 SDn 指令中，索引字节 $B$ 与实际码位原点的映射关系极具语言学特色：
* `0x01`–`0x67`：原点为 $B \times 0\text{x80}$（覆盖 $0\text{x0080} \sim 0\text{x3380}$ 的各个半区块）；
* `0x68`–`0xA7`：原点为 $B \times 0\text{x80} + 0\text{xAC00}$（覆盖 $0\text{xE000} \sim 0\text{xFF80}$）；
* 特殊离散值：`0xF9` $\to 0\text{x00C0}$（拉丁文），`0xFA` $\to 0\text{x0250}$（国际音标），`0xFB` $\to 0\text{x0370}$（希腊文），`0xFC` $\to 0\text{x0530}$（亚美尼亚文），`0xFD` $\to 0\text{x3040}$（日文平假名），`0xFE` $\to 0\text{x30A0}$（日文片假名），`0xFF` $\to 0\text{xFF60}$（半角片假名）。

#### BOCU-1（保持二进制排序特性的压缩方案，UTR #24）
虽然 SCSU 压缩率极高，但它破坏了字符串底层的码位大小顺序。BOCU-1 在提供与 SCSU 相当的压缩性能的同时，实现了一个极其震撼的数学特性：**保持二进制顺序（Binary Ordered）**！  
这意味着：直接对若干段经过 BOCU-1 压缩的原始二进制字节流进行字典序比较，其排序结果与将它们解压回完整 Unicode 文本后的排序结果**完全严格一致**！这使得数据库能够在保持底层数据压缩存储的状态下，直接在索引树上执行高速二分查找与归并排序，同时它完全兼容 MIME 协议，安全避开了 ASCII 关键控制符。

*图 2-2：Unicode 体系中已分配填充的六大平面（The six currently populated planes of Unicode）：第 0 平面（BMP）、第 1 平面（SMP）、第 2 平面（SIP）、第 14 平面（SSP）、以及第 15 与 16 平面（私用补充平面）。*

* **第 0 平面：基本多语言平面（BMP, Basic Multilingual Plane, $0\text{x0000}$–$0\text{xFFFF}$）**：  
  全书最核心的心脏地带，囊括了当今现代世界正在使用的绝大多数书写系统、全套通用符号体系与常用汉字表意文字；
* **第 1 平面：第一辅助平面 / 多语言补充平面（SMP, Supplementary Multilingual Plane, $0\text{x10000}$–$0\text{x1FFFF}$）**：  
  主要容纳人类历史上的古代文献书写系统（如埃及象形文字、苏美尔与波斯楔形文字、古希腊古代碑铭与音乐记号）、专业数学字母数字符号、以及历史古记号；
* **第 2 平面：第二辅助平面 / 表意文字补充平面（SIP, Supplementary Ideographic Plane, $0\text{x20000}$–$0\text{x2FFFF}$）**：  
  东亚中日韩表意汉字的海量扩充库（收录扩展 B、C、D 等大批古籍异体字、历史地名及生僻姓氏字）；
* **第 14 平面：特别用途补充平面（SSP, Supplementary Special-Purpose Plane, $0\text{xE0000}$–$0\text{xE0FFF}$）**：  
  类似“工程隔离检疫区”，专门存放语言标签标记与补充变体选择符；
* **第 15 与 16 平面：私用补充平面（Supplementary Private Use Areas, Planes 15 & 16）**：  
  共计 $131,068$ 个完全对公众开放的自定义码位，供各类企业、字库厂商与专业研究机构自行定义内部专用字符。

让我们顺着这幅宏伟的知识地图，逐一勘察 BMP 各核心区块的精妙布局：

### 1. 拉丁文字与西方语音扩展区（$0\text{x0000} \sim 0\text{x02AF}$）
* **基本拉丁（ASCII, $0\text{x0000}$–$0\text{x007F}$）**与 **Latin-1 补充（$0\text{x0080}$–$0\text{x00FF}$）**：原汁原味地保留了 ISO 8859-1 的全部码位布局；
* **拉丁文扩展-A 与扩展-B（$0\text{x0100}$–$0\text{x024F}$）**：收录了中欧、波罗的海、土耳其语、以及西方语言学家为非洲及美洲土著语汇编的稀有拉丁变体字母；在此亦收录了罗马尼亚语中带下逗号而非下加尾的特殊字母 ‘ș’ 与 ‘ț’，以及克罗地亚文与塞尔维亚文一一对应的三个双合字母：‘Ǆ’（dž）、‘ǈ’（lj）与 ‘Ǌ’（nj）。由于这些双合字母在词首大写（如 ‘Dž’）与全大写（如 ‘DŽ’）时具有不同字形，Unicode 不得不为它们分别分配独立码位；
* **国际音标扩展（IPA Extensions, $0\text{x0250}$–$0\text{x02AF}$）**：国际语音学学会用于精确记录全人类所有发音形态的单形态小写音标符号。

### 2. 欧洲古典与东方基督教文种区（$0\text{x0370} \sim 0\text{x052F}$）
* **希腊文与科普特文（$0\text{x0370}$–$0\text{x03FF}$）**：包含现代单音希腊文与早期埃及科普特教会字母；而在随后的 $0\text{x1F00}$–$0\text{x1FFF}$ 区段，则完整保留了古希腊语典雅的多音重音系统（Polytonic Greek，带有粗气符、柔气符、锐音符与抑扬符）；
* **西里尔字母及其扩展（$0\text{x0400}$–$0\text{x052F}$）**：不仅收录了现代俄语、乌克兰语、保加利亚语与塞尔维亚语字母，还收录了古教会斯拉夫语（Old Church Slavonic）珍贵的早期西里尔字母；
* **亚美尼亚文（$0\text{x0530}$–$0\text{x058F}$）**：公元五世纪圣梅斯罗布（Mesrop Mashtots）创立的高加索独特文字。

### 3. 近东闪米特从右至左（RTL）文字区（$0\text{x0590} \sim 0\text{x08FF}$）
* **希伯来文（$0\text{x0590}$–$0\text{x05FF}$）**：包含现代方块字母、圣经吟诵音符（Cantillation marks）与提比里亚元音点标记（Niqqud）；
* **阿拉伯文及其扩展（$0\text{x0600}$–$0\text{x06FF}$）**：收录了阿拉伯语、波斯语、乌尔都语、普什图语、信德语以及维吾尔语等所有使用阿拉伯字母书写的语言符号体系；
* **叙利亚文（Syriac, $0\text{x0700}$–$0\text{x074F}$）**：美索不达米亚平原古基督教文学的重要载体；
* **它拿字母（Thaana, $0\text{x0780}$–$0\text{x07BF}$）**：印度洋岛国马尔代夫的官方书写系统，其字母巧妙脱胎于阿拉伯数字与本地数字符号。

### 4. 印度次大陆与南亚婆罗米系文字群（$0\text{x0900} \sim 0\text{x0DFF}$）
涵盖了梵文、印地文的天城文（Devanagari）、孟加拉文（Bengali）、果鲁穆奇文（Gurmukhi，锡克教圣书文字）、古吉拉特文（Gujarati）、奥里亚文（Oriya）、泰米尔文（Tamil）、泰卢固文（Telugu）、卡纳达文（Kannada）、马拉雅拉姆文（Malayalam）与僧伽罗文（Sinhala）。这些文字在底层共用高度一致的婆罗米（Brahmi）音素音节架构，其码位分布呈现出近乎严密的平行镜像布局。

### 5. 东南亚、高加索与美洲土著文字区（$0\text{x0E00} \sim 0\text{x18FF}$）
* **泰文（Thai, $0\text{x0E00}$–$0\text{x0E7F}$）** 与 **老挝文（Lao, $0\text{x0E80}$–$0\text{x0EFF}$）**：词间无空格的连续书写系统；
* **藏文（Tibetan, $0\text{x0F00}$–$0\text{x0FFF}$）**：庞大的上下叠字辅音与宗教法器记号；
* **缅甸文、格鲁吉亚文与高棉文**；
* **埃塞俄比亚文（Ethiopic, $0\text{x1200}$–$0\text{x137F}$）**：闪米特语族中唯一从左至右书写的音节文字；
* **切罗基文（Cherokee, $0\text{x13A0}$–$0\text{x13F4}$）**：北美印第安酋长塞阔雅（Sequoyah）于 1820 年代独立发明的音节文字，借用了拉丁字母外观却赋予其完全不同的发音（例如用字母 ‘D’、‘R’、‘T’ 分别表示音节 /a/、/e/、/i/）；
* **加拿大原住民音节文字（Unified Canadian Aboriginal Syllabics, $0\text{x1401}$–$0\text{x1676}$）**：以纯粹几何形状及其空间旋转方向表达不同元音的精妙书写系统；
* **欧甘文字（Ogham, $0\text{x1680}$–$0\text{x169C}$）**与**如尼文字（Runic, $0\text{x16A0}$–$0\text{x16FF}$）**：古代凯尔特人刻于石柱棱线上的树木文字，以及维京人的古代占卜文字；
* **菲律宾古代文字（塔加洛文、哈努诺文、布希德文、塔格巴努瓦文）**；
* **蒙古文（Mongolian, $0\text{x1800}$–$0\text{x18AF}$）**：源自回鹘字母、自上而下垂直书写、且带有极复杂词首/词中/词尾变形的古老文字。

### 6. 通用符号、数学公式与技术制表符（$0\text{x2000} \sim 0\text{x2BFF}$）
这一大区是现代科学、制图与数学排版的军火库：
* **常用标点（General Punctuation, $0\text{x2000}$–$0\text{x206F}$）**：收录了各种宽度（Em-space, En-space, Thin-space）的排印空格、各式破折号（Em-dash, En-dash）、连字控制符（ZWJ / ZWNJ）；
* **上标与下标、货币符号（包括欧元符号 €）、组合符号用标记、字母式符号（如 $\mathbb{R}, \mathbb{C}, \aleph, \wp$）**；
* **数学运算符、几何图形、技术制表符（Box Drawing，DOS 界面遗老）**；
* **杂项技术符号、盲文点字（Braille Patterns, $0\text{x2800}$–$0\text{x28FF}$，用 8 位点阵的二进制子集完美覆盖全部 256 种盲文形态）**；
* **印刷杂符（Dingbats）**：全套继承赫尔曼·察夫设计的 ITC Zapf Dingbats 经典装饰符号。

### 7. 汉字部首、假名、注音与东亚大区（$0\text{x2E80} \sim 0\text{xA4CF}$）
* **康熙部首与表意文字描述符（IDC, $0\text{x2FF0}$–$0\text{x2FFB}$）**；
* **平假名、片假名、注音符号（Bopomofo）与谚文兼容字母**；
* **彝文音节（Yi Syllables, $0\text{xA000}$–$0\text{xA48F}$）**：中国西南部大凉山彝族规范化的千余个音节文字；
* **CJK 统一表意文字基本区（$0\text{x4E00} \sim 0\text{x9FA5}$）**：收录了 20,902 个中日韩常用汉字，构成了东亚文明的信息中枢；
* **朝鲜文谚文音节（Hangul Syllables, $0\text{xAC00} \sim 0\text{xD7A3}$）**：收录了全部 11,172 个预合成音节方块字。

### 8. 代理区、私用区与兼容区（$0\text{xD800} \sim 0\text{xDFFF}$ / $0\text{xE000} \sim 0\text{xFFFF}$）
* **代理区（Surrogates, $0\text{xD800}$–$0\text{xDFFF}$）**：永不分配任何字符的 UTF-16 专用禁区；
* **私用区（Private Use Area, PUA, $0\text{xE000}$–$0\text{xF8FF}$）**：共 6,400 个供用户和厂商内部自由定义的私有码位；
* **兼容区与全半角变体区（$0\text{xFB00}$–$0\text{xFFFD}$）**：收录了西文连字（ﬁ, ﬂ）、阿拉伯文连字形态、中日韩竖排兼容符号、以及为了兼容遗留终端而保留的半角假名与全角 ASCII 字符。

### 1. 第一辅助平面（SMP）：古代文献与学术记号的方舟
SMP（第一平面，$\text{U+10000} \sim \text{U+1FFFF}$）堪称全人类古代考古与死文字的数字万神殿：
* **迈锡尼线形文字 B（Linear B, $0\text{x10000}$–$0\text{x100FA}$）**：克里特岛米诺斯文明时期的古老文字（约公元前 2000 年），由英国建筑师兼业余考古学者迈克尔·文特里斯（Michael Ventris）于 1952 年奇迹般破译；
* **古希腊与爱琴海数字、古意大利字母与古哥特字母（Gothic）**；
* **美索不达米亚苏美尔、阿卡德与波斯楔形文字（Cuneiform）**；
* **乌加里特文字（Ugaritic）与腓尼基字母（Phoenician）**；
* **德瑟雷特字母（Deseret, $0\text{x10400}$–$0\text{x1044F}$）**：19 世纪中叶犹他州摩门教徒试图建立文化隔离而自创的一套奇异音标拼写系统；
* **肖伯纳字母（Shavian）**：剧作家萧伯纳在遗嘱中资助建立的英语正字法改革字母；
* **卡罗须提文（Kharoshthi, $0\text{x10A00}$–$0\text{x10A5F}$）**：古代犍陀罗佛教文献的核心文字；
* **音乐记号体系**：不仅收录了现代西洋五线谱记号，还包括中世纪东正教**拜占庭音乐记号（Byzantine Musical Symbols）**与古希腊音乐记谱法；
* **数学字母数字符号（Mathematical Alphanumeric Symbols, $0\text{x1D400}$–$0\text{x1D7FF}$）**：为了让数学公式中的粗体（$\mathbf{A}$）、黑板粗体（$\mathbb{R}, \mathbb{C}$）、手写花体（$\mathcal{H}$）与哥特体（$\mathfrak{g}$）具有独立的数学语义，Unicode 特意在 SMP 中为它们分别建立了严格独立的码位空间！

### 2. 第二辅助平面（SIP）：浩瀚汉字之海
SIP（第二平面，$\text{U+20000} \sim \text{U+2FFFF}$）几乎完全被 **CJK 统一表意文字扩展 B 区（Extension B, $0\text{x20000}$–$0\text{x2A6DF}$）** 所占据。

扩展 B 区收录了惊人的 **42,711 个表意汉字**！这些汉字绝大多数来自中国古代《康熙字典》、《中华大字典》、《汉语大字典》、历代地方志、石刻碑帖以及佛教大藏经中的罕见异体字。在平面尾部，还收录了来自台湾 CNS 11643-1992 标准的补充兼容表意文字（$0\text{x2F800}$–$0\text{x2FA1D}$）。扩展 B 区的入轨，使得全球学者在数字化整理千年前的甲骨、青铜铭文与宋元古籍时，第一次摆脱了字形造字与图片贴图的桎梏。

### 3. 第十四平面（SSP）：受控的特殊语言指令
SSP（第十四平面，$\text{U+E0000} \sim \text{U+E0FFF}$）收录了极为罕见的控制标签符：
* **语言标签（Language Tags, $0\text{xE0001}$–$0\text{xE007F}$）**：这是整个 Unicode 标准中最具争议的区块。尽管高层标记语言（如 XML 的 `xml:lang`）能够更干净地声明语言，但为了在最受限的纯文本通信（如 URL）中亦能传递语言元数据，Unicode 在此复刻了一整套 ASCII 码的“幽灵标签字符”；
* **补充变体选择符（Variation Selectors Supplement, $0\text{xE0100}$–$0\text{xE01EF}$）**：共 240 个选择符（`VS17` 至 `VS256`），与 BMP 中的 16 个变体选择符相呼应，专门用于为海量生僻汉字与历史古文字指定极其微妙的书写流派异体字形。

## 候选文字与未来扩展（Scripts Proposed for Addition）

在作者成书之际，Unicode 的疆界依然在不断向外开拓。人类学者与语言学家组成的专门委员会仍在夜以继日地推进未入轨文字的标准化考察：
* **巴萨哇文（Bassa Vah）**：利比里亚与塞拉利昂沿海巴萨族人使用的古老字母。20 世纪初，一位名叫弗洛·达文·刘易斯（Flo Darvin Lewis）的化学家震惊地发现巴西与西印度群岛的黑奴后裔仍在使用该文字，随后他在利比里亚大力推动了这一失落文字的复兴；
* **布利斯符号（Blissymbolics）**：由查尔斯·布利斯（Charles Bliss）在 1950 年代发明的一套纯表意视觉符号语言体系。布利斯原初梦想构建一种超越民族国家藩篱、促进国际和平与跨文化沟通的“世界共通语”，如今它广泛应用于存在严重语言与认知交流障碍的残障人士康复辅助交流系统；
* **瑟斯如尼文字（Cirth）**：托尔金（J.R.R. Tolkien）在奇幻文学史诗《魔戒》中为中土世界矮人与精灵专门发明的如尼符文体系；
* **赫梯楔形文字（Hittite）**：公元前 1600 至 1100 年安纳托利亚中北部赫梯帝国使用的泥板楔形文字；
* **印度河文字（Indus Valley script）**：公元前 2500 至 1700 年哈拉帕印度河流域文明留下的神秘印章文字，至今仍未被破译；
* **凯提文（Kaithi）**：古代至近代广泛流行于北印度行政司法文书中的非正式草书文字；
* **兰纳文（Lanna / Tai Tham）**：泰国北部兰纳王国与西双版纳傣族的历史佛教经书文字；
* **曼达文（Mandaic）**：伊拉克南部曼达教派使用的古代阿拉米文字变体；
* **柏格理苗文（Pollard script）**：二十世纪初英国传教士塞缪尔·柏格理（Samuel Pollard）在中国西南乌蒙山区为苗族创立的精妙音节文字；
* **吕底亚文（Lydian）、卡里亚文（Carian）与吕基亚文（Lycian）**：小亚细亚安纳托利亚半岛的三大古希腊化前古代文字；
* **索永布文字（Soyombo）**：1686 年由蒙古高僧扎那巴扎尔创制的精美字母，其首个复合字符至今仍作为国家主权象征傲然铭刻在蒙古国的国旗之上。

从字符的抽象神髓，到字形的千变万化，再到十六进制二进制比特流在平面间的有序排列，Unicode 为人类文明筑起了一座坚不可摧的数字巴别塔。

然而，仅有码位的排列分配，并不足以支撑一篇赏心悦目的高质量文献排印。每个字符在自然语言文本中具备怎样的语法与排版特性？大写与小写如何映射？双向文本如何折行？变音符号如何锚定？

这正是我们在**第三章：Unicode 字符核心属性体系**中即将踏上的全新探索航程。
