在本章中，我们将深入探讨 Unicode 体系中表面上看似毫无关联、但皆要求深厚计算机技术背景的三个核心高级领域。对于普通文字处理者而言，它们或许显得过于晦涩精深；然而对于计算语言学学者、排版引擎架构师以及系统级软件工程师而言，它们却是决定数字文字处理成败的基石：
1. **分解与规范化流程**（Decomposition and Normalization）：这是所有面向万维网（Web）与数据库的文本引擎开发者所必须彻底精通的底层算法；
2. **双向文本排版算法**（The Bidirectional Algorithm）：这是正确呈现阿拉伯文、希伯来文与叙利亚文等从右至左文字不可或缺的核心渲染管线；
3. **东亚书写系统**（East Asian Scripts）：涵盖中日韩统一表意文字（CJK Ideographs）与朝鲜语谚文（Hangul）音节块的编码哲学、字形构造学与字母组合算术。

## 分解与规范化（Decompositions and Normalizations）

### 组合字符与规范结合类（Combining Characters & Combining Classes）

在上一章中，我们已经对**组合字符**（Combining Characters）区块以及非进幅附加符号（Nonspacing Marks）进行了宏观介绍。然而，这些字符在计算机底层究竟是如何运作的？

在排版渲染时，一个组合字符的字形必须与它所依附的**基底字符**（Base Character）发生几何物理交互。这种交互呈现出千变万化的形式：锐音符位于字母上方，下加符（Cedilla）位于字母下方，希伯来文的重音点（Dagesh）嵌入字母腹中，等等。

部分附加符号在空间与语言学上是彼此完全独立的：在一个字母下方添加下加符，丝毫不会妨碍在字母上方继续叠加扬抑符（Circumflex）。然而，另一些附加符号则占据着完全相同的空间拓扑位置，此时它们出现的物理先后次序便具有决定性的正字法意义。例如在越南语（Vietnamese）中，字母 ‘$\hat{\tilde{\text{E}}}$’ 同时带有扬抑符与硬颚波浪符，并且必须严格遵循先扬抑、后波浪的层叠次序；颠倒其次序将被视为严重的拼写错误。

这一切事实昭示了两个核心原理：
1. 变音符号可以划分为彼此“正交”（Orthogonal）的空间与功能范畴；
2. 在同一个正交范畴内部，附加符号的施加次序至关重要。

Unicode 通过引入**规范结合类**（Canonical Combining Class，简称 `ccc`）将这一机制形式化。在 Unicode 5.0 中，共收录了 352 个组合字符，它们被精细分配在 53 个结合类之中。

每个结合类被赋予一个 0 至 255 之间的整数数值：
- **类 0**：基底字符（Base Characters）以及所有产生进幅间距的独立字符；
- **类 1**：重叠覆盖符号（Overlay Marks，如划杠、斜杠）；
- **类 7**：希伯来文音调符号（Nukta）；
- **类 9**：印度系文字维拉玛符号（Virama / Halant）；
- **类 200..240**：依空间拓扑位置严格细分的结合类：
  - 类 202：下加附着符号（如中世纪拉丁文尾符）；
  - 类 216：回旋附着符号；
  - 类 218：左下结合符号；
  - 类 220：正下方结合符号（Below，如 Cedilla、下加点）；
  - 类 222：右下结合符号；
  - 类 228：左上结合符号；
  - 类 230：正上方结合符号（Above，如 Acute、Grave、Circumflex、Macron、Tilde）；
  - 类 232：右上结合符号；
  - 类 240：希腊文变音符号专有类（Iota Subscript）。

### 规范重排序算法（Canonical Ordering Algorithm）

假设我们在内存中拥有一串由基底字符与多个组合变音符拼接而成的字符序列。由于不同输入法、键盘驱动或 OCR 软件的录入习惯差异，这些结合符号在原始字节流中的存储顺序可能完全不同。如果计算机直接进行按位二进制比对，就会将字形完全相同、发音完全相同的两个词汇误判为不同内容。

为了彻底消解这种歧义，Unicode 规定了著名的**规范重排序算法**（Canonical Ordering Algorithm）：
1. 遍历字符串中的字符序列，获取每个字符的结合类数值 `ccc`；
2. 保持所有结合类为 0 的基底字符位置绝对不动；
3. 对于依附于同一基底字符之后的一连串结合字符，**依据其规范结合类数值 `ccc` 的升序（从低到高）进行稳定排序**；
4. 若两个相邻结合字符具有完全相同的结合类数值（且不为 0），则保持它们原有的相对输入先后顺序不变。

经过规范重排序清洗后，原本次序混乱的变音符序列将被收敛为数学上严格唯一的规范表示形式。

---

### 规范合成（Canonical Composition）

在解决重排序问题后，下一个核心挑战是：某些字符在 Unicode 中既可以表示为一个预先组合好的独立单字符（Precomposed Character，如 ‘é’ `U+00E9`），也可以表示为一个基底字母加结合符号的拆分序列（“e” `U+0065` + “´” `U+0301`）。

在 Unicode 的架构哲学中，这两者被称为**规范等价**（Canonically Equivalent）。排版软件与搜索引擎必须无条件地将它们视为完全一致的同一对象。

将预组合单字符拆解为基底与结合符序列的过程，称为**规范分解**（Canonical Decomposition）；反之，将基底与结合符合并为一个独立预组合单字符的过程，则称为**规范合成**（Canonical Composition）。

为了确保合成过程的确定性与单向收敛，Unicode 严格规定了**主合成字符**（Primary Composites）的判定标准，并排除了那些具有复合分解历史缺陷的孤立字符。

---

### 四大规范化形式（The Four Normalization Forms）

将上述分解、重排序与合成技术系统化组合，Unicode 联合会确立了举世闻名的**四大规范化形式**（The Four Unicode Normalization Forms，详见 UAX #15）：

| 形式代码 | 英文全称 | 核心算法流程与特征定义 |
| :--- | :--- | :--- |
| **`NFD`** | Normalization Form D（规范分解形式） | 先对所有字符执行递归的**规范分解**，随后执行**规范重排序**。结果文本中所有预组合带音符字母均被彻底拆卸为基底加变音符的标准序列。 |
| **`NFC`** | Normalization Form C（规范合成形式） | 先执行 `NFD`（完整规范分解与重排序），随后在可能的最大范围内执行**规范合成**。这是**现代万维网（W3C）官方推荐的首选通用传输格式**。 |
| **`NFKD`** | Normalization Form KD（兼容分解形式） | 先对所有字符执行彻底的**兼容分解**（包括连字拆解、上标下标降级、粗体花体等样式剥离、全角半角归一），随后执行规范重排序。语义信息会发生部分不可逆削减。 |
| **`NFKC`** | Normalization Form KC（兼容合成形式） | 先执行 `NFKD`（完整兼容分解），随后执行最大规范合成。常用于搜索引擎文本清洗、无差别模糊匹配与通用标识符预处理。 |

## 双向排版算法（The Bidirectional Algorithm / UAX #9）

### 段落排印的宏观流动与微观断行

在人类书写文明的画卷中，西方拉丁语系文字遵循从左至右（Left-to-Right, LTR）的书写方向；而闪米特语系的希伯来文（Hebrew）与阿拉伯文（Arabic）则遵循从右至左（Right-to-Left, RTL）的书写方向。当这两种截然相反的书写传统在同一个段落、甚至同一行文字中相互交织碰撞时，便诞生了计算排版领域最精妙复杂的算法构型——**Unicode 双向排版算法**（Unicode Bidirectional Algorithm，简称 Bidi 算法）。

要理解双向算法，首先必须辨明**宏观全局语境**（Global Context）与**微观局部流**（Local Run）的本质区别。

### 双向字符类型（Bidirectional Character Types）

在 `UnicodeData.txt` 的第 4 号字段中，记录了每一个字符的**双向字符类型**（Bidi Character Type）。Unicode 将全体字符划分为 19 种类型，并归入三大阵营：

1. **强字符（Strong Types）**：具有不可动摇的固有书写方向性，绝不随上下文而动摇：
   - `L`（Left-to-Right）：强左至右字符（拉丁字母、汉字、假名、谚文等）；
   - `R`（Right-to-Left）：强右至左字符（非阿拉伯系 RTL 字符，如希伯来字母）；
   - `AL`（Right-to-Left Arabic）：阿拉伯文字及其衍生字符，具有特化的数字上下文关联。
2. **弱字符（Weak Types）**：其方向性相对被动，极易受邻近强字符的影响：
   - `EN`（European Number）：欧洲数字（0..9）；
   - `ES`（European Number Separator）：欧洲数字分隔符（加号、减号）；
   - `ET`（European Number Terminator）：欧洲数字终止符（度数符号、百分号、货币符）；
   - `AN`（Arabic-Indic Number）：阿拉伯-印度数字；
   - `CS`（Common Number Separator）：通用数字分隔符（逗号、冒号、小数点）；
   - `NSM`（Nonspacing Mark）：非进幅附加符号；
   - `BN`（Boundary Neutral）：边界中性符（零宽字符、控制码）。
3. **中性字符（Neutral Types）**：本身完全不具备固有方向性，其排印方向彻底随波逐流：
   - `B`（Paragraph Separator）：段落分隔符；
   - `S`（Segment Separator）：段内制表分隔符；
   - `WS`（Whitespace）：普通空白空格符；
   - `ON`（Other Neutral）：其余一切符号与通用标点（感叹号、括号、斜杠等）。
4. **显式格式控制符（Explicit Formatting Codes）**：
   - `LRE`、`RLE`：显式指定子串进入 LTR 或 RTL 嵌入模式；
   - `LRO`、`RLO`：强行覆盖（Override）后续字符的方向性；
   - `PDF`（Pop Directional Format）：终结当前嵌入或覆盖模式，弹出调用栈。

---

### 双向算法六大步骤（The Six Steps of UAX #9）

1. **确定段落边界与基底嵌入级别（Base Level）**：
   扫描段落中出现的第一个强方向性字符。若为 `L`，则段落基底级别设为 0（偶数，代表 LTR）；若为 `R` 或 `AL`，则基底级别设为 1（奇数，代表 RTL）。
2. **处理显式嵌入与覆盖状态栈（Explicit Levels and Overrides）**：
   建立深度可达 61 级的方向栈。每当遇到 `LRE` / `RLE` / `LRO` / `RLO` 时将新级别压入栈顶；遇到 `PDF` 时弹出栈顶。字符随之继承其所处的显式级别。
3. **解析弱类型（Resolving Weak Types）**：
   依据严格的 `W1` 至 `W7` 规则状态机，消解非进幅标志、以及将位于特定数字前后的分隔符与终止符转化为确定类型的弱数字。
4. **解析中性类型（Resolving Neutral Types）**：
   依据 `N1` 与 `N2` 规则，若中性字符两端被相同方向的强字符所包夹，则该中性字符蜕变为该强方向；否则，它将退化并服从当前所处环境的嵌入级别方向。
5. **计算最终隐式嵌入级别（Resolving Implicit Levels）**：
   结合字符的固有属性与计算得到的环境级别，对欧洲数字与阿拉伯数字施加微调加权，得出最终的整数嵌入级别值。
6. **执行子串逆序反转（Reversing Substrings）**：
   这是整个算法最富美感的高潮：**在内存中寻找当前最高级别的字符运行切片，将其原地反向颠倒；随后将级别阈值递减 1，再次反转包含该级别的更大连续切片，直至回退到段落基底级别。** 经过这番自内向外的层层反转，原本在逻辑内存中线序存储的双向文本便在屏幕上完美呈现出符合人类自然阅读习惯的视觉布局！

### 镜像属性（Mirroring & BidiMirroring.txt）

在双向排版中，括号等成对标点符号带来了一个隐蔽而深邃的问题：在英文（LTR）中，开括号 ‘(’ 开口朝右；但当我们在一段希伯来文（RTL）中书写开括号时，由于阅读方向是从右向左流动的，因此“开启”该语段的括号在视觉上必须**开口朝左**！

如果排版引擎机械地保留原有字形，原本具有开启语义的括号就会在视觉上变成闭括号。

为此，Unicode 在 `UnicodeData.txt` 的第 9 字段中设立了镜像标志位（`Bidi_Mirrored`），并在配套数据库 `BidiMirroring.txt` 中详尽维护了 320 对具有镜像拓扑关系的字符映射表（如 `0028; 0029` 圆括号对、`003C; 003E` 小于大于号对等）。排版引擎在 RTL 环境下会自动调用其镜像字形进行替换。

## 东亚书写系统（East Asian Scripts）

### 中日韩汉字表意文字（Ideographs of Chinese Origin / CJK）

汉字是人类文明史上唯一历经数千年风霜而延绵不绝的语素文字体系（Logographic Writing System）。面对海峡两岸、日本、韩国以及越南在漫长历史中演化出的庞大字库，早期的数字编码标准陷入了各自为政的泥潭。

Unicode 联合会与 ISO/IEC 联合技术委员会所取得的里程碑式成就，正是启动了**中日韩汉字统合工程**（Han Unification）。专家委员会确立了三项金科玉律：
1. **源字典考证法**：凡见于《康熙字典》、《大汉和辞典》、《汉语大字典》或《大韩民国汉字字典》的字形均予严格核验；
2. **部首与笔画分析法**：依据东汉许慎《说文解字》确立、并经《康熙字典》发扬光大的 **214 康熙部首体系**，计算字根归属与剩余笔画数；
3. **字源异体字分离原则**：对于在中国大陆、台湾、日本、韩国呈现不同现代字体风貌（如字形笔画存在微小印刷风格差异）但历史源流、构字理据与语义完全相同的汉字，**统一赋予同一个唯一的 Unicode 编码码点**，将其细微差异交由字体字形（Glyphs）与样式系统去呈现；唯有当两个字在历史源字典中确立为不同字素时，方分别赋予独立码点。

#### 汉字结构描述字符（Ideographic Description Characters, IDC）
尽管 Unicode 收录了数万个统合汉字，但在历史古籍、佛教经典、方言俚字乃至现代人名中，依然存在着数以十万计的未编码罕用字。为了彻底终结“造字无门”的困境，Unicode 极富创造力地在 `U+2FF0..U+2FFB` 区块设立了 12 个**汉字结构描述字符**（IDC）：

| 码点 | 符号 | 结构名称 | 空间拓扑构字语义与解析示例 |
| :---: | :---: | :--- | :--- |
| `U+2FF0` | ⿰ | 左右结构（Left-to-Right） | 如 `⿰ 木 木` 组合描述 “林” |
| `U+2FF1` | ⿱ | 上下结构（Above-to-Below） | 如 `⿱ 木 木` 组合描述 “ forest (未收录时的上下拆分)” |

| `U+2FF3` | ⿳ | 上中下结构（Above-to-Middle-and-Below） | 如 `⿳ 艹 曰 曰` |
| `U+2FF4` | ⿴ | 全包围结构（Full Surround） | 如 `⿴ 口 十` 组合描述 “田” |

### 字符描述语言（Character Description Language, CDL）

在 20 世纪 80 年代，汉学专家汤姆·毕晓普（Tom Bishop）与文林软件研究所（Wenlin Institute）在开发汉字教学系统时，开创了一种革命性的汉字结构解析模型。伴随着 XML 技术的风靡，这套模型被升华为国际标准提案——**字符描述语言**（Character Description Language，简称 CDL）。

CDL 的核心哲学在于：**任何复杂的汉字均可以通过递归的 XML 树状结构，由最基础的笔画（Strokes）与构件（Components）在标准坐标系空间内拼装而成。**

例如，汉字构件不仅可以通过其自身的 Unicode 码点进行定位引用，更能在网格坐标系中精确限定其外接包围盒（Bounding Box）：

```xml
<cdl char="L">
  <comp char="K" points="0,0 40,128"/>
  <comp char="E" points="60,12 128,128"/>
</cdl>
```

而在原子笔画层级，CDL 将中国传统书法理论中的“永字八法”进行了现代数字化形式重构，系统提炼出了整整 **42 种基础笔画原型**。以下历史文献图版完整收录了全部 42 种基本笔画的官方形态、汉语拼音定名、标准英文缩写及真实构字范例：

细心的读者会发现，这些笔画名称是由若干核心构字术语复合派生而成的：
- **横（héng, h）**：水平笔画；
- **提（tí, t）**：自左下向右上挑起的笔画；
- **竖（shù, s）**：垂直下行笔画；
- **撇（piě, p）**：向左下轻快掠出的弧线笔画；
- **捺（nà, n）**：向右下沉稳铺开的波磔笔画；
- **点（diǎn, d）**：微小顿笔；

- **弯（wān, w）**：柔和转折的圆弧曲线；
- **圈（quān, o）**：闭合圆圈笔画。

### 朝鲜语谚文（Hangul）与字母算术

在公元 15 世纪以前，朝鲜半岛一直借用汉字（吏读、口诀）来记录其与汉语完全不同的黏着语系母语。由于汉字极其深奥难懂，广大平民阶层深陷文盲困境。

公元 1443 年，朝鲜王朝第四代君主**世宗大王**（King Sejong the Great, 1397–1450）召集集贤殿学者，历经数年呕心沥血的秘密钻研，于 1446 年正式颁布了旷世巨作《**训民正音**》（Hunminjeongeum，意为“教导百姓以正确声音”）。这部被诸多现代西方语言学家赞誉为“**人类历史上设计最为精妙完备的书写系统**”的诞生，彻底改写了东亚文字史。

#### 辅音的生理发音器官几何象征
世宗大王依据发音时舌、齿、唇、喉的物理几何形态设计了五大基本辅音字母，并通过在基本形态上逐级“加画”（加笔画）来表达送气与硬音：

- 舌根音 ‘ᄀ’（g）：象征舌根闭合喉部的轮廓；
- 舌尖音 ‘ᄂ’（n）：象征舌尖抵住上颚的侧面形态；

### 现代谚文音节块的数字算法艺术

在书写时，朝鲜语谚文并非线性排布字母，而是将一个或多个声母辅音、介音元音与韵尾辅音，在正方形汉字方块的二维空间内拼接拼装为一个独立的**音节块**（Syllable Block）。

例如，声母 ‘ᄒ’（h）+ 韵母 ‘ᅡ’（a）+ 韵尾 ‘ᆫ’（n）凝结为一个方块字：‘**한**’（Han）。

在 Unicode 编码体系中，为了同时满足传统音素级检索与现代高速文本处理的双重需求，标准设立了双轨制：
1. **谚文字母区块**（Hangul Jamo, `U+1100..U+11FF`）：记录纯粹的单个初声、中声与终声字母；
2. **预组合谚语音节区块**（Hangul Syllables, `U+AC00..U+D7A3`）：以惊人的气魄完整分配了现代朝鲜语中所可能组合出的**全部 11,172 个标准音节块**！

更令人叹服的是，这 11,172 个音节块的码点绝非随机散乱分配，而是严格遵循严密的**离散数学多项式算术法则**：

现代韩语拼音包含：
- **初声（Choseong, L）**：共 19 种可能（$L_0$ 至 $L_{18}$）；
- **中声（Jungseong, V）**：共 21 种可能（$V_0$ 至 $V_{20}$）；
- **终声（Jongseong, T）**：共 28 种可能（包含 0 号“无终声”以及 27 种辅音韵尾）。

三者组合的笛卡尔积空间恰好为：
$$N = 19 \times 21 \times 28 = 11{,}172$$

任何一个三元组 $(L, V, T)$ 所对应的预组合音节码点 $S$，均可以通过以下简洁优美的线性算式无损计算得出：

$$\text{CodePoint} = \text{0xAC00} + (L_{\text{index}} \times 21 \times 28) + (V_{\text{index}} \times 28) + T_{\text{index}}$$

反之，给定任意一个落在 `0xAC00..0xD7A3` 范围内的韩语音节，计算引擎只需进行简单的除法与模运算（Modulo Arithmetic），即可在零内存开销、零查表延迟的前提下，瞬间将其解构还原为最本源的初声、中声与终声字母序列！
